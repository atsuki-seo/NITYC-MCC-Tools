# 要点設計ガイド

`class-material` の Step 2（要点の設計）と Step 3（小テストの織り込み）で参照する。

このガイドの目的は、**テーマと到達目標から、話すべき要点を導く**ことである。テーマをそのまま節に分解するのではなく、学生が何を理解できていない状態から何を理解できる状態へ移るのかを設計する。

---

## 1. 設計の観点

以下の5つを順に検討する。各観点が1つ以上の節に対応する。

### 1.1 導入 — なぜこのテーマが必要か

**扱わない場合に何が困るかを、具体的な状況で示す。** 定義から入ってはならない。

学生にとって、新しい概念はまず「なぜ覚えなければならないのか」が不明である。困る状況を先に提示することで、以降の説明が解決策として位置づく。

良い導入の型:

- **規模の対比**: 「1000件のデータから1件を取り出す」— 手作業と仕組みの差が量で示せる場合
- **素朴な方法の破綻**: 単純な方法をまず示し、それが通用しなくなる条件を示す
- **選択の必要性**: 複数の方法があり、状況によって適否が変わることを示す

導入の節では、本講で扱う概念を箇条書きで予告し（※次回予告ではなく当該回の内容の列挙）、`.note` で到達点を明示する。

### 1.2 中核概念の展開

**1節1概念を原則とする。** 概念ごとに「定義 → 仕組み → 図解」の順で積み上げる。

- **定義**: 何を定め、何を定めないのかを弁別できる形で述べる
- **仕組み**: なぜそうなるのかを、内部の動作に基づいて説明する
- **図解**: 言葉で追いにくい構造・遷移を図にする（`figure-guide.md`）

概念の順序は依存関係に従う。後の概念の説明に前の概念が必要なら、必ず先に置く。

### 1.3 性質の対比 — 判断の根拠を与える

**得意・不得意、他の手法との比較など、使い分けの根拠となる観点を示す。**

学生が実際に必要とするのは「何であるか」より「いつ使うか」である。対比の節では以下を扱う:

- その構造・手法が得意とする操作と、不得意とする操作
- 代替手段との比較（どちらが優れているかではなく、どの条件でどちらを選ぶか）
- 誤用しやすい場面

表形式（`.table-scroll`）が有効な場面が多い。

**挙げた利点・欠点それぞれについて、それが判断を左右する条件を確認する。** 教科書的に列挙される項目には、計算機の性能向上によって現在では選択の決め手にならなくなったものが含まれる。条件を検討せずに並べると、学生はそれらを同程度に重要なものとして受け取る。記述の仕方は `writing-style-guide.md` § 5.2 を参照する。

**現代の実務での位置づけを確認する。** 現在では用いられない手法であれば、廃れた理由と、それでも残っている用途を述べる。「古い手法である」で終えると、なぜ学ぶのかが示されない。特定の製品名・規格名を挙げるより、その手法が要件となる条件を述べるほうが、学生の既知の語彙で理解できる。

### 1.4 到達点との対応づけ

シラバスの当該週の到達目標を、解説の内容が満たしているかを確認する。

到達目標に「〜を説明できる」とあれば説明の根拠を、「〜を実装できる」とあれば手順を、本文中に必ず含める。満たしていない項目があれば節を追加する。

### 1.5 総括

**節ごとの要点を再掲し、全体を締める。** 新しい概念を導入しない。

箇条書きで各節の要点を1行ずつ再掲する形が扱いやすい。学生が復習時に最初に読む箇所になる。

---

## 2. 節の分割と統合

節の分割は、上記の観点を満たすのに要する数だけ置く。

- **分割する**: 1節1概念の原則を保てなくなったとき
- **統合する**: 独立した概念として述べることがなくなったとき

節数をあらかじめ決めてから内容を割り当てるのではなく、内容から節数が決まる。薄いテーマを水増しせず、濃いテーマを圧縮しない。

各節には確認問題を1問以上配置する（`quiz-guide.md`）。

## 3. 直近の小テストの織り込み

Step 3 で抽出した出題論点を、解説ページに組み込む。

### 3.1 目的

直近の小テストで問うた論点を再度扱うことで、復習機会を与え理解の定着を図る。小テストは学生がつまずいた箇所が判明している貴重な情報源である。

### 3.2 織り込み方

**設問文をそのまま転載しない。** 問うた論点を以下のいずれかの形に再構成する:

- **本文への組み込み**: 該当する節の説明を、その論点が明確になるよう厚くする
- **確認問題への再構成**: 同じ論点を別の角度から問う問題を作る（数値・文脈を変える、選択式を記述式にする等）

### 3.3 言及の禁止

「小テストで出題した」「前回のテストで問うた」等の言及はしない。

理由は予告の禁止（`writing-style-guide.md`）と同じく、資料の汎用性を保つためである。特定回・特定年度への依存を作らない。

### 3.4 複数回の小テストの扱い

直近の1件を主たる織り込み対象とする。それ以前の小テストで**繰り返し問われている論点**があれば、定着が不十分な箇所として併せて扱ってよい。

---

## 4. 構成案プレビューの作り方

Step 2 でユーザーに提示する構成案は、**節タイトルだけでなく、その節で何を述べるかまで書く。** 節タイトルのみでは内容の妥当性を判断できず、合意の意味がない。

```
=== 解説ページ構成案: スタック・キュー ===
対象: 第3週 ／ 到達目標: スタックとキューの構造・操作を理解し、実装できる。

1. データを取り出す順序という観点
   要点: 同じデータ集合でも取り出す順序の規約が異なれば用途が変わる。
         ブラウザの戻る操作と印刷待ち行列を対比して示す。
   図版: なし
   確認問題: 順序の規約が処理結果を左右することの理解

2. スタック — 後入れ先出し
   要点: LIFO の定義、push/pop の動作、先頭位置の管理。
   図版: あり（積み上げと取り出しの遷移）
   確認問題: 一連の push/pop 後の内容を追跡する

...

直近の小テスト: 小テスト1（第5週実施）
  織り込む論点: 配列の添字計算 / 要素数と最終添字の区別
```
