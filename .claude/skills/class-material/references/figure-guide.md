# 図版ガイド

`class-material` の Step 4（HTML生成）で参照する。図版はインラインSVGで記述する。

---

## 1. 原則

### 1.1 色値を直書きしない

配色は必ず共通クラス（`.svg-*`）で指定する。SVG内に `fill="#1f5f8b"` 等の色値を書くと、ダークモードで判読できなくなる。

例外: `marker` の `path` には `fill="var(--c-accent)"` のように CSS 変数を用いる（クラスが効かないため）。

### 1.2 アクセシビリティ

`role="img"` と `aria-label` を必ず付ける。`aria-label` には図が示す内容を文章で記述する。

```html
<svg viewBox="0 0 580 150" role="img" aria-label="添字 2 から 5 までの区間に 4 個の要素が含まれることを示す図">
```

### 1.3 サイズ指定

- `viewBox` のみを指定し、`width`/`height` 属性を付けない（CSS 側で `max-width: 100%` が効く）
- 横幅は 560〜580 を基準とする。これを超えるとスマートフォンで縮小され、文字が読めなくなる
- 文字サイズは `.svg-text`(15px) / `.svg-mono`(13px) / `.svg-small`(12px) に委ねる。SVG内で `font-size` を上書きしない

### 1.4 テキストの寄せ

`.svg-text` / `.svg-mono` / `.svg-small` は CSS で `text-anchor: middle` が指定されている。左寄せ・右寄せにする場合は `style` 属性で上書きする。

```html
<text x="10" y="18" class="svg-small" style="text-anchor:start">静的型付け</text>
```

**`text-anchor="start"` の属性指定は効かない。** CSS の宣言は SVG のプレゼンテーション属性を常に上書きするためである。インラインの `style` でなければ上書きできない。

### 1.5 viewBox の寸法決定

**描画要素の外接範囲は、stroke の太さを含めて viewBox に収める。** `rect` の `y + height` が viewBox の高さちょうどだと、枠線の外側半分がはみ出して切れる。

各要素が占める範囲は以下で求める:

| 要素 | 占める範囲 |
|------|-----------|
| `rect` | `x - sw/2` 〜 `x + width + sw/2`（縦も同様。`sw` は stroke-width） |
| `path`（線・矢印） | 端点 ± `sw/2`。`marker-end` を付けた線は矢尻の分だけ先まで伸びる |
| `text` | `y` を基準に上へ約 0.8em、下へ約 0.25em。`text-anchor` に応じて左右に広がる |

クラス別の `stroke-width`:

| クラス | stroke-width | 片側のはみ出し |
|--------|-------------|---------------|
| `.svg-cell` / `.svg-cell-plain` | 2 | 1 |
| `.svg-hl` | **3** | **1.5** |
| `.svg-line` / `.svg-arrow` | 2 | 1 |

`.svg-hl` だけ太いため、最下段・最右端を強調枠にした図は見落としやすい。

**viewBox の各辺には最低 4 の余白を確保する。** 例: 最下段の要素が `y="210" height="42"` の `.svg-hl` であれば、下辺は 210 + 42 + 1.5 = 253.5 に達するため、viewBox の高さは 258 以上とする。

### 1.6 重なりの前後関係

SVG に `z-index` はなく、**後に書いた要素が上に描画される**。この順序を意識せずに書くと、補助線や矢印がセルの上に乗り、枠線を分断して読みにくくなる。

**データの入れ物（セル）を最前面に置く。** 補助線・矢印・円弧などの背景要素は、セル群より**前**に書く。

```html
<!-- 背景の補助線・矢印を先に書く -->
<circle cx="180" cy="130" r="86" class="svg-line"/>
<path d="M 112 62 A 86 86 0 0 1 143 38" class="svg-arrow" marker-end="url(#ah8)"/>

<!-- セルは後に書く。これで矢印の上に重なる -->
<rect x="152" y="27" width="56" height="34" class="svg-bg"/>
<rect x="152" y="27" width="56" height="34" class="svg-cell-plain"/>
<text x="180" y="49" class="svg-mono">[0]</text>
```

あわせて、**矢印の終端はセルの手前で止める。** `marker-end` の矢尻はセル枠に食い込むと枠線と干渉するため、セルの辺より数ポイント手前を終点とする。

#### 辺を共有するセルの描画順

隣接するセルが辺を共有する場合、その辺は**両方のセルによって2回描かれる**。クラスが異なれば stroke の色・太さも異なるため、**後に書いた側の stroke が見える**。

表形式の図でこれが問題になる。ある行を `.svg-cell` で強調し、上下の行が `.svg-cell-plain` であるとき、行の順に書くと強調行の上辺と下辺で勝つクラスが食い違い、**片側だけ強調色・反対側は通常色**という非対称な枠になる。

```html
<!-- 誤: 行の順に書くと、強調行の下辺を後続の .svg-cell-plain が上書きする -->
<rect x="24" y="38"  width="92" height="40" class="svg-cell-plain"/>
<rect x="24" y="78"  width="92" height="42" class="svg-cell"/>
<rect x="24" y="120" width="92" height="40" class="svg-cell-plain"/>

<!-- 正: 強調するセルを最後に書く。共有辺は四辺とも強調色になる -->
<rect x="24" y="38"  width="92" height="40" class="svg-cell-plain"/>
<rect x="24" y="120" width="92" height="40" class="svg-cell-plain"/>
<rect x="24" y="78"  width="92" height="42" class="svg-cell"/>
```

**強調するセル（`.svg-cell` / `.svg-hl`）は、辺を共有する通常セルより後に書く。** セルの描画順は図の意味する配置を変えないため、ソース上の並びを行順に保つ必要はない。

### 1.7 枠線のみのセルは背景を敷く

`.svg-cell-plain` は `fill: none` である。背後に補助線・矢印・他の図形が通る位置でこのクラスを使うと、**セルの内側を背景要素が素通りする**。

背後に何かが通る位置では、同一座標の `.svg-bg`（`fill: var(--c-surface)`）を直前に敷いて不透明にする。

```html
<rect x="77.5" y="70" width="56" height="34" class="svg-bg"/>
<rect x="77.5" y="70" width="56" height="34" class="svg-cell-plain"/>
```

`.svg-cell` に置き換えて塗りつぶしてはならない。`.svg-cell` は「データが入っている」ことを表す記法であり、空きセルに用いると図全体の対比が崩れる。**塗りつぶしは可読性のための措置であり、意味の変更を伴わせない。**

## 2. 共通クラス

| クラス | 用途 |
|--------|------|
| `.svg-cell` | 通常の枠（塗りあり）。データの入れ物を表す |
| `.svg-cell-plain` | 枠線のみ（`fill: none`）。文脈上の背景・対象外の要素 |
| `.svg-bg` | 背景色の塗り（枠線なし）。`.svg-cell-plain` の下に敷いて不透明にする（§ 1.7） |
| `.svg-hl` | 強調枠。注目させたい要素・変化した箇所 |
| `.svg-text` | 主要なラベル（値・名前） |
| `.svg-mono` | 等幅。添字・アドレス・記号 |
| `.svg-small` | 補助説明・見出し |
| `.svg-line` | 補助線（灰色） |
| `.svg-arrow` | 矢印の線（アクセント色） |

`.svg-cell` と `.svg-hl` の対比で「通常」と「注目」を表現するのが基本である。

## 3. 頻出パターン

以下は特定テーマに限らず再利用できる図版の型である。テーマに応じて要素名を差し替える。

### 3.1 セル列 — 並んだ要素を示す

配列・メモリ領域・文字列・バッファなど、**同種の要素が並ぶ構造**に用いる。

構成:
- `rect` を等間隔・隙間なしで横に並べる（連続性を示す場合）
- 各セルの中央に `.svg-text` で値、下に `.svg-mono` で添字
- 注目させる要素だけ `.svg-hl` にする

```html
<rect x="40"  y="40" width="70" height="50" class="svg-cell-plain"/>
<rect x="110" y="40" width="70" height="50" class="svg-hl"/>
<text x="75"  y="71" class="svg-mono">[0]</text>
<text x="145" y="71" class="svg-mono">[1]</text>
```

隙間を空けると「連続していない」という誤解を生む。連続領域を示す場合は `x` を幅ちょうどずつ進める。

### 3.2 前後比較 — 状態の遷移を示す

操作の前後で構造がどう変わるかを示す。**挿入・削除・更新・並べ替え**など、動作を伴う概念に用いる。

構成:
- 上段に「操作前」、下段に「操作後」を配置
- 各段の上に `.svg-small` で見出し（「挿入前（要素数 4）」）
- 変化した要素を `.svg-hl` で示す
- 段の間に矢印を置き、操作内容を `.svg-small` で添える

縦に並べることで、同じ位置の要素を目で対応づけられる。左右に並べると対応関係が追いにくい。

### 3.3 上書きの表現

値が置き換わり、元の値が失われることを示す。

構成:
- 左に変更前の値（`.svg-cell`）、右に変更後の値（`.svg-hl`）
- 間に矢印と操作内容（`x ← 25`）
- 失われる値を破線枠（`.svg-cell-plain` + `stroke-dasharray="6 4"`）で示し、「失われる」と明記

```html
<rect x="420" y="45" width="110" height="60" class="svg-cell-plain" stroke-dasharray="6 4"/>
```

破線は「もう存在しない」「概念上の存在」を表す記法として一貫して用いる。

### 3.4 範囲の強調 — 区間を示す

添字の区間、探索範囲、対象部分列などを示す。

構成:
- 全体をセル列で描き、範囲内のみ `.svg-hl`
- 範囲の下に両端矢印と個数・長さの注記

「範囲内が何個か」を図から数えられるようにすることで、オフバイワンの誤解を視覚的に解消できる。

### 3.5 計算の注記 — 式と対象を結ぶ

計算結果がどの要素を指すかを示す。

構成:
- 図の上部に `.svg-mono` で式（`100 + 3 × 4 = 112`）
- そこから対象要素へ `.svg-arrow` で下向き矢印

式と結果の対応が一目で分かるため、アドレス計算・添字計算・インデックス変換に有効である。

## 4. 矢印の定義

矢印には `marker` が必要である。SVG ごとに一意な `id` を付ける（同一ページ内で衝突するため）。

```html
<path d="M 170 75 L 235 75" class="svg-arrow" marker-end="url(#ah3)"/>
...
<defs>
  <marker id="ah3" markerWidth="9" markerHeight="9" refX="8" refY="4.5" orient="auto">
    <path d="M 0 0 L 9 4.5 L 0 9 z" fill="var(--c-accent)"/>
  </marker>
</defs>
```

`id` の命名は `ah[通し番号]` とし、ページ内で重複させない。`<defs>` は各 SVG の末尾に置く。

## 5. 図版を入れる判断

**言葉で追いにくいものだけを図にする。** 箇条書きや表で十分な内容を図にしても、情報量は増えない。

| 図が有効 | 図が不要 |
|----------|---------|
| 構造の配置（何がどこにあるか） | 用語の定義 |
| 状態の遷移（操作前後の変化） | 分類の列挙（表が適切） |
| 位置・範囲の計算 | 性質の対比（表が適切） |
| 要素間の関係（参照・接続） | 手順の列挙（擬似コードが適切） |

分類・対比は `.table-block` の表、手順は `pre` の擬似コードを用いる。

## 6. 生成後の検証

### 6.1 寸法検証

**全ての SVG について、四辺すべてのはみ出しを検証する。** 左右のみ、あるいは目視のみの確認では不足である。ブラウザで開いた見た目は viewBox 外を切り落とした結果であり、切れていること自体が分かりにくい。

検証は生成した HTML を読み取り、各 SVG について以下を突き合わせる:

1. `viewBox` の値（`0 0 W H`）を取得する
2. 各 `rect` / `path` / `text` の座標から、§ 1.5 の規則で外接範囲を求める（stroke の片側幅を含める）
3. 四辺それぞれについて、範囲が `0` 未満または `W`／`H` 超過になっていないかを判定する

はみ出しがあれば viewBox を広げる。要素の座標を詰める方向で直すと、図の意味する配置が変わりうるため、原則 viewBox 側を調整する。

検証結果は図ごとに四辺の値を示す形で報告する。「問題なし」とだけ述べない。

```
図 4-1  viewBox 580x262
  左 8.0 / 右 572.0 / 上 6.0 / 下 253.5  → 収まる
```

### 6.2 重なりの検証

寸法が収まっていても、要素同士が重なって判読できない状態は検出されない。各 SVG について以下を確認する:

1. **テキスト同士の重なり** — ラベルが互いに重なっていないか
2. **テキストと線の重なり** — ラベルが補助線・矢印を横切っていないか
3. **セルと背景要素の重なり** — 補助線・矢印がセル枠の上に乗っていないか（§ 1.6）。`.svg-cell-plain` の内側を背景要素が素通りしていないか（§ 1.7）
4. **辺を共有するセルの描画順** — クラスの異なるセルが接する辺で、強調側が後に書かれているか（§ 1.6）

1・2 は座標計算で判定できる。3 は**描画順の確認で判定する**: 補助線・矢印がセル群より後に書かれていれば、その時点で誤りである。

4 は**面積のある重なりではなく接触であるため、矩形の交差判定では検出できない。** 矩形を総当たりし、クラスが異なる組について、一方の辺ともう一方の辺が同一線上にあり（座標差が 0）、かつ直交方向に重なりがある組を列挙する。該当する組ごとに、ソース上で後に現れるのが強調側（`.svg-cell` / `.svg-hl`）であることを確認する。

```
図 5-1  クラス差のある共有辺 8 件
  y=78  x[24,116]  svg-cell-plain / svg-cell  → 後: svg-cell   OK
  y=120 x[24,116]  svg-cell-plain / svg-cell  → 後: svg-cell   OK
```

`.svg-cell` と `.svg-hl` が接する場合は `.svg-hl` が後であればよい。強調の強い側が境界を持つ。

### 6.3 描画結果の目視確認

座標計算は「要素がどこにあるか」しか検証しない。**配置が図の意味を正しく表しているかは、描画結果を見て確認する。** 円周上への配置・環状の表現など、座標の対称性が意味を担う図では特に、計算上の整合と見た目の妥当性が一致しない場合がある。

ローカルファイルを直接開くと相対パスの CSS が読み込まれず、`.svg-*` クラスが効かない状態で描画される。この状態での確認は無意味であるため、**HTTP 経由で配信して確認する**。CSS の適用は、`.svg-small` の `text-anchor` が `middle`、`font-size` が `12px` に解決されることで判定できる。

ダークモード・ライトモードの双方で確認する。`.svg-bg` のような背景色に依存する要素は、片方のモードでのみ破綻しうる。
