# 文体・表現ガイド

`class-material` の Step 4（HTML生成）で参照する。解説ページ本文の文体を統一するための規約。

---

## 1. 常体で書く

アカデミックな文体として常体（「〜である」「〜する」）を用いる。

| 用いる | 用いない |
|--------|---------|
| 〜である／〜する | 〜です／〜ます |
| 〜と呼ぶ | 〜と呼びます |
| 注意を要する | 注意しましょう |
| 確認されたい | 確認してみてください |

呼びかけ（「〜しましょう」「〜してみよう」「〜に注目してください」）を用いない。読み手に対する指示ではなく、事実の記述として書く。

例外: 確認問題の設問文は、問いとして自然な形（「〜はどれか」「〜を答えよ」）とする。

## 2. 用語の英語併記

用語の**初出時**に原語を併記する。

```html
<span class="term">データ型</span><span class="en">(data type)</span>
```

- 2回目以降は `.term` のみ、または通常のテキストでよい
- 日本語として定着している語（プログラム、メモリ等）には併記しない
- 併記するのは、学生が今後英語文献・エラーメッセージで遭遇しうる語

## 3. 名前で指す

対象や概念を指すとき、**数え上げではなく名前を用いる。** 読み手に「どれとどれだったか」を数え直させる表現は、その時点で理解を止める。

### 3.1 数だけで指さない

「三方式」「2つの手法」のように数だけで指す語は、名前の代わりにならない。節見出し・到達点の列挙・キャプションなど、**本文から切り離して読まれる箇所では特に成立しない。**

| | 書き方 |
|---|---|
| 避ける | 三方式と配列の使い分け |
| 用いる | リストと配列の使い分け |

対象をまとめて指す必要があるときは、**それらを束ねる上位の名前を使う**（線形リスト・双方向リスト・カーソルリスト → 「リスト」）。上位の名前がない場合は列挙する。

直後に名前が列挙される場合に限り、数を伴う表現を導入として使ってよい（「本講では次の三つの方式を扱う」＋箇条書き）。

複数の対象を対比した後、それらをまとめて別の対象と比較する節を設けるときは、**節の冒頭で対象を名指しで振り返り、まとめて扱える理由を述べる。** 何と何を比較しているのかが不明なまま対比表に入ることを防ぐ。

### 3.2 概念を説明したら名前を与える

ある概念を説明する記述を書いたなら、**それに対応する用語を示す。** 説明だけを与えて名前を伏せると、学生はその概念を他の文脈で認識できず、今後の文献・講義で同じ語に出会っても結び付けられない。

| | 書き方 |
|---|---|
| 避ける | 一方を得るために他方を手放す関係にある |
| 用いる | 一方を得るために他方を手放す関係にある。このような関係を<span class="term">トレードオフ</span><span class="en">(trade-off)</span> と呼ぶ |

説明が本文・キャプション・解答のいずれにあっても同様に扱う。用語の提示は § 2 の記法に従う。

## 4. 強調の使い分け

| 記法 | 用途 |
|------|------|
| `<span class="term">` | 用語の定義箇所。青字で示す |
| `<strong>` | 文中で特に重要な命題。下線ハイライトが付く |
| `<code>` | 識別子・記号・短い擬似コード片 |

`<strong>` の多用は強調の意味を失わせる。1節あたり数箇所にとどめる。

## 5. 断定の程度

### 5.1 成り立つ範囲を示す

過度の単純化を避ける。言語や処理系によって異なる事柄は、そのことを明示する。

| 状況 | 書き方 |
|------|--------|
| 常に成り立つ | 「〜である」 |
| 多くの場合成り立つ | 「一般に〜である」「多くの言語では〜」 |
| 処理系依存 | 「処理系によって異なるが、〜」 |

例: 「配列の添字は0から始まる」は言語依存である。「多くの言語では添字は0から始まる」と書く。

### 5.2 利点・欠点は効く条件とともに示す

利点や欠点を挙げるときは、**事実として正しいかだけでなく、それが判断を左右する条件を示す。** 条件を伴わない提示は、事実が正しくとも重みづけを誤らせる。学生は挙げられた項目を同程度に重要なものとして受け取るためである。

| | 書き方 |
|---|---|
| 避ける | 代償として、ノードあたりの記憶域が増える |
| 用いる | 記憶域も増えるが、これが選択を左右するのはノードが小さく大量にある場合や、使える記憶域の総量が限られる環境に限られる |

判断の指針:

- **計算機の性能向上によって影響が小さくなった事柄**（記憶域の数バイト差など）を、現在も効く要因と並べて挙げない
- 複数の代償を挙げるときは、**条件によらず効くものを先に置く。** 実装の誤りやすさ・保守性は環境の進歩と無関係に残るが、資源量に関する事柄は環境に左右される
- 欠点を述べる際は、**それが顕在化する状況**を併記する。「起こりうる」だけでは、いつ気にすべきかが判断できない

一覧表で構成や仕様を並記する場合はこの限りではない。「値 ＋ ポインタ2本」のように事実を列挙するだけで、優劣の主張を伴わないためである。

## 6. 予告の禁止

以下は**出力に含めない**。

- 「次回は〜を扱う」「以降の授業で説明する」「後の講で詳しく述べる」
- 「前回学んだとおり」「既に扱ったように」等、特定の授業回への依存

**理由**: 資料の汎用性・再利用性を損なうため。他の回・他年度でも単体で成立する記述とする。

ただし以下は予告ではないため、含めてよい:

- 当該回の到達点を述べる `.note`（「本講の到達点」）
- 本講で扱う内容の列挙（導入節での予告）
- 当該テーマの学習上の位置づけ（「あらゆるデータ構造の土台を成す」等、回への言及を伴わないもの）

## 7. 擬似コードの記法

特定言語の構文に依存しない。詳細は `figure-guide.md` と併せて参照する。

| 操作 | 記法 |
|------|------|
| 代入 | `a ← 3` |
| 比較 | `a = b`（等価）、`a ≠ b` |
| 手順 | 行頭に連番 `1.` `2.` |
| 制御構造 | 日本語で記述（「〜の間繰り返す」「もし〜ならば」） |

```
1. a ← 3
2. b ← 8
3. a ← b
4. b ← 5
```

以下は用いない:

- 特定言語の実行可能コード（`int a = 3;` `a = 3` 等、言語が特定できる形）
- 言語固有のライブラリ名・関数名
- セミコロン・波括弧等の言語固有の区切り記号

## 8. 図版・表のキャプション

図版と表には必ずキャプションを付ける。本文から番号で参照でき、図表単体でも何を示すものかが分かるようにするためである。

| 対象 | 形式 | 位置 |
|------|------|------|
| 図版 | `図 [節番号]-[連番]　[説明文]` | 図の**下**（`figcaption`） |
| 表 | `表 [節番号]-[連番]　[説明文]` | 表の**上**（`.table-caption`） |

- 節番号は `h2` の `.num` と一致させる
- 図と表は独立した番号系列とする（同一節に `図 3-1` と `表 3-1` が併存してよい）
- 全角スペースで区切る
- 説明文は図表が示す事実と、そこから読み取るべき含意を述べる

```html
<figcaption>
  図 3-1　代入は既存の値を上書きする。過去の値を保持したい場合は、
  別の変数に退避させるなど、明示的な手当てを要する。
</figcaption>
```

```html
<p class="table-caption">
  表 3-1　各データ型が定める値域と操作。型の指定は記憶域の配置や
  実行速度ではなく、この二点を定めるものである。
</p>
```

## 9. 注記ボックスの使い分け

| クラス | 用途 | ラベル例 |
|--------|------|---------|
| `.note` | 補足・到達点の提示 | 「本講の到達点」「補足」 |
| `.note.caution` | 誤りやすい点・注意喚起 | 「注意」「誤りやすい点」 |

`.label` には内容を表す短い語を入れる。
