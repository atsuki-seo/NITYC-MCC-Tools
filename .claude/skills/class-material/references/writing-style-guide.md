# 文体・表現ガイド

`class-material` の Step 4（HTML生成）で参照する。解説ページ本文の文体を統一するための規約。

---

## 1. 常体で書く

アカデミックな文体として常体（「〜である」「〜する」）を用いる。

| 用いる | 用いない |
|--------|---------|
| 〜である／〜する | 〜です／〜ます |
| 〜と呼ぶ | 〜と呼びます |
| 注意を要する | 注意しましょう |
| 確認されたい | 確認してみてください |

呼びかけ（「〜しましょう」「〜してみよう」「〜に注目してください」）を用いない。読み手に対する指示ではなく、事実の記述として書く。

例外: 確認問題の設問文は、問いとして自然な形（「〜はどれか」「〜を答えよ」）とする。

## 2. 用語の英語併記

用語の**初出時**に原語を併記する。

```html
<span class="term">データ型</span><span class="en">(data type)</span>
```

- 2回目以降は `.term` のみ、または通常のテキストでよい
- 日本語として定着している語（プログラム、メモリ等）には併記しない
- 併記するのは、学生が今後英語文献・エラーメッセージで遭遇しうる語

## 3. 強調の使い分け

| 記法 | 用途 |
|------|------|
| `<span class="term">` | 用語の定義箇所。青字で示す |
| `<strong>` | 文中で特に重要な命題。下線ハイライトが付く |
| `<code>` | 識別子・記号・短い擬似コード片 |

`<strong>` の多用は強調の意味を失わせる。1節あたり数箇所にとどめる。

## 4. 断定の程度

過度の単純化を避ける。言語や処理系によって異なる事柄は、そのことを明示する。

| 状況 | 書き方 |
|------|--------|
| 常に成り立つ | 「〜である」 |
| 多くの場合成り立つ | 「一般に〜である」「多くの言語では〜」 |
| 処理系依存 | 「処理系によって異なるが、〜」 |

例: 「配列の添字は0から始まる」は言語依存である。「多くの言語では添字は0から始まる」と書く。

## 5. 予告の禁止

以下は**出力に含めない**。

- 「次回は〜を扱う」「以降の授業で説明する」「後の講で詳しく述べる」
- 「前回学んだとおり」「既に扱ったように」等、特定の授業回への依存

**理由**: 資料の汎用性・再利用性を損なうため。他の回・他年度でも単体で成立する記述とする。

ただし以下は予告ではないため、含めてよい:

- 当該回の到達点を述べる `.note`（「本講の到達点」）
- 本講で扱う内容の列挙（導入節での予告）
- 当該テーマの学習上の位置づけ（「あらゆるデータ構造の土台を成す」等、回への言及を伴わないもの）

## 6. 擬似コードの記法

特定言語の構文に依存しない。詳細は `figure-guide.md` と併せて参照する。

| 操作 | 記法 |
|------|------|
| 代入 | `a ← 3` |
| 比較 | `a = b`（等価）、`a ≠ b` |
| 手順 | 行頭に連番 `1.` `2.` |
| 制御構造 | 日本語で記述（「〜の間繰り返す」「もし〜ならば」） |

```
1. a ← 3
2. b ← 8
3. a ← b
4. b ← 5
```

以下は用いない:

- 特定言語の実行可能コード（`int a = 3;` `a = 3` 等、言語が特定できる形）
- 言語固有のライブラリ名・関数名
- セミコロン・波括弧等の言語固有の区切り記号

## 7. 図版のキャプション

形式: `図 [節番号]-[連番]　[説明文]`

- 節番号は `h2` の `.num` と一致させる
- 全角スペースで区切る
- 説明文は図が示す事実と、そこから読み取るべき含意を述べる

```html
<figcaption>
  図 3-1　代入は既存の値を上書きする。過去の値を保持したい場合は、
  別の変数に退避させるなど、明示的な手当てを要する。
</figcaption>
```

## 8. 注記ボックスの使い分け

| クラス | 用途 | ラベル例 |
|--------|------|---------|
| `.note` | 補足・到達点の提示 | 「本講の到達点」「補足」 |
| `.note.caution` | 誤りやすい点・注意喚起 | 「注意」「誤りやすい点」 |

`.label` には内容を表す短い語を入れる。
