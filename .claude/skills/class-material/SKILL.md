# 授業解説ページ生成スキル

授業テーマを入力として、話すべき要点の設計から行い、iPad投影用のスライドと学生の手元資料を兼ねる解説ページ（単一HTML）を生成するスキル。

## なぜこのスキルが必要か

小テスト・定期試験の生成（`class-test`）は整備済みだが、授業そのものを進行するための資料は手作業のままである。本スキルはシラバスの授業計画・到達目標を入力として解説ページを生成し、板書・スライド作成の負荷を削減する。

## このスキルの中核

**要点設計がスキルの主業務である。** ユーザーからの入力は授業テーマのみであり、何を話すべきかの構成設計はスキル側の責任である。

テーマを受け取った直後にHTMLを書き始めてはならない。Step 2 の要点設計とユーザー合意を必ず経由する。

## 前提条件

- シラバスMarkdownファイルが `output/` 配下に存在すること（`/class-syllabus` で事前に作成）
- シラバス解析を `/class-syllabus-parse` で実行済みであること（未実行の場合は Step 0 で案内する）

## 対話ルール

ユーザーへの質問・プレビュー・修正ループの作法は `specs/dialog-conventions.md` を正本とする。本スキルもこの規約に従う。

## 入出力契約

- **入力（シラバス情報）**: `class-syllabus-parse` がコンテキストに残す情報を利用する。契約は `specs/syllabus-markdown-schema.md` § 9 を参照
- **入力（小テスト）**: `output/[YYYY]_[教科名]/tests/[テスト名]/` 配下の既存成果物（`specs/output-layout.md`）
- **出力ファイルパス**: `output/[YYYY]_[教科名]/materials/`（`specs/output-layout.md`）

## 処理フロー

```
Step 0: シラバス情報の読み込み
Step 1: テーマの受け取りと授業回の特定
Step 1.5: 前提資材の検証 → 不足時の判断        ★生成前ゲート
Step 2: 要点の設計 → プレビュー → ユーザー合意   ★スキルの中核
Step 3: 直近の小テストの参照
Step 4: HTML生成（共通CSSの配置を含む）
Step 5: ファイル出力 → 完了レポート
```

### Step 0: シラバス情報の読み込み

シラバスの解析は `class-syllabus-parse` スキルに委譲する。会話コンテキストに既にシラバス情報が読み込まれているかを確認する。

- **読み込み済みの場合**: 抽出結果を再利用して Step 1 へ進む
- **未読み込みの場合**: 事前実行を案内する:
  ```
  解説ページの作成にはシラバス情報の解析が必要です。
  先に `/class-syllabus-parse` スキルを実行してシラバスを読み込んでください。
  ```

本スキルが利用する情報: 基本情報（教科名・開講年度・担当教員・対象学年・開講期・開設学科）、授業計画（週・授業内容・到達目標）、到達目標、評価割合のカテゴリキー、試験スケジュール。

### Step 1: テーマの受け取りと授業回の特定

プレーンテキストでテーマを受け取る。

```
解説ページを作成する授業のテーマを教えてください
（例: スタック・キュー）:
```

受け取ったテーマをシラバスの授業計画と照合し、該当する週を特定する。

- **単一の週に対応する場合**: その週を採用する
- **複数の週にまたがる場合**: `AskUserQuestion` で範囲を確認する
- **照合できない場合**: `AskUserQuestion` で候補の週を提示して選択させる（"Other" で範囲外のテーマも受け付ける）

ここで確定した週番号は、ファイル名の回次と Step 1.5 / Step 3 の小テスト判定に用いる。

### Step 1.5: 前提資材の検証（生成前ゲート）

要点設計に入る前に、入力として依拠する資材が揃っているかを検証する。不足に気づかないまま生成すると、シラバスとの不整合や小テスト連携の欠落が出力後まで発覚しない。

#### 1.5.1 シラバス側の検証

| 検証項目 | 不足時の扱い |
|----------|-------------|
| 基本情報（教科名・開講年度・担当教員・対象学年・開講期・開設学科） | 不足項目をユーザーに確認して補完する |
| 授業計画に対象回の行が存在する | Step 1 に差し戻す |
| 対象回の到達目標が記載されている | 警告し、テーマから設計してよいか確認する |
| 到達目標が `（要確認）` を含まない | 該当箇所をユーザーに提示して確定させる |

#### 1.5.2 小テストの検証

**まず当該科目に小テストが定義されているかを判定する。** 判定は評価割合のカテゴリキー `小テスト`（`specs/syllabus-markdown-schema.md` § 2.3）と試験スケジュール（同 § 3.2）による。定義されていない科目では本検証を行わず、小テスト連携ごとスキップして Step 2 へ進む。

小テストが定義されている場合、**対象回より前に実施される全ての小テスト**について成果物の作成状況を検証する:

1. シラバスから、実施週が対象回の週番号以前である小テストを全件列挙する
2. 各小テストについて `output/[YYYY]_[教科名]/tests/[テスト名]/` の存在を確認する
3. 存在する場合、`[テスト名]_確認用.md` と `[テスト名]_解説.md` が揃っているかを確認する

直近の1件ではなく先行する全件を対象とする。解説ページはその回までの学習内容の上に成り立つため、途中の回の小テストが欠けていれば織り込むべき論点の把握が不完全になる。

#### 1.5.3 不足時の扱い

検証結果を提示し、`AskUserQuestion` で判断を仰ぐ。

```
=== 前提資材の検証結果 ===
対象: 第[N]週「[テーマ]」

シラバス: [OK | 以下が不足]
  - [不足項目]

先行する小テスト（第[N]週以前）:
  ✓ 小テスト1（第5週）  作成済み
  ✗ 小テスト2（第8週）  未作成
  △ 小テスト3（第10週） 解説ファイルが不足
```

選択肢:

1. **不足分の小テストを作成する**: `/class-test` の実行を案内し、本スキルを一旦終了する
2. **このまま続行する**: 作成済みの小テストのみを連携対象とする。未作成分が織り込まれない旨を明示する
3. **中断する**

検証が全て OK の場合は、この確認を挟まず Step 2 へ進む。

### Step 2: 要点の設計（中核）

テーマと到達目標から、話すべき要点を設計する。設計の方法論は `references/content-design-guide.md` を参照する。

設計結果を以下の形式でプレビューし、`AskUserQuestion` で合意を取る。

```
=== 解説ページ構成案: [テーマ] ===
対象: 第[N]週 ／ 到達目標: [シラバスの到達目標]

1. [節タイトル]
   要点: [その節で述べること]
   図版: [有無と内容]
   確認問題: [問う論点]

2. ...

直近の小テスト: [テスト名]（第[M]週実施）
  織り込む論点: [論点1] / [論点2]
```

`AskUserQuestion` の選択肢: 「確定する」「節構成を修正したい」「確認問題を修正したい」「中断する」。

**合意が取れるまで HTML を生成しない。**

### Step 3: 直近の小テストの参照

Step 1.5 で作成済みと確認された小テストのうち、実施週が対象回の週番号以前であるもののうち最も週番号が大きいものを「直近の小テスト」とする。

`[テスト名]_確認用.md` と `[テスト名]_解説.md` を読み取り、出題論点を抽出する。織り込み方は `references/content-design-guide.md` の「直近の小テストの織り込み」を参照する。

### Step 4: HTML生成

`references/html-template.md` のテンプレートに従って生成する。

1. `output/[YYYY]_[教科名]/materials/assets/material.css` の存在を確認し、無ければ `references/material.css` をコピーする（**既存の場合は上書きしない**）
2. `materials/assets/kousho.svg` の存在を確認し、無ければ同一リポジトリ内の既存科目からコピーする
3. 単一HTMLを生成する

文体は `references/writing-style-guide.md`、図版は `references/figure-guide.md`、確認問題は `references/quiz-guide.md` に従う。

#### 生成後の必須チェック

- [ ] 予告・次回言及を含んでいないか
- [ ] 特定言語の構文に依存していないか（概念図・擬似コード中心か）
- [ ] 敬体が混入していないか
- [ ] 全ての `.quiz` に対応する `details.answer` があるか
- [ ] SVG内に色値の直書きが無いか
- [ ] 目次の `href` と `section` の `id` が対応しているか
- [ ] CSSへの `<link>` パスが `assets/material.css` になっているか

### Step 5: ファイル出力と完了レポート

ファイル単位の既存検出を行う（`specs/file-output-policy.md` § 1.2）。既存時は「上書きする / 別名で保存する / キャンセル」を提示する。

```
=== 解説ページを作成しました ===
出力先: output/[YYYY]_[教科名]/materials/[ファイル名].html
共通CSS: materials/assets/material.css（[新規作成 | 既存を再利用]）

構成: [N]節 ／ 確認問題 [M]問 ／ 図版 [K]点
織り込んだ直近小テストの論点: [論点]

ブラウザで開いて確認してください。
```

## ファイル命名規約

- 形式: `class[週番号]_[テーマ].html`
- 複数週にまたがる場合: `class[開始]-[終了]_[テーマ].html`
- 週番号はゼロ埋め2桁（`class01`, `class03`, `class01-02`）
- テーマ名は `specs/syllabus-markdown-schema.md` § 5.3 の共通ルールに従って正規化する
