1文字の列をトークンの列に分ける

字句解析(lexical analysis) は、ソースコードの文字の列を トークン(token) の列に切り分け、各トークンに種別を与える工程である。 正規表現と有限オートマトンを用いれば、ある文字列が「識別子」や「整数」の言語に属するかは判定できる。 しかし字句解析器が受け取るのは、一語ずつ区切られた文字列ではなく、ソースコード全体である。

多くの言語では、語と語の間の空白を省いてよい。x1<=25; と書いても x1 <= 25 ; と同じ意味になる。 このとき字句解析器は、どこで語が終わるかを自ら決めなければならない。 図 1-1 のとおり、全ての文字を余さず割り当てる切り方は一通りではない。

字句解析器が出力するトークンは、種別だけでなく、元の文字の並びと位置を伴う。 トークンとして切り出された文字の並びそのものを 字句(lexeme) と呼ぶ。 識別子 count と識別子 total は、種別は同じで字句が異なる。

表 1-1　トークンが持つ情報と、それを用いる工程。構文解析は種別の並びだけを見るが、字句と位置は後の工程と誤りの報告のために保持しておく。

本講では、次の事柄を扱う。

  • 移り先が一つに定まらない有限オートマトンと、それを移り先の定まる形に変換する手順
  • トークンの種別ごとの規則を一つの有限オートマトンにまとめる方法と、規則が競合したときの決め方
  • 入力の中からトークンを一つずつ切り出す規則である最長一致
  • 字句解析器の設計の流れと、プログラムとしての実装
本講の到達点
  • 非決定性有限オートマトンを部分集合構成法で決定性有限オートマトンに変換できる
  • 最長一致と規則の優先順位によって、入力がどのトークン列に切り分けられるかを説明できる
  • トークンの仕様から字句解析器を設計し、簡単な字句解析プログラムを作成できる
確認問題 1-1

構文解析器は、count < 10 と total < 99 を同じ形の式として扱う。その理由として最も適切なものはどれか。

  1. 構文解析はトークンの種別の並びを見ており、字句や値の違いは文法への適合に影響しないため
  2. 字句解析が識別子の字句と整数の値を捨て、種別だけを構文解析に渡すため
  3. 構文解析の時点では、count と total が宣言済みかどうかが分からないため
  4. 字句解析が、識別子を全て同じ字句に置き換えてから渡すため
解答

正解: (A)

どちらの式も「識別子、比較演算子 <、整数」という種別の並びである。 構文解析が確かめるのは、この並びが文法に適合するかであり、字句の違いは結果を変えない。

(B) は、構文解析が見ない情報は捨てられると考えた誤りである。字句と値はトークンに保持され、どの変数か、どの値かを扱う意味解析やコード生成が用いる。 (C) は、宣言の有無という別の検査を理由にしている。宣言の確認は意味解析の役割であり、二つの式を同じ形と扱う理由ではない。 (D) は、字句を書き換えると考えた誤りである。字句解析は字句をそのまま保持する。構文解析が字句を参照しないだけである。

2非決定性有限オートマトン

有限オートマトンのうち、どの状態でどの文字を読んでも移り先が高々一つに定まるものを 決定性有限オートマトン(deterministic finite automaton, DFA) と呼ぶ。 これに対し、次の二つを許すものを 非決定性有限オートマトン(nondeterministic finite automaton, NFA) と呼ぶ。

  • 同じ状態で同じ文字を読んだときの移り先が、複数ありうる
  • 文字を読まずに状態を移る遷移がありうる。これを ε 遷移(ε-transition) と呼ぶ

NFA が文字列を受理するのは、初期状態から、その文字列を読み終えて受理状態に至る経路が一つでもあるときである。 移り先の選び方によって受理状態に至らない経路があっても、受理状態に至る経路が一つあれば受理する。 DFA は、移り先の選択肢が常に一つしかない NFA とみなせる。

図 2-1 は、a と b からなり ab で終わる文字列、すなわち正規表現 (a|b)*ab の言語を受理する NFA である。

NFA を手で追うときは、経路を一本ずつ試す必要はない。その時点でありうる状態を全て集めた集合を、一文字ごとに更新すればよい。 集合の中の各状態から、読んだ文字で移れる状態を全て集めたものが、次の集合になる。 読み終えた時点の集合に受理状態が一つでも含まれていれば受理する。

表 2-1　図 2-1 の NFA に二つの文字列を読ませたときの、ありうる状態の集合の移り変わり。q0 は常に集合に残り、末尾が ab であるときに限り q2 が加わった状態で読み終える。

入力状態の集合の移り変わり読み終えた集合結果
aab {q0} →(a) {q0, q1} →(a) {q0, q1} →(b) {q0, q2} {q0, q2} q2 を含むため受理
aba {q0} →(a) {q0, q1} →(b) {q0, q2} →(a) {q0, q1} {q0, q1} 受理状態を含まないため受理しない

図 2-2 は、表 2-1 の二つの入力について、各時点の集合を状態ごとに並べたものである。 集合内の状態が、読んだ文字の遷移を持たなければ、その状態は次の集合に引き継がれない。 aab の二文字目の a では、q1 に a の遷移が無いため q1 からの経路は途切れる。しかし q0 から a で q1 へ移れるため、q1 は改めて加わり、集合は {q0, q1} のまま変わらない。 集合が空になった場合は、その後どの文字を読んでも受理されないことが確定する。

NFA を用いる利点は、正規表現から機械的に組み立てられることにある。 連接・選択・繰り返しのそれぞれについて小さな NFA の部品を定め、それらを ε 遷移でつなげば、どれほど長い正規表現からでも NFA が得られる。 この組み立て方を トンプソンの構成法(Thompson's construction) と呼ぶ。

図 2-3 は、a|b と ab* をこの方法で組み立てた NFA である。 選択 a|b は、ε 遷移で二つの部品に分かれ、それぞれの部品を読み終えた後に ε 遷移で一つの受理状態に合流する。 繰り返し b* は、b を読み終えた n3 から読み始めの n2 へ戻る ε 遷移で繰り返しを表し、n1 から n4 へ飛び越す ε 遷移で b を一度も読まない場合を表す。 ab* は、a の部品の後に b* の部品を連接したものである。

同じ言語の DFA を正規表現から直接作ろうとすると、図 2-1 で先送りした「どの a が末尾の a か」の判断を、設計者が状態の配置として解決しなければならない。

確認問題 2-1

次の NFA がある。初期状態は q0、受理状態は q2 である。この NFA は、0 と 1 からなり後ろから 2 文字目が 1 である文字列を受理する。 入力 110 に対する判定として正しいものはどれか。 

q0: 0 を読むと q0 へ。1 を読むと q0 または q1 へ
q1: 0 を読むと q2 へ。1 を読むと q2 へ
q2: 遷移なし
  1. 読み終えた時点のありうる状態の集合は {q0, q2} であり、q2 を含むため受理する
  2. q0 に留まり続けて q0 で読み終える経路があるため、受理しない
  3. 遷移の選び方によって結果が変わるため、受理するかどうかは定まらない
  4. 1 文字目を読んだ時点で移り先が二つあり、一つに定まらないため判定できない
解答

正解: (A)

ありうる状態の集合は、{q0} →(1) {q0, q1} →(1) {q0, q1, q2} →(0) {q0, q2} と移る。 最後の 0 で、q0 は q0 へ、q1 は q2 へ移り、q2 には遷移が無いため消える。読み終えた集合が受理状態 q2 を含むため受理する。 後ろから 2 文字目は 1 であり、言語の説明とも一致する。

(B) は、全ての経路が受理状態に至る必要があると考えた誤りである。NFA は受理状態に至る経路が一つでもあれば受理する。 (C) は、非決定性を無作為な選択と混同している。NFA の判定は全ての経路を考えた結果であり、入力ごとに一通りに定まる。 (D) は、移り先が複数あることを判定の失敗と取り違えている。移り先が複数あれば、その全てを状態の集合として追えばよい。

3部分集合構成法 — NFA から DFA へ

NFA は正規表現から作りやすいが、一文字ごとに状態の集合を更新する手間がかかる。 そこで、表 2-1 で追った状態の集合そのものを一つの状態とみなした DFAを、あらかじめ作っておく。 この変換手順を 部分集合構成法(subset construction) と呼ぶ。

手順には、ある状態の集合から ε 遷移だけをたどって到達できる状態を全て加えた集合を用いる。 これを ε 閉包(ε-closure) と呼ぶ。ε 遷移の無い NFA では、ε 閉包は元の集合と同じである。

図 2-3 の a|b の NFA では、初期状態 p0 から ε 遷移で p1 と p3 に到達できるため、{p0} の ε 閉包は {p0, p1, p3} となる。 ここで a を読むと、移れるのは p1 からの p2 だけである。{p2} の ε 閉包は、ε 遷移で到達できる p5 を加えた {p2, p5} となり、受理状態 p5 を含む。 ε 閉包は、読み始める前と、文字を読んで移った後の両方でとる。後者を怠ると、a を読み終えた時点で受理状態にあることを見落とす。 

1. NFA の初期状態の ε 閉包を、DFA の初期状態とし、未処理の一覧に入れる
2. 未処理の状態集合が残っている間、次を繰り返す
3.   未処理の一覧から状態集合 S を一つ取り出す
4.   入力に現れうる各文字 c について、次を行う
5.     T ← S の各状態から c で移れる状態を全て集め、その ε 閉包をとった集合
6.     もし T が空でなく、まだ現れていない集合ならば、DFA の新しい状態とし未処理の一覧に入れる
7.     DFA に「S で c を読むと T へ移る」遷移を加える
8. NFA の受理状態を一つでも含む集合を、DFA の受理状態とする

図 2-1 の NFA に適用する過程を図 3-1 に示す。この NFA には ε 遷移が無いため、ε 閉包は元の集合のままである。 未処理の一覧から集合を一つ取り出すたびに a と b の移り先を求め、まだ現れていない集合だけを一覧に加える。 一覧が空になった時点で、現れうる集合が出尽くしたことになり、手順は止まる。 状態の集合は有限通りしかないため、手順は必ず止まる。

B の行の b の欄は、q0 から b で移れる {q0} と、q1 から b で移れる {q2} を合わせた {q0, q2} である。 集合内の一部の状態だけでなく、全ての状態からの移り先を合わせることが、この手順の要点である。 表 3-1 を状態遷移図にしたものが図 3-2 である。

図 3-2 の DFA に aab を読ませると、A →(a) B →(a) B →(b) C と移り、受理状態 C で読み終える。 この状態の並びは、表 2-1 で NFA の集合を追った {q0} → {q0, q1} → {q0, q1} → {q0, q2} と一つずつ対応する。 NFA では一文字ごとに行っていた集合の計算を、DFA ではあらかじめ済ませて遷移として持っている。

部分集合構成法で得た DFA は、元の NFA と同じ言語を受理する。逆に DFA はそのまま NFA でもあるため、 NFA で受理できる言語と DFA で受理できる言語は一致する。どちらも正規言語の範囲である。 非決定性は表せる言語を広げるのではなく、オートマトンを組み立てやすくする。

状態数については注意を要する。NFA の状態が n 個であれば、その部分集合は 2n 通りあり、DFA の状態は最悪で 2n 個に達する。 このように変換で状態数が急増することを 状態爆発(state explosion) と呼ぶ。 例えば「後ろから k 文字目が 1」の言語は、NFA なら k + 1 個の状態で済むが、DFA では 2k 個の状態を要する。 直前の k 文字を全て覚えておかなければならないためである。 確認問題 2-1 の NFA は k = 2 の場合であり、部分集合構成法を適用すると、表 3-2 のとおり 22 = 4 個の状態が現れる。

確認問題 3-1

図 2-3 の ab* の NFA に部分集合構成法を適用する。DFA の初期状態 {n0} で a を読むと、{n1} の ε 閉包である {n1, n2, n4} に移る。 この状態 {n1, n2, n4} で b を読んだときの移り先として正しいものはどれか。

  1. {n3}
  2. {n3, n4}
  3. {n2, n3, n4}
  4. {n1, n2, n3, n4}
解答

正解: (C)

集合内で b の遷移を持つのは n2 だけであり、b を読むと n3 へ移る。n1 と n4 は b の遷移を持たないため引き継がれない。 次に {n3} の ε 閉包をとる。n3 からは ε 遷移で n2 と n4 に到達できるため、移り先は {n2, n3, n4} となる。 n2 を含むことで続く b も読め、n4 を含むことで ab で読み終えても受理できる。

(A) は、文字を読んで移った後の ε 閉包をとっていない。この集合は受理状態 n4 を含まず、ab を受理しない DFA になってしまう。 (B) は、ε 閉包で前へ進む ε 遷移だけをたどり、n2 へ戻る ε 遷移を見落としている。n2 が欠けると、abb のように b が二つ以上続く入力を受理できない。 (D) は、b の遷移を持たない n1 が集合に残ると考えた誤りである。遷移を持たない状態は次の集合に引き継がれない。

確認問題 3-2

NFA と、部分集合構成法で得た DFA に関する記述として、最も適切なものはどれか。

  1. 状態が n 個の NFA から得た DFA は、状態が 2n 個を超えず、元の NFA と同じ言語を受理する
  2. NFA は、DFA では受理できない言語も受理できる
  3. 部分集合構成法で得た DFA の状態数は、元の NFA の状態数より必ず少ない
  4. NFA の ε 遷移は DFA にも残るため、DFA でも一文字につき複数の遷移をたどる場合がある
解答

正解: (A)

DFA の各状態は NFA の状態の部分集合であり、部分集合は 2n 通りしかない。 また、DFA の判定は NFA の状態の集合を追う操作をそのまま表に置き換えたものであるため、受理する言語は変わらない。

(B) は、非決定性が表せる言語を広げると考えた誤りである。NFA と DFA が受理できる言語は一致し、だからこそ変換できる。 (C) は、状態数の上限と下限を取り違えている。変換で状態数が増えることは珍しくなく、「後ろから k 文字目」の言語では 2k 個に達する。 (D) は、ε 閉包の役割を見落としている。ε 遷移で到達できる状態は ε 閉包として集合に取り込まれるため、DFA には ε 遷移が残らない。

4複数のトークン規則を一つにまとめる

字句解析器は、識別子・整数・演算子など全ての種別を一つのオートマトンで判定する。 種別ごとの NFA が得られていれば、新しい初期状態を一つ設け、そこから各 NFA の初期状態へ ε 遷移を張るだけでまとめられる。 図 4-1 は、予約語 if の規則と、英字で始まり英字か数字が続く識別子の規則をまとめた NFA である。 予約語(reserved word) は、言語が特別な意味のために取り置いた語であり、キーワードとも呼ぶ。

この NFA に部分集合構成法を適用したものが表 4-1 である。初期状態は s の ε 閉包 {s, k0, d0} となる。 英字は i、f、それ以外の英字の三つに分けて扱う。この三つで移り先が異なるためである。

表 4-1　図 4-1 の NFA に部分集合構成法を適用した結果。C は二つの規則の受理状態 k2 と d1 を同時に含み、どちらの種別とするかを決める必要がある。

文字列 if は予約語の規則にも識別子の規則にも当てはまる。このように一つの DFA の状態が複数の規則の受理状態を含むときは、 あらかじめ規則に順位を付けておき、順位の高い規則の種別を採る。 この順位を 優先順位(priority) と呼び、多くの場合、規則を書いた順を優先順位とする。 予約語の規則を識別子の規則より先に書けば、C は予約語 if を受理する状態になる。

図 4-3 は、この DFA に四つの入力を読ませたものである。読み終えた状態が受理する種別が、その文字列の種別となる。 if と ifx は C まで同じ経路をたどり、三文字目の有無で種別が分かれる。x9 は一文字目で D に入り、予約語の経路を一度も通らない。

実用の字句解析器生成系は、この流れを自動で行う。種別ごとの正規表現をトンプソンの構成法で NFA にし、ε 遷移でまとめ、 部分集合構成法で DFA に変換し、受理状態ごとに優先順位で種別を一つに決める。 さらに、同じ振る舞いをする状態を併合して状態数を減らす 最小化(minimization) を行い、最終的に遷移表を出力する。

確認問題 4-1

図 4-2 の DFA の状態 C（NFA の状態の集合 {k2, d1}）に関する記述として、最も適切なものはどれか。

  1. 予約語 if と識別子の両方の受理状態を含むため、優先順位によって種別を一つに決める
  2. NFA の受理状態を二つ含み、どちらの種別とも決められないため、DFA の受理状態にはしない
  3. 二つの規則の受理状態が一つの集合に入るのは、部分集合構成法の適用を誤った結果である
  4. C に入った時点で予約語 if が確定するため、続く文字を読む必要はない
解答

正解: (A)

文字列 if は二つの規則のどちらの言語にも属するため、両方の受理状態が同じ集合に入る。 この競合は規則の優先順位で解決し、予約語の規則を先に置けば C は予約語 if を受理する状態となる。

(B) は、競合を受理の取り消しで解決しようとしている。C を受理状態から外すと、if がどの種別としても受理されなくなる。 (C) は、規則同士の言語が重なることを手順の誤りと取り違えている。予約語は識別子の形をしているため、重なりは必ず生じる。 (D) は、受理状態に入った時点で切り出しが終わると考えた誤りである。ifx のように後に英字が続けば D へ移り、識別子として読み続ける。

5最長一致による切り出し

まとめた DFA を用いて、入力からトークンを一つずつ切り出す。 図 1-1 で見たとおり、受理状態に入った時点で切るか、さらに読み進めるかによって結果が変わる。 字句解析では、次の規則で切り出し位置を決める。

  • 最長一致(longest match) — 受理できる限り長く読み進め、最後に受理状態にあった位置までを一つのトークンとする
  • 優先順位 — 最長の候補が複数の規則に当てはまるときは、優先順位の高い規則の種別とする

二つの規則は、まず長さで決め、長さが同じときに限って優先順位で決めるという順で適用する。 図 4-2 の DFA に ifx を読ませると、if まで読んだ時点で予約語の受理状態 C にあるが、 x も読めるため D まで進み、三文字の識別子 ifx となる。 優先順位が効くのは、if だけで読み終えたときのように、同じ長さで複数の規則が受理する場合だけである。 図 1-1 の入力 x1<=25; も、最長一致により <= が一つのトークンとなり、切り方 B に定まる。

行き詰まったら最後の受理位置まで戻る

読み進めた末に移り先が無くなったとき、その時点の状態が受理状態であるとは限らない。 受理状態を通り過ぎた後で行き詰まった場合は、最後に受理状態にあった位置まで戻ってトークンを確定し、戻った位置から次の切り出しを始める。 読みすぎた文字を入力に返すこの操作を 読み戻し と呼ぶ。 

1. 状態 ← DFA の初期状態、i ← start、最後の受理位置 ← なし
2. i が入力の長さ未満で、状態から 入力[i] で移れる間、次を繰り返す
3.   状態 ← 移り先、i ← i + 1
4.   もし 状態 が受理状態ならば、最後の受理位置 ← i、種別 ← その状態が受理する種別
5. もし 最後の受理位置 = なし ならば、start の位置で字句エラーとする
6. トークン ← 入力の start 番目から 最後の受理位置 − 1 番目までの文字と、種別
7. start ← 最後の受理位置（ここから次の切り出しを始める）

図 5-1 は、整数 [0-9]+、小数 [0-9]+\.[0-9]+、範囲を表す演算子 .. の三つの規則をもつ言語で、 入力 1..5 を切り出す様子である。範囲演算子を備える言語は多いが、その綴りは言語によって異なる。

長さと優先順位の適用順

図 5-2 は、擬似コードの 4 行目で記録する最後の受理位置と種別が、一文字ごとにどう変わるかを示したものである。 if の後に空白が続く入力では、i で位置 1・識別子が記録され、f で位置 2・予約語 if に上書きされる。 C は予約語と識別子の両方を受理するが、同じ長さであるため優先順位で予約語 if が記録される。 ifx= では、x を読んだ時点で記録がさらに位置 3・識別子に上書きされる。 受理状態に入るたびに記録が上書きされるため、長さが先に決まり、優先順位はその長さで受理した規則の中から種別を選ぶときにだけ働く。

一文字も受理できないまま行き詰まった場合、すなわち最後の受理位置が一度も記録されなかった場合は、その位置にどの規則にも当てはまらない文字の並びがある。 これを 字句エラー(lexical error) として報告する。 演算子 != をもち、! だけではトークンとしない言語での !x がその例である。 ! を読むと != の途中の状態に移るが、そこは受理状態ではなく、続く x で行き詰まる。戻る先となる記録が無いため、切り出せるトークンが無い。

確認問題 5-1

ある言語の演算子は <, <=, <<, = の四つであり、<<= は無い。 識別子は英字一文字以上の並びである。入力 a<<=b を最長一致で切り出した結果として正しいものはどれか。区切りを「|」で示す。

  1. a | < | <= | b
  2. a | << | = | b
  3. a | < | < | = | b
  4. <<= という演算子が無いため、字句エラーとなる
解答

正解: (B)

a を切り出した後、< の位置から始める。< を読んで受理し、続く < で << を受理する。 次の = では移り先が無いため、最後の受理位置である << で確定する。残りは = と b である。

(A) は、全体として長いトークンが現れる切り方を探している。最長一致は先頭から一つずつ、その位置で最も長いトークンを選ぶ規則であり、後のトークンを長くするために前のトークンを短くすることはない。 (C) は、最長一致を適用していない。<< を読めるのに < で止めている。 (D) は、行き詰まった時点で誤りとする考えである。最後の受理位置まで戻ればトークンを確定でき、字句エラーにはならない。

確認問題 5-2

整数 [0-9]+、小数 [0-9]+\.[0-9]+、ピリオド .、識別子の規則をもつ言語がある。 入力 7.x に対する最初の切り出しとして正しいものはどれか。

  1. 7. を切り出し、次の切り出しは x から始める
  2. 7 を切り出し、次の切り出しは . から始める
  3. 小数の途中で行き詰まったため、字句エラーを報告する
  4. 7 を切り出し、次の切り出しは x から始める
解答

正解: (B)

7 を読んで整数の受理状態に入り、. を読んで小数の途中の受理でない状態に移る。 x では移り先が無いため、最後の受理位置である 7 の直後まで戻ってトークン 7 を確定する。 読み戻した . から次の切り出しを始め、ピリオドと識別子 x が続く。

(A) は、行き詰まった位置で切っている。7. はどの規則にも受理されない文字の並びである。 (C) は、最後の受理位置を記録していることを見落としている。受理状態を一度通っていれば、そこまで戻ってトークンを確定できる。 (D) は、トークンの確定位置は正しいが、読みすぎた . を入力に返していない。読み戻しを行わないと、読んだ文字が失われる。

6字句解析器の設計

字句解析器を作る前に、何をトークンとし、何を読み捨て、何を誤りとするかを決める。設計は次の順で進める。

  1. トークンの種別を列挙し、それぞれを正規表現で定める。言葉で書いた規則は、007 や .5 のような境界の例で解釈が分かれる
  2. 予約語の扱いを決める。識別子の規則と重なるため、どちらの方式で区別するかを決める
  3. 読み捨てるものを決める。空白・改行・コメントはトークンを区切る役目だけをもち、構文解析には渡さない
  4. 構文解析器への渡し方を決める。トークンに持たせる情報と、入力の終わりの表し方を決める
  5. 誤りの扱いを決める。どの規則にも当てはまらない文字に出会ったとき、何を報告し、どこから再開するかを決める

予約語 while を、識別子として切り出した後に予約語表と照合して判定する字句解析器がある。 入力 whilex から得られるトークンとして正しいものはどれか。

  2. 識別子 whilex の一つ
  3. 予約語 while の一つ。続く x は字句エラーとなる
  4. 予約語表を識別子の規則より先に調べるように変えない限り、識別子 whilex とはならない
解答

正解: (B)

識別子の規則で最長一致により whilex の六文字を切り出し、その字句を予約語表と照合する。 whilex は表に無いため識別子となる。予約語表との照合は、切り出しが終わった後の字句全体に対して行う。

(A) は、予約語の判定を切り出しより先に行うと考えた誤りである。その順で処理すると、予約語で始まる識別子が全て二つに分かれてしまう。 (C) は、x がどの規則にも当てはまらないと考えている。x は英字であり、識別子の続きとして読まれる。 (D) は、照合の順序を入れ替えれば正しくなると考えている。実際には逆で、予約語表を先に調べると while と x に分かれる誤りが生じる。

確認問題 6-2

次の誤りのうち、字句解析の段階で検出できるものはどれか。

  1. どのトークンの規則にも当てはまらない文字 @ が現れる
  2. 宣言されていない変数 total が使われている
  3. 開き括弧 ( に対応する閉じ括弧が無い
  4. 整数の変数に文字列を代入している
解答

正解: (A)

字句解析が判定できるのは、文字の並びがトークンの規則に当てはまるかどうかである。 @ はどの規則の DFA でも初期状態から移り先が無く、最後の受理位置が記録されないため、字句エラーとなる。

(B) は、total を識別子として正しく切り出せるため、字句解析では誤りにならない。宣言の有無は記号表を用いる意味解析が調べる。 (C) は、入れ子の対応を数える必要があり、有限個の状態しか持たないオートマトンでは判定できない。構文解析が検出する。 (D) は、トークンの並びとしては正しく、型の不一致は意味解析が検出する。

7字句解析プログラムの実装

表 6-1 の仕様を、分岐で直接書く方式で実装する。入力の先頭の文字で種別の候補を絞り、その種別の規則に従って読み進める。 次の擬似コードは、入力全体をトークン列に変換する。 

字句解析(入力):
1. pos ← 0、行 ← 1、結果 ← 空の列
2. pos が入力の長さ未満である間、次を繰り返す
3.   c ← 入力[pos]
4.   もし c が改行ならば、行 ← 行 + 1、pos ← pos + 1 として 2. へ戻る
5.   もし c が空白かタブならば、pos ← pos + 1 として 2. へ戻る
6.   もし c が # ならば、改行の直前まで pos を進めて 2. へ戻る
7.   start ← pos
8.   もし c が英字か _ ならば
9.     英字・数字・_ が続く間、pos ← pos + 1
10.    種別 ← 識別子
11.  そうでなく c が数字ならば
12.    数字が続く間、pos ← pos + 1
13.    種別 ← 整数
14.  そうでなく c と 先読み(1) の二文字が二文字の演算子ならば
15.    pos ← pos + 2、種別 ← その演算子
16.  そうでなく c が一文字の演算子か区切り記号ならば
17.    pos ← pos + 1、種別 ← その記号
18.  そうでなければ
19.    行 と c を示して字句エラーを報告する
20.    pos ← pos + 1 として 2. へ戻る
21.  字句 ← 入力の start 番目から pos − 1 番目までの文字
22.  もし 種別 = 識別子 かつ 字句 が予約語表にあれば、種別 ← その予約語
23.  結果の末尾に (種別, 字句, 行) を加える
24. 結果の末尾に (入力の終わり, 空, 行) を加える
25. 結果を返す

先読み(k): もし pos + k が入力の長さ未満ならば 入力[pos + k] を、そうでなければ「終わり」を返す

この擬似コードは、DFA を表として持たないが、最長一致に従っている。 9 行目と 12 行目は、続けて読める限り読み進める繰り返しである。 14 行目で二文字の演算子を 16 行目の一文字の演算子より先に調べることで、<= を < と = に分けずに切り出す。 分岐を調べる順序が、最長一致と優先順位を表している。 この言語では、どのトークンも途中で受理状態でない状態を経ないため、読み戻しは要らない。小数のように途中に受理でない状態を経る規則を加える場合は、5 節の読み戻しが必要になる。

位置は二つの添字で管理する。start はトークンの先頭を、pos は次に読む文字を指す（図 7-1）。 pos はトークンの最後の文字ではなく、その次の文字を指すため、字句は start 番目から pos − 1 番目までとなり、その長さは pos − start である。

確認問題 7-1

7 節の擬似コードをもとに作成した字句解析プログラムは、入力 x = 1; を正しく処理できるが、入力 a $ b を与えると処理が終わらなくなった。 原因として最も適切なものはどれか。

  1. 字句エラーを報告した後、pos を進めずに繰り返しの先頭へ戻っている
  2. 空白を読み捨てる分岐で、pos を進めていない
  3. 予約語表に $ が登録されていない
  4. 二文字の演算子を、一文字の演算子より先に調べている
解答

正解: (A)

$ はどの規則にも当てはまらないため、字句エラーの分岐に入る。ここで pos を進めないと、次の繰り返しで再び同じ $ を読み、同じ報告を限りなく繰り返す。 x = 1; は字句エラーの分岐を通らないため、この誤りが表に出ない。

(B) は、x = 1; も空白を含むことと矛盾する。空白の分岐が誤っていれば、そちらでも処理が終わらなくなる。 (C) は、予約語表の役割を取り違えている。予約語表は識別子として切り出した字句を照合するためのものであり、$ は識別子として切り出されない。 (D) は、正しい順序を原因と考えている。長い候補を先に調べるのは最長一致のための正しい順序であり、処理が終わらない原因にはならない。

8総括

  • 文字の列をトークンの列に分ける — 区切りのない入力は複数の切り方を許すため、切り方を一つに定める規則が要る。 トークンは種別・字句・位置をもち、構文解析は種別の並びを、後の工程は字句を用いる。
  • 非決定性有限オートマトン — 移り先が複数ありうる遷移と ε 遷移を許し、受理状態に至る経路が一つでもあれば受理する。 ありうる状態の集合を追えば判定でき、読んだ文字の遷移を持たない状態は集合から消える。トンプソンの構成法により、正規表現から機械的に組み立てられる。
  • 部分集合構成法 — NFA の状態の集合を DFA の一つの状態とし、集合内の全状態からの移り先を合わせ、その ε 閉包をとって遷移を定める。 未処理の一覧が空になるまで繰り返す。 NFA と DFA が受理できる言語は一致するが、DFA の状態数は最悪で 2n 個になる。
  • 複数のトークン規則を一つにまとめる — 新しい初期状態から各規則の NFA へ ε 遷移を張って変換する。 複数の規則の受理状態を含む状態の種別は、優先順位で決める。
  • 最長一致による切り出し — 受理できる限り読み進め、最後に受理状態にあった位置で切る。長さが同じときに限り優先順位で種別を決める。 行き詰まったら最後の受理位置まで読み戻し、受理位置が一度も記録されなければ字句エラーとする。
  • 字句解析器の設計 — トークンの種別と正規表現、予約語の扱い、読み捨てるもの、構文解析器への渡し方、誤りの扱いを順に決める。 手で書く場合は、識別子として切り出した後に予約語表と照合する。
  • 字句解析プログラムの実装 — 先頭の文字で分岐し、長い候補から順に調べることで最長一致を実現する。 全ての分岐で位置を進めること、字句の範囲を start と pos で正しく取ることを、境界の例で確かめる。
