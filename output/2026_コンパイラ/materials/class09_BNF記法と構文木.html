1入れ子の構造を有限の規則で書く

構文解析は、字句解析が切り出したトークン列を受け取り、その並びが言語の規則に適合するかを調べて、適合するなら構造を木の形で表す工程である。 この工程を組むには、まず「正しい並び」を過不足なく定める必要がある。

プログラムの並びには入れ子が現れる。(a + (b * c)) - d のように括弧の中に括弧を含む式、 ブロックの中にさらにブロックを含む文、関数呼び出しの引数に別の関数呼び出しを書く式などである。 括弧の対応を判定するには、開いたままの括弧の個数、すなわち入れ子の深さを覚えておく必要がある。 図 1-1 は、((a + b) + c) を一記号ずつ読み、読んだ直後の深さを記したものである。

有限オートマトンでこの深さを覚えるには、深さごとに別の状態を用意するほかない。 深さ k までの状態しか持たないオートマトンは、k + 1 個目の ( を続けて読んだとき、移るべき状態を持たない。 有限個の状態では、深さに上限のない入れ子は判定できない。 したがって、正規表現でこれらの並びを定めることもできない。 語の綴りを字句解析に、語の並びを構文解析に受け持たせる分担は、この限界に由来する。

自分自身を参照する定義

括弧で囲める式を言葉で定めると、次のようになる。

  • 規則 1：識別子は式である
  • 規則 2：式と式を + でつないだものは式である
  • 規則 3：式を ( と ) で囲んだものは式である

この定義は「式」を定めるのに「式」を用いている。定義の中で定義される対象そのものを参照する書き方を 再帰的定義(recursive definition) と呼ぶ。 規則は三つしかないが、規則 3 を何度でも適用できるため、どれほど深い入れ子の式もこの定義に含まれる。

図 1-2 は、((a + b) + c) が式であることを、内側から規則を当てはめて確かめたものである。 a, b, c がそれぞれ規則 1 で式となり、規則 2 と規則 3 を交互に当てはめるたびに、式を表す範囲が一回り外へ広がる。

深さを状態として覚えるのではなく、規則を適用した回数として構造に刻む点が、有限オートマトンとの違いである。 正規表現の繰り返し * も同じ記述を何度でも適用できるが、繰り返すのは左から右への連接である。 a*b* は a の並びの後に b の並びが続く文字列を表すが、両者の個数を揃えることはできない。 一方、「S は ab であるか、a と S と b をこの順に並べたものである」と再帰的に定めると、 規則を一回適用するたびに a と b が一つずつ同時に増えるため、個数は常に揃う（図 1-3）。 ( を a、) を b と読み替えれば、これは括弧が対応した入れ子の並びである。

確認問題 1-1

次の規則のうち、正規表現では定められず、再帰的定義を要するものはどれか。

  1. 小数点を一つ含んでもよい数値リテラルの綴り
  2. 括弧を何重にでも入れ子にできる算術式の並び
  3. キーワード if と、if で始まる識別子 ifx の区別
  4. 英字で始まり、長さが 31 文字以下である識別子の綴り
解答

正解: (B)

括弧の対応を確かめるには、開いたままの括弧の個数を覚える必要がある。 入れ子の深さに上限がないため、有限個の状態では足りず、正規表現でも定められない。 「式を括弧で囲んだものは式である」という再帰的定義によって初めて書き表せる。

(A) は規則がやや複雑に見えるが、数字の繰り返しと省略可能な小数部の連接であり、正規表現で書ける。 (C) は最長一致で ifx を読み切った後にキーワード表と照合すれば区別でき、字句解析の範囲で解決する。 (D) は長さを数えているが、上限が決まっているため、読んだ文字数ごとに状態を並べれば有限個で足りる。

2文脈自由文法 — 終端記号・非終端記号・生成規則

再帰的定義を記号で書き表す枠組みを 文脈自由文法(context-free grammar) と呼ぶ。 文脈自由文法は、次の四つの要素で一つの言語を定める。

  • 終端記号(terminal symbol) — 文を実際に構成する記号。これ以上置き換えられない
  • 非終端記号(nonterminal symbol) — 記号列のまとまりに付けた名前。「式」「文」のような構文上の単位を表す
  • 生成規則(production rule) — 非終端記号を、終端記号と非終端記号を並べた記号列に置き換えてよいことを定める規則
  • 開始記号(start symbol) — 非終端記号のうち、文全体を表すもの

生成規則は 左辺 → 右辺 の形で書く。1 節の「a と b の個数が揃った並び」は、次の文法で定まる。 

S → a S b
S → a b

左辺が同じ規則は | でまとめ、S → a S b | a b と書いてよい。 | は規則を区切る記号であり、これで規則が一つになるわけではない。 右辺に記号を一つも置かない規則も許され、その右辺を空文字列 ε で表す。 括弧が正しく対応した並びの全体は、ε を用いて S → ( S ) S | ε と定まる。

開始記号 S から始め、S を規則の右辺で一つずつ置き換えていくと、この文法が ()() を生み出す過程を追える。 一回の置き換えを ⇒ で表すと、図 2-1 のように五回で終端記号だけの並びに行き着く。 S → ε を適用した段では、S が何も残さずに消える。

表 2-1　文脈自由文法の構成要素と、文法 S → a S b | a b における具体例。文法は記号の集合と規則の集合の組であり、規則の数は | で区切られた右辺の数に等しい。

構成要素役割S → a S b | a b での例
終端記号文に実際に現れる記号a, b
非終端記号置き換えの対象となる構文上の単位S
生成規則非終端記号の置き換え方S → a S b と S → a b の二つ
開始記号置き換えを始める非終端記号S

文脈自由(context-free) という名は、生成規則の左辺が非終端記号一つだけであることに由来する。 非終端記号は、その前後にどの記号が並んでいるか（文脈）によらず、同じ規則で置き換えられる。 左辺に前後の記号を書き、置き換えてよい場面を限る文法もあるが、プログラミング言語の構文の記述には一般に文脈自由文法が用いられる。

終端記号はトークンである

構文解析に用いる文法では、終端記号は文字ではなくトークンの種別である。 構文解析が受け取るのは字句解析が出力したトークン列であり、文字の並びではないためである。 図 2-2 は、ソースコード x1 = 42 + y が文法の終端記号の列になるまでを示したものである。

識別子を一つの終端記号 id で、整数リテラルを num で表し、 x1 であるか y であるかという綴りの違いは文法では区別しない。 綴りや値はトークンに添えられた情報として後段の処理へ引き継がれる。 空白やコメントはトークンとして残らないため、文法にも現れない。

誤りやすい点

二文字以上からなる演算子は、一つの終端記号である。<= は最長一致によって一つのトークンとして切り出されるため、 文法では < と = の二つを並べたものではなく、<= という一つの記号として扱う。

確認問題 2-1

次の文法で、終端記号は id, num, <, <=, = である。 ソースコード中の x1 <= 25 が構文解析に渡されるとき、この文法の終端記号の列として正しいものはどれか。 

条件 → 項 比較 項
比較 → < | <= | =
項   → id | num
  1. x 1 < = 2 5
  2. id < = num
  3. id <= num
  4. 項 比較 項
解答

正解: (C)

字句解析は x1 を識別子、<= を演算子、25 を整数リテラルとして切り出す。 構文解析が受け取るのはこの三つのトークンの種別であり、終端記号の列は id <= num となる。

(A) は終端記号を文字と混同している。文法の終端記号はトークンであり、文字ではない。 (B) は <= を二つのトークンに分けている。最長一致により <= は一つのトークンとして切り出され、 < の後に = が続く列は、この文法の 比較 のどの規則にも当てはまらない。 (D) は非終端記号の列である。非終端記号は文法の中の名前であり、構文解析への入力には現れない。

確認問題 2-2

文法 S → a S b | a b（開始記号は S）について、正しい記述はどれか。

  1. この文法の生成規則は二つである
  2. a と b は、S と同じく非終端記号である
  3. 規則 S → a S b だけを残しても、ab を含む同じ言語を定める
  4. この文法が定める文の長さには上限がある
解答

正解: (A)

| は左辺が同じ規則をまとめて書くための区切りであり、S → a S b と S → a b の二つの規則を表す。

(B) の a と b は、どの規則の左辺にも現れず置き換えられないため、終端記号である。 (C) では、S を置き換えても必ず新しい S が残るため、終端記号だけの列に行き着かない。S → a b は再帰を終わらせる規則として欠かせない。 (D) は、規則の数が有限であることと文の長さを混同している。S → a S b は何度でも適用できるため、文の長さに上限はない。

3BNF と EBNF

文脈自由文法を文書に書き表す記法として広く用いられるのが BNF(Backus-Naur form) である。 プログラミング言語の仕様書の多くは、この記法かその拡張で構文を示している。

  • 非終端記号を山括弧で囲み、<式> のように書く
  • 生成規則の矢印 → の代わりに ::= を用いる
  • 右辺の選択肢を | で区切る
  • 山括弧で囲まれていない記号は終端記号である

次は、代入文・if 文・関数呼び出しを BNF で書いた例である。id は識別子のトークン、if と else はキーワードのトークンを表す。 <式> の規則は省略している。 

<文>       ::= <代入文> | <if文>
<代入文>   ::= id = <式> ;
<if文>     ::= if ( <式> ) <文> | if ( <式> ) <文> else <文>
<呼び出し> ::= id ( ) | id ( <引数並び> )
<引数並び> ::= <式> | <引数並び> , <式>

<if文> の右辺に <文> が現れ、<文> の右辺に <if文> が現れる。 二つの規則が互いを参照することで、if 文の中に if 文を書く入れ子が表される。 <引数並び> は自身を右辺に含み、, で区切った式を何個でも並べられる。

図 3-1 は、f(x, y, z) のトークン列 id ( id , id , id ) を <呼び出し> に当てはめたものである。 <引数並び> は、二つ目の選択肢を適用するたびに右端へ , <式> を一組加えて伸び、 最も内側で一つ目の選択肢 <式> を適用して止まる。引数が三つなら、二つ目の選択肢を二回、一つ目の選択肢を一回適用する。

EBNF — 省略と繰り返しの略記

BNF では、省略できる部分や繰り返しを表すたびに規則を書き分けるか、補助の非終端記号を設ける必要がある。 これを略記できるようにした記法を EBNF(extended BNF) と呼ぶ。 上の <if文> と <呼び出し> は、EBNF では次のように一行で書ける。 

<if文>     ::= "if" "(" <式> ")" <文> [ "else" <文> ]
<呼び出し> ::= id "(" [ <式> { "," <式> } ] ")"

EBNF では [ ], { }, ( ) が記法の側の記号になる。 文法の記述に用いる記号を、記述される言語の記号と区別して メタ記号(metasymbol) と呼ぶ。 終端記号の ( とメタ記号の ( が紛れるため、EBNF では記号そのものを表す終端記号を引用符で囲む。id のようにトークンの種別を表す名前は囲まない。

あるトークン列が EBNF の規則に当てはまることは、列の各部分を規則の各部分に割り当てられることを意味する。 図 3-2 は、id ( id , id , id ) と id ( ) を <呼び出し> の規則に割り当てたものである。

逆に、どう割り当てても食い違いが出る列は、規則に当てはまらない。 図 3-3 の id ( , id ) では、( の直後に , が来ている。 [ ] を採用するなら ( の直後は <式>、省略するなら ) でなければならず、, はどちらにも当たらない。

表 3-1　EBNF の略記と、それを BNF に書き直した形。どの略記も補助の非終端記号 <A> を一つ設ければ BNF で書けるため、EBNF で定められる言語は BNF と変わらない。正規表現の略記と同じ関係である。

EBNF意味BNF での書き直し対応する正規表現
[ x ]x を省いてもよい（0 回か 1 回）<A> ::= ε | xx?
{ x }x を 0 回以上繰り返す<A> ::= ε | x <A>x*
( x | y )まとまりの中で x か y を選ぶ<A> ::= x | y(x|y)

EBNF は規則の数が少なく、言語の仕様として人が読むには向く。 一方、繰り返しを { } で書くと、並んだ要素が左から順にまとまるのか右からまとまるのかが規則から読み取れなくなる。 この違いが効くのは、演算子の結合の向きを文法で定めたい場合である（7 節）。 記法の細部は文書によって異なり、::= の代わりに = や : を用いるもの、非終端記号を山括弧で囲まないものもある。 文法を読む際は、その文書の冒頭にある記法の説明を確かめる必要がある。

確認問題 3-1

EBNF の規則 <並び> ::= num { "," num } と同じ言語を定める BNF の規則はどれか。

  1. <並び> ::= num | <並び> , num
  2. <並び> ::= num | num , num
  3. <並び> ::= ε | num , <並び>
  4. <並び> ::= num , <並び>
解答

正解: (A)

EBNF の規則は、num の後に「, と num の組」を 0 回以上続けた列を表す。 (A) は、num 一つか、既にある並びの後に , num を一組付け足したものを並びとする。 付け足しは何度でも行えるため、同じ列の全体を定める。

(B) は繰り返しを一回に限っており、num , num , num を含まない。 (C) は空の列と、num , のように末尾に , が残る列を含み、num 一つだけの列を含まない。 (D) には再帰を終わらせる選択肢がない。<並び> を置き換えるたびに新しい <並び> が残るため、終端記号だけの列に行き着かず、一つの列も定めない。

確認問題 3-2

本節の EBNF の規則 <呼び出し> ::= id "(" [ <式> { "," <式> } ] ")" について、<式> が id 一つで置き換えられるものとする。 <呼び出し> に当てはまらないトークン列はどれか。

  1. id ( )
  2. id ( id )
  3. id ( id , id , id )
  4. id ( id , )
解答

正解: (D)

{ "," <式> } は , と式を必ず組にして繰り返す。, の後に式が続かない (D) は当てはまらない。

(A) は [ ] の中身を丸ごと省いた場合であり、引数のない呼び出しとして当てはまる。 (B) は [ ] の中身を採り、{ } を 0 回とした場合である。 (C) は { } を 2 回繰り返した場合である。{ } の繰り返しは 0 回以上であり、回数に上限はない。

4導出 — 開始記号から文を生み出す

文法がどの記号列を定めるかは、開始記号から出発して生成規則を一回ずつ適用し、非終端記号を置き換えていく手順で確かめられる。 この手順を 導出(derivation) と呼び、一回の置き換えを ⇒ で表す。

本節以降では、次の文法 G を例に用いる。開始記号は E（式）であり、id は識別子のトークンを表す。 

E → E + E | E * E | ( E ) | id

ソースコードの a + b * c は、字句解析を経て id + id * id というトークン列になる。 この列が文法 G の文であることは、次の導出で示される。 

E ⇒ E + E ⇒ id + E ⇒ id + E * E ⇒ id + id * E ⇒ id + id * id

開始記号から導出できる記号列を 文形式(sentential form) と呼ぶ。 途中に現れる、終端記号と非終端記号の混じった記号列も文形式である。非終端記号が一つも残らない文形式が文である。 文法 G が定める言語 L(G) とは、開始記号から導出できる文の全体である。

置き換える位置の選び方

文形式に非終端記号が複数あるとき、どれを先に置き換えてもよい。 図 4-1 は、常に最も左の非終端記号を置き換えている。この導出を 最左導出(leftmost derivation) と呼ぶ。 常に最も右の非終端記号を置き換える導出を 最右導出(rightmost derivation) と呼ぶ。 同じ id + id * id の最右導出を図 4-2 に示す。各段の番号は、図 4-1 で同じ非終端記号に同じ規則を適用した段の番号である。

最左導出と最右導出は途中の文形式が異なるが、どの非終端記号にどの規則を適用したかの組は同じである。 どちらも、最初の E に E → E + E を、その右の E に E → E * E を、残る三つの E に E → id を適用している。 違うのは適用の順序だけであり、最左導出は ①②③④⑤、最右導出は ①③⑤④② の順に適用する。

導出できない列

どの順序で置き換えても行き着かない列は、文法の言語に属さない。 たとえば id + * id は文法 G の文ではない。 文法 G で + の右に置かれるのは E であり、E から導出される列は必ず id か ( で始まる。 ある記号の直後に来うる記号は規則の形から限られ、+ の直後に * が来る並びはどの規則からも生じない。

確認問題 4-1

文法 G（E → E + E | E * E | ( E ) | id、開始記号は E）から導出できないトークン列はどれか。

  1. id
  2. ( ( id ) )
  3. id ( id )
  4. id * id + id
解答

正解: (C)

文法 G で ( を置くのは E → ( E ) だけであり、( は E が置かれていた位置の先頭に来る。右辺に現れる E の直前は常に +, *, ( のいずれかか右辺の先頭であるため、( の直前に来うるのもこれらの記号か列の先頭に限られる。 id の直後に ( が続く並びはどの規則からも生じない。関数呼び出しに似た形であるが、文法 G はその規則を持たない。

(A) は E → id を一回適用するだけで導出できる。式には演算子が必要だという思い込みがあると誤る。 (B) は E → ( E ) を二回、続けて E → id を適用すれば導出できる。括弧の入れ子に回数の制限はない。 (D) は E → E + E の左の E に E → E * E を適用すれば導出できる。文法 G は演算子の並ぶ順序を制限していない。

確認問題 4-2

文法 G でトークン列 ( id ) * id を最右導出する。一段目は E ⇒ E * E である。二段目の文形式はどれか。

  1. ( E ) * E
  2. E * id
  3. ( E ) * id
  4. E * ( E )
解答

正解: (B)

最右導出では最も右の非終端記号を置き換える。E * E の右の E は、最終的に id になる位置にあるため、E → id を適用して E * id を得る。 以降は ( E ) * id、( id ) * id と続く。

(A) は左の E を先に置き換えており、最左導出の二段目である。 (C) は二つの E を一度に置き換えている。一回の導出で置き換えるのは非終端記号一つだけである。 (D) は右の E を括弧に置き換えているが、目標の列で * の右にあるのは id であり、括弧ではない。

5構文木と抽象構文木

導出で適用した規則を木の形に描いたものを 構文木(parse tree) と呼ぶ。 次の手順で描く。

  • 根には開始記号を置く
  • 非終端記号 A に規則 A → X1 X2 … Xn を適用したら、A の子として X1 から Xn を左から順に置く
  • 内部の節点は非終端記号、葉は終端記号（右辺が ε の規則を適用した箇所では ε）となる

図 5-1 は、図 4-1 の最左導出を一段ずつ木に描き加えたものである。 各段で、置き換えた非終端記号の節点（強調）が、規則の右辺の記号を子として得る。 各段の木の葉を左から読むと、その段の文形式になる。

構文木の葉を左から順に読むと、導出した文に一致する。 木が記録するのは「どの非終端記号にどの規則を適用したか」であり、適用の順序は記録しない。 このため、4 節の最左導出と最右導出は同じ一つの構文木を与える。 導出の順序という本質的でない違いが木の上では消え、文の構造だけが残る。

後段の処理に要る情報だけを残す

構文木は文法の規則をそのまま写すため、構造の決定に使い終えた記号も含んでいる。 括弧は、どの部分を先にまとめるかを指定する役目を持つが、その指定は木の形に既に反映されている。 非終端記号 E の節点も、そこに式があるという情報以上のものを持たない。

そこで、演算子を内部の節点、被演算子をその子とし、構造の決定にだけ用いた記号を除いた木を作る。 この木を 抽象構文木(abstract syntax tree, AST) と呼ぶ。 これと区別する場合、文法の規則をそのまま写した構文木を 具象構文木(concrete syntax tree) と呼ぶ。

例として (a + b) * c を考える。字句解析を経たトークン列は ( id + id ) * id であり、文法 G から次のように最左導出される。 

E ⇒ E * E ⇒ ( E ) * E ⇒ ( E + E ) * E ⇒ ( id + E ) * E ⇒ ( id + id ) * E ⇒ ( id + id ) * id

規則の適用は 6 回である。この導出が与える構文木と、同じ式の抽象構文木を並べたものが図 5-2 である。

意味解析は木をたどり、各演算子について被演算子の型が適合するかを調べる。 コード生成は、木の下から順に演算を並べて命令列を作る。 どちらの処理が必要とするのも、どの演算子がどの被演算子に作用するかであり、括弧や E の節点はたどる手間を増やすだけである。 構文解析の出力として後段に渡されるのは、多くの処理系では抽象構文木である。 「構文木」という語は文献によって両方の木を指すため、どちらの意味かを文脈で確かめる必要がある。

木のたどり方の一つに、ある節点の子をすべて訪れてからその節点を訪れる順序がある。これを 帰りがけ順(post-order) と呼ぶ。 抽象構文木を帰りがけ順にたどると、演算子に着いた時点でその被演算子の計算は済んでいる。 図 5-3 は、図 5-2 の抽象構文木を帰りがけ順にたどり、演算子を訪れるたびに計算を一つ書き出したものである。 t1, t2 は途中の結果を置く場所を表す。

表 5-1　構文木と抽象構文木の比較。構文木は文法の形に従い、抽象構文木は計算の構造に従う。同じ言語の文法を書き換えると構文木の形は変わるが、抽象構文木は変わらない。

観点構文木（具象構文木）抽象構文木
内部の節点非終端記号演算子・文の種類（代入、if など）
括弧・区切り記号葉として残る木の形に反映し、記号は除く
形を決めるもの文法の規則の立て方処理系の設計者が定めた節点の種類
葉の並び入力のトークン列に一致する入力のトークン列に一致するとは限らない
主な用途文法と入力の対応の確認意味解析・最適化・コード生成への受け渡し

抽象構文木にすると、文法の細部を書き換えても後段の処理は影響を受けない。この利点は、文法の書き換えが起こりうる言語ほど大きい。 ただし、抽象構文木にどの節点を設けるかに決まった形はなく、処理系によって異なる。 また、ソースコードの体裁を保ったまま書き換える整形ツールのように、括弧やコメントの位置を必要とする用途では、除いた情報を別に保持する必要がある。

確認問題 5-1

文法 G のもとで、二つの式 (a + b) * c と ((a + b)) * c を比べる。正しい記述はどれか。

  1. 抽象構文木は同じであり、構文木は異なる
  2. 抽象構文木も構文木も同じである
  3. 構文木は同じであり、抽象構文木は二つ目の式のほうが節点が多い
  4. 抽象構文木も構文木も異なり、二つ目の式は二つ目の括弧を表す節点を抽象構文木に持つ
解答

正解: (A)

二つ目の式では E → ( E ) が一回多く適用されるため、構文木には E の節点と括弧の葉が一組多く現れる。 一方、どちらの式も「a と b の和に c を掛ける」という同じ計算を表し、抽象構文木は根が *、その子が + と c の同じ形になる。

(B) は、構文木も括弧を除いた形だと考えている。構文木は適用した規則をすべて写すため、余分な括弧の分だけ節点が増える。 (C) は二つの木の性質を取り違えている。括弧の数に応じて変わるのは構文木の側である。 (D) は、抽象構文木が括弧を節点として残すと考えている。括弧の役目は木の形に置き換わり、記号は除かれる。

確認問題 5-2

構文木（具象構文木）について、正しい記述はどれか。

  1. 同じ文の最左導出と最右導出からは、異なる構文木が得られる
  2. 内部の節点は終端記号であり、葉は非終端記号である
  3. 葉を左から順に読むと、導出した文に一致する
  4. 葉の個数は、導出で生成規則を適用した回数に等しい
解答

正解: (C)

規則の右辺の記号を左から順に子として置くため、葉の並びは導出の最後に得られる文そのものである。

(A) は、木が適用の順序を記録すると考えている。木が記録するのはどの非終端記号にどの規則を適用したかだけであり、最左導出と最右導出は同じ木を与える。 (B) は内部と葉を逆にしている。子を持つのは置き換えられる非終端記号であり、置き換えられない終端記号は葉になる。 (D) は、規則の適用回数と葉の数を混同している。規則一回の適用が作るのは内部の節点一つであり、図 5-2 の構文木では規則を 6 回適用しているが、葉は 7 個である。

6あいまいな文法

文法 G で id + id * id を導出する方法は、4 節の導出だけではない。 最初に E → E * E を適用し、その左の E に E → E + E を適用しても、同じ列に行き着く。 これも最左導出である。 

E ⇒ E * E ⇒ E + E * E ⇒ id + E * E ⇒ id + id * E ⇒ id + id * id

二つの導出は、どの非終端記号にどの規則を適用したかが異なるため、異なる構文木を与える。 図 6-1 はその二つの木である。

ある文に対して構文木が二つ以上存在する文法を あいまい(ambiguous) な文法と呼ぶ。 文法 G はあいまいである。 構文木が異なれば、それをもとに作る抽象構文木も、意味解析とコード生成の結果も異なる。 あいまいな文法だけでは、一つの文に一つの意味を定められない。

誤りやすい点

最左導出と最右導出があることは、あいまいさではない。5 節で見たとおり、両者は同じ構文木を与えうる。 あいまいさは構文木が複数あることで定まり、導出で言い換えるなら、一つの文に最左導出が二通り以上あることに当たる。

あいまいさは文法の性質であって、言語の性質ではない。 文法 G と同じ言語を定め、どの文にも構文木を一つしか与えない文法が存在する（7 節）。 一方、任意の文脈自由文法があいまいかどうかを判定する一般的な手順は存在しないことが知られている。 そのため、言語の設計では、あいまいにならないことが分かっている規則の型を用いて文法を組み立てる。

確認問題 6-1

文法があいまいであることの説明として、正しいものはどれか。

  1. ある文について、最左導出と最右導出がともに存在する
  2. ある文について、構文木が二つ以上存在する
  3. 文法が定める言語に、無限個の文が含まれる
  4. ある生成規則の右辺に、左辺と同じ非終端記号が現れる
解答

正解: (B)

あいまいさは、一つの文に構文木が複数あることで定まる。木が異なれば文の構造の解釈が異なり、意味が一つに定まらない。

(A) は導出の順序の違いと構造の違いを混同している。どの文にも最左導出と最右導出があり、それらは同じ木を与えうる。 (C) は言語の大きさとあいまいさを混同している。S → a S b | a b は無限個の文を定めるが、どの文にも構文木は一つしかない。 (D) は再帰とあいまいさを混同している。再帰は入れ子を表すために欠かせず、それだけであいまいになるわけではない。

確認問題 6-2

文法 E → E - E | id で a - b - c を考える。a = 10, b = 4, c = 3 とするとき、構文木の違いによって得られる計算結果として正しいものはどれか。

  1. 演算子が一種類なので構文木は一つであり、結果は 3 だけである
  2. 構文木は二つあり、結果は 3 と 9 である
  3. 構文木は二つあり、どちらも左から計算するため結果は 3 だけである
  4. 構文木は一つであり、右から計算するため結果は 9 だけである
解答

正解: (B)

根で E → E - E を適用したとき、a - b を左の E にまとめる木と、b - c を右の E にまとめる木の二つがある。 前者は (10 - 4) - 3 = 3、後者は 10 - (4 - 3) = 9 である。演算子が一種類でも、まとめ方の違いによってあいまいさは生じる。

(A) は、あいまいさが異なる演算子の組合せでしか生じないと考えている。 (C) は、計算の順序が木と別に決まると考えている。計算の順序は木の形そのものであり、木 2 では b - c を先に計算する。 (D) は、一方の読み方だけが文法から定まると考えている。この文法には、どちらか一方に決める手掛かりがない。

7優先順位と結合性を文法で定める

あいまいさを除くには、一つの文に許す木の形が一つになるよう文法を書き換える。 文法 G のあいまいさには二つの種類がある。

  • 優先順位(precedence) — 異なる演算子が並んだとき、どちらを先にまとめるか（a + b * c で * を先にする）
  • 結合性(associativity) — 同じ優先順位の演算子が並んだとき、左右どちらからまとめるか（a - b - c を (a - b) - c とする）

段を分けて優先順位を定める

優先順位ごとに非終端記号を一段ずつ設ける。E（式）は項を + でつないだもの、T（項）は因子を * でつないだもの、F（因子）は識別子か括弧で囲んだ式とする。 

E → E + T | T
T → T * F | F
F → ( E ) | id

* は T の規則にしか現れないため、構文木の上で * の節点は必ず T の内側、すなわち + の節点より下に置かれる。 下の段に置いた演算子ほど先にまとめられ、優先順位が高くなる。 F → ( E ) は、括弧の中で最も上の段 E に戻ることを許す規則であり、括弧で優先順位を変えられることを表す。 この文法は文法 G と同じ言語を定め、どの文にも構文木を一つしか与えない。

図 7-1 は、この文法で a + b * c を描いたものである。 図 6-1 の木 2 の形、すなわち * を最上位に置き、その左に a + b をまとめる形を作ろうとすると、T の下に + を置く必要がある。 T の規則にも F の規則にも、括弧で囲まずに + を含む右辺はないため、この形は作れない。

再帰の向きで結合性を定める

E → E + T は右辺の左端に左辺と同じ非終端記号を持つ。このような規則を 左再帰(left recursion) の規則と呼ぶ。 左の E は再び E + T に展開できるが、右の T には + を含められない。 したがって、+ が並んだときは左側がより深くまとまり、左から順に結合する。 逆に、右辺の右端に左辺と同じ非終端記号を持つ規則を 右再帰(right recursion) の規則と呼び、右から結合させる。 図 7-2 は、減算を同じ段に加えた文法 E → E - T | T による a - b - c の木と、 べき乗 ^ を右再帰で定めた文法 T → F ^ T | F による a ^ b ^ c の木を並べたものである。 二つの木は、左右を写したような形になる。

表 7-1　二項演算子の規則の形と結合性。op は演算子、B は一段下の非終端記号を表す。どの形でも、op の片側に同じ段の非終端記号を許すかどうかで、連続した演算子のまとまり方が決まる。

規則の形結合性連続した演算子の読み方
A → A op B | B（左再帰）左結合a - b - c を (a - b) - c と読む
A → B op A | B（右再帰）右結合べき乗 a ^ b ^ c を a ^ (b ^ c) と読む
A → B op B | B結合しないa < b < c のように連続して書くことを文法で禁じる

どの演算子を左結合にし、どれを右結合にするかは言語の設計で定まり、言語によって異なる。 多くの言語では四則演算を左結合とする。比較演算子を連続して書けるかどうかも言語によって異なる。

優先順位の定め方の選択

3 節の EBNF で E → T { + T } と書くと、言語は E → E + T | T と同じであるが、 + が並んだときに左右どちらからまとめるかは規則から読み取れなくなる。 結合性は、仕様の本文で別に定めることになる。 図 7-3 は、a + b + c の構文木を二つの書き方で比べたものである。

また、あいまいな文法 G のまま、演算子ごとの優先順位と結合性を表にして添え、その表で構文木を一つに選ぶ方式もある。

表 7-2　優先順位と結合性の定め方と、それぞれが選ばれる条件。どちらの方式でも、最終的に一つの文に一つの構文木を対応させる点は変わらない。

方式利点欠点が効く条件
文法の段と再帰の向きで定める 文法だけで構造が一つに定まり、規則を読めば解釈が分かる 優先順位の段が多い言語では、段の数だけ非終端記号と一つ子の連鎖が増え、文法が読みにくくなる
あいまいな文法に優先順位の表を添える 式の規則が短く保て、演算子の追加は表に一行を足すだけで済む 文法と表の二箇所を読まなければ解釈が定まらず、文法だけを読んでも構造が分からない。演算子の種類が多いほど表との照合が要る

if 文のあいまいさ

あいまいさは演算子の式に限らない。3 節の <if文> の規則では、if (x) if (y) s1 else s2 の else が内側と外側のどちらの if に対応するかで、構文木が二つになる（図 7-4）。 このあいまいさを ぶら下がり else(dangling else) と呼ぶ。

多くの言語は「else は対応の付いていない最も近い if に対応する」と定め、木 1 を採ることで解消している。 この規則は文法を書き換えて表すこともでき、仕様の本文で別に定めることもある。

確認問題 7-1

次の文法で、^ はべき乗を表す。トークン列 2 ^ 3 ^ 2 + 1 を、この文法が定める唯一の構文木に従って計算した結果はどれか。 

E → E + T | T
T → F ^ T | F
F → ( E ) | num
  1. 65
  2. 513
  3. 1024
  4. 512
解答

正解: (B)

^ は T の段にあり、+ の E の段より下にあるため、先にまとめられる。 また T → F ^ T は右再帰であり、^ は右から結合する。 したがって構文木は (2 ^ (3 ^ 2)) + 1 を表し、2 ^ 9 + 1 = 513 となる。

(A) は ^ を左結合と読み、(2 ^ 3) ^ 2 + 1 = 65 としている。再帰の向きを確かめていない。 (C) は + を ^ より先にまとめ、2 ^ (3 ^ 2 + 1) = 2 ^ 10 としている。段の上下と優先順位の関係を逆にしている。 (D) は結合性と優先順位の両方を誤り、(2 ^ 3) ^ (2 + 1) = 8 ^ 3 としている。

確認問題 7-2

T を一段下の非終端記号とする。a - b - c を必ず (a - b) - c と読ませ、かつ a - b - c を文として含む規則はどれか。

  1. E → T - E | T
  2. E → E - E | T
  3. E → E - T | T
  4. E → T - T | T
解答

正解: (C)

左再帰の規則では、- の左側だけが再び E - T に展開できる。 このため a - b が左の E にまとまり、構文木は (a - b) - c の一つに定まる。

(A) は右再帰であり、a - (b - c) と右から結合させる。 (B) は - の両側に同じ段の E を許すため、二つの構文木を持つあいまいな規則である。 (D) は - の両側に一段下の T しか許さないため、減算を一つしか含まない。a - b - c は文として含まれない。

8総括

  • 入れ子の構造を有限の規則で書く — 深さに上限のない入れ子は、有限オートマトンでも正規表現でも扱えない。 定義の中で自身を参照する再帰的定義によって、有限個の規則で書き表せる。
  • 文脈自由文法 — 終端記号・非終端記号・生成規則・開始記号の四つで言語を定める。 構文解析の文法では、終端記号はトークンの種別である。
  • BNF と EBNF — BNF は < >, ::=, | で文法を書く記法である。 EBNF の [ ], { } は省略と繰り返しの略記であり、定められる言語を広げない。
  • 導出 — 開始記号から規則を一回ずつ適用して非終端記号を置き換える。導出できる文の全体が文法の定める言語である。
  • 構文木と抽象構文木 — 構文木は適用した規則を写した木であり、導出の順序によらない。 抽象構文木は括弧や一つ子の連鎖を除き、演算子と被演算子だけを残した木であり、後段の処理に渡される。
  • あいまいな文法 — 一つの文に構文木が二つ以上ある文法であり、文の意味が一つに定まらない。最左導出と最右導出があることとは別である。
  • 優先順位と結合性 — 演算子ごとに段を分けると、下の段ほど優先順位が高くなる。 左再帰の規則は左結合を、右再帰の規則は右結合を定める。
