1CPU が一手を選ぶまでの部品

ゲーム木を先読みして最善の手を選ぶ、という方針は明快である。 しかし「先読みする CPU」をいきなり書き始めると、対局中に CPU が奇妙な手を打ったとき、 原因がどこにあるのかを突き止められない。石の返し方が誤っているのか、 置けないマスを合法手として数えているのか、探索の符号が逆なのか、評価関数の重みが悪いのか。 完成した CPU の振る舞いだけを見ていては、これらの誤りを区別できない。

そこで CPU を、役割の異なる部品に分けて作る。 リバーシの CPU は、次の部品から組み立てられる。

  • 盤面表現(board representation) — 64 マスの状態をデータ構造として持つ
  • 合法手生成(move generation) — その局面で置けるマスを列挙する
  • 着手・取り消し — 石を置いて返し、必要に応じて元の局面へ戻す
  • 探索 — 手を仮に進めては戻し、先の局面を調べて最善の手を決める
  • 評価関数(evaluation function) — 探索の末端の局面がどちらにどれだけ有利かを数値にする

部品は依存される側から順に作る。盤面処理が完成していれば、人対人で最後まで対局できる。 この段階で誤りを潰しておけば、以降に CPU がおかしな手を打ったとき、 疑う範囲を探索と評価関数に絞れる。各部品について、 単体で正しさを確かめる検証用のコードを書きながら進めることが、 遠回りに見えて最も早く完成へ近づく方法である。

本ページでは、ゲーム木とミニマックス法の考え方は要点の振り返りにとどめ、 それらを動くプログラムにするための具体的な手順を扱う。 手順はすべて特定の言語に依存しない擬似コードで示す。

本講の到達点
  • 盤面を配列で表し、番兵と方向のオフセットを用いて8方向を走査できる
  • 合法手の判定と着手・取り消しを実装し、検証ケースによって正しさを確かめられる
  • ミニマックス法を再帰で実装し、パスと終局を正しく扱える
  • αβ枝刈りと手の並べ替えによって読む局面を減らし、結果が変わらないことを確かめられる
  • 評価関数の要素を組み合わせ、対戦によって改良の効果を比べられる
確認問題 1-1

リバーシ CPU の開発で、評価関数や探索に取りかかる前に、合法手生成と着手の処理を 単体で検証しておくべき理由として最も適切なものはどれか。

  1. CPU が不自然な手を打ったとき、盤面処理が正しいと確かめてあれば、原因を探索と評価関数に絞り込めるから
  2. 合法手生成は評価関数より計算量が大きいため、先に高速化しておく必要があるから
  3. 評価関数は盤面処理の誤りを打ち消すように重みを調整できるため、盤面処理を先に固めないと調整がやり直しになるから
  4. 合法手生成は対局中に1回しか呼ばれないため、後から修正するのが難しいから
解答

正解: (A)

探索と評価関数は盤面処理の上に成り立つ。下の部品が誤っていれば、 上の部品が正しくても CPU は誤った振る舞いをする。下の部品の正しさを先に確かめておくことで、 誤りが現れたときに疑う範囲を限定できる。

(B) は部品の順序を計算量の大小で説明しているが、先に作る理由は依存関係であって速度ではない。 (C) は評価関数で盤面処理の誤りを補えると考えているが、置けないマスに置く・返せない石を返すといった 規則違反は、重みをどう変えても解消しない。 (D) の合法手生成は探索の各局面で呼ばれ、1回の思考で数千〜数百万回呼ばれることもある。

2盤面を配列で表す

盤面は 8×8 のマスからなり、各マスは「空き」「黒」「白」のいずれかの状態をとる。 最も素直な表現は、8 行 8 列の2次元配列に各マスの状態を格納するものである。 列を a〜h、行を 1〜8 で呼ぶ慣例に合わせ、本ページでは列 a〜h を 1〜8 の番号に対応させる。

状態を数値で持つ

状態の表し方は、空き = 0、黒 = 1、白 = −1 とすると後の処理が単純になる。 手番の色を c とすれば、相手の色は −c で求まる。「自分の石か」「相手の石か」の判定が 手番によらず同じ式で書け、評価関数で石を数える際も、値を合計するだけで 黒から見た石数の差が得られる。

周囲に壁を置く — 番兵

合法手の判定では、あるマスから8方向へ1マスずつ進みながら石を調べる。 8×8 の配列のままでは、1歩進むたびに行と列が盤の範囲内に収まっているかを確かめなければならない。 この確認を1か所でも書き忘れると、配列の範囲外を参照する誤りが生じる。

そこで盤の周囲を1マスずつ広げた 10×10 の配列を用意し、外周のマスに 「壁」を表す値（空き・黒・白のいずれとも異なる値。例えば 2）を入れておく。 走査は壁に当たった時点で「相手の石でも自分の石でもない」と判定されて自然に止まるため、 範囲の確認そのものが不要になる。このように、探索の終端に置いて範囲判定を省くための 特別な値を番兵(sentinel) と呼ぶ。

1次元に並べて方向を数で表す

10×10 の盤面を1次元の配列に並べ、マスの添字を 行 × 10 + 列 とする。 例えば d3 は 3 行 4 列であるから、添字は 34 となる。 このとき、隣のマスへの移動は添字への加算で表せる。右へ1マスは +1、 下へ1マスは +10、右下へ1マスは +11 である。 8方向それぞれの加算量をオフセット(offset) と呼ぶ。

オフセットが一定になるのは、1行の幅を 10 としたためである。 壁の列を設けずに幅 8 のまま1次元に並べると、h 列から右へ1マス進んだ先が次の行の a 列になり、 盤の端で反対側へ回り込んでしまう。壁の列は、この回り込みを防ぐ役割も担う。

表 2-1　盤面表現の比較。いずれも正しく実装すれば同じ対局ができ、違いは盤外の扱いと速度にある。 速度の差が効いてくるのは探索を深くしたい場合に限られ、それ以外では誤りにくさを優先して選ぶ。

8×8 の2次元配列 (行, 列) の組 1歩ごとに行・列の範囲を確認する 位置と配列の対応が直観的で、表示処理も書きやすい。範囲確認の書き忘れに注意を要する

補足

配布されたソースコードを土台にする場合は、最初にその盤面表現を確認する。 空き・黒・白にどの値を割り当てているか、座標の (行, 列) と (x, y) のどちらで書かれているかを 取り違えると、以降の部品がすべて食い違う。

確認問題 2-1

図 2-1 の番兵付き盤面（添字 = 行 × 10 + 列）で、添字 66 のマスから左上方向へ2マス進んだマスの添字はどれか。

  1. 44
  2. 48
  3. 55
  4. 64
解答

正解: (A)

左上は1行上（−10）かつ1列左（−1）であり、オフセットは −11 となる。 2マス進むので 66 − 11 − 11 = 44 である。66 は f6、44 は d4 にあたる。

(B) は 66 − 9 − 9 であり、右上方向へ進んだ結果である。−9 は「1行上・1列右」を表す。 幅 8 の盤面で左上のオフセットが −9 になることと混同した場合にもこの値になる。 (C) は 1マスだけ進んだ位置であり、進んだ回数を数え誤っている。 (D) は左へ2マス（−1 を2回）進んだ位置であり、行の移動を落としている。

3合法手の判定 — 8方向に挟めるかを調べる

リバーシで石を置けるのは、置いたときに相手の石を1個以上返せるマスに限られる。 このようなマスへの着手を合法手(legal move) と呼ぶ。 「返せる」とは、置いたマスからある方向へ見て、相手の石が1個以上連続し、 その直後に自分の石がある状態をいう。間に挟まれた相手の石が返る。

この条件を1方向ずつ確かめる。ある方向について見るべき状況は次の4通りである。

  • 隣が空きまたは壁 — その方向には返せない
  • 隣が自分の石 — 挟む相手の石が0個であり、返せない
  • 相手の石が続いた後、空きまたは壁に当たる — 挟めていないため、返せない
  • 相手の石が続いた後、自分の石に当たる — 間の相手の石をすべて返せる

1方向の確認は、隣から順に1マスずつ見て、相手の石でなくなった時点で打ち切る 線形探索である。番兵付き盤面であれば、壁も「相手の石でない値」として扱われ、 特別な処理を書かずに走査が止まる。これを8方向について繰り返し、 挟めた方向の石を集めたものが、そのマスに置いたときに返る石の一覧になる。 

返せる石(盤面 B, 位置 p, 手番 c):
1. 結果 ← 空の一覧
2. B[p] ≠ 空き ならば、結果を返して終了する
3. 8方向の各オフセット d について、以下を繰り返す
   3.1 候補 ← 空の一覧、q ← p + d
   3.2 B[q] = −c である間、q を候補に加えて q ← q + d とする
   3.3 B[q] = c かつ 候補が空でない ならば、候補をすべて結果に加える
4. 結果を返す

手順 3.3 の二つの条件がこの判定の要である。B[q] = c は 「相手の石の列が自分の石で終わっている」こと、候補が空でない は 「挟まれた相手の石が1個以上ある」ことを確かめている。前者を欠くと空きや壁で終わる列まで返し、 後者を欠くと隣が自分の石であるだけのマスを合法手と誤る。

合法手の一覧は、盤内の64マスすべてについて返せる石を調べ、1個以上あるマスを集めれば得られる。 

合法手の一覧(盤面 B, 手番 c):
1. 一覧 ← 空の一覧
2. 盤内の各位置 p について、返せる石(B, p, c) が空でなければ p を一覧に加える
3. 一覧を返す

パスと終局

合法手の一覧が空であれば、その手番の側は石を置けず、 盤面を変えないまま相手に手番を渡す。これをパス(pass) と呼ぶ。 パスした直後の相手にも合法手が無ければ、どちらも打てないため対局は終わる。 盤が埋まった場合もこの条件に含まれる。 終局の判定は「盤が埋まったか」ではなく「両者とも合法手が無いか」で行う。 盤が埋まる前に両者が打てなくなる局面や、一方の石が全滅する局面も存在するためである。

確認問題 3-1

黒の手番で、空きマス X に黒を置くことを考える。X から右方向に並ぶマスの状態が次のいずれかであるとき、 右方向の石が返るものはどれか。並びは X の隣から順に書いてあり、「壁」は盤外を表す。

  1. 白、白、空き
  2. 黒、白、黒
  3. 白、白、黒
  4. 白、白、白、壁
解答

正解: (C)

白が2個続いた直後に黒があり、2個の白が挟まれる。返せる石の手順で、 候補に2個が入った状態で B[q] = c が成り立つ場合にあたる。

(A) は白の列の先が空きであり、挟めていない。 (B) は隣が黒であり、挟む白が0個である。その先に白と黒が並んでいても、 走査は隣の黒の時点で止まるため関係しない。 (D) は白の列の先が壁であり、盤の端まで白が続いていても挟めていない。

4着手と取り消し

合法手が決まれば、着手の処理は返せる石の一覧を使って書ける。 置いたマスを自分の色にし、一覧にある石をすべて自分の色に変える。 

着手(盤面 B, 位置 p, 手番 c):
1. 返す石 ← 返せる石(B, p, c)
2. B[p] ← c
3. 返す石 の各位置 q について、B[q] ← c
4. 返す石 を返す

着手の誤りで最も多いのは、相手の石が続く方向をすべて返してしまうものである。 図 3-1 では相手の石が続く方向が4つあるが、返してよいのは2方向だけである。 返せる石の判定と着手で別々に走査を書くと、着手の側だけ手順 3.3 の条件を落としやすい。 判定で得た一覧をそのまま着手に使えば、両者が食い違うことはない。

探索のために局面を元へ戻す

探索では、手を仮に打って先の局面を調べ、調べ終えたら打つ前の局面へ戻す、という操作を 何度も繰り返す。局面を戻す方法には二つある。

  • 盤面の複製 — 着手の前に盤面全体を別の配列へ写し、調べ終えたら写しを捨てる
  • 差分の記録 — 置いた位置と返した石の位置を記録しておき、調べ終えたら記録をもとに元へ戻す

二つの方法は、トレードオフ(trade-off) の関係にある。 複製は着手の処理に手を加えずに済み、戻し忘れや戻し誤りが原理的に起こらない。 差分の記録は1手あたりに書き換えるマスが数個で済むため速いが、 記録と復元の処理を自分で書く必要があり、返した石の記録漏れがあると局面が少しずつ壊れていく。 この種の誤りは、数十手後に「置けるはずのマスに置けない」といった形で現れるため、原因の特定が難しい。

速度の差が効いてくるのは、1回の思考で数十万以上の局面を調べる場合に限られる。 10×10 の盤面の複製は100個の値を写すだけであり、浅い探索では差は体感できない。 まず複製で正しく動く版を作り、探索を深くして速度が足りなくなってから差分の記録へ切り替えるのが安全である。 切り替えた後は、両方の版で同じ局面数・同じ評価値が得られることを確かめる。

確認問題 4-1

盤面を複製せず、差分の記録によって着手を取り消したい。着手のたびに記録しておく必要がある情報として、 過不足のないものはどれか。

  1. 置いた位置と、返したすべての石の位置
  2. 置いた位置だけ
  3. 置いた位置と、返した石の個数
  4. 着手の直前の局面に対する評価関数の値
解答

正解: (A)

取り消しでは、置いた位置を空きへ戻し、返した石を相手の色へ戻す。 そのためには、どのマスを書き換えたかがすべて分かっていればよい。 返した石の元の色は、着手した側の相手の色に決まっているため、記録しなくてよい。

(B) は、置いた位置から返した石を求め直せると考えている。しかし着手後の盤面では 返した石も自分の色になっており、もともと自分の石だったものと区別できない。 (C) の個数だけでは、どの方向の何個目までが返した石なのかが定まらない。 (D) の評価値は局面の良さを表す数値であり、局面そのものを復元する情報を含まない。

局面数による総合検証

個別のケースに加えて、初期局面から合法手をすべて試しながら n 手先まで進め、 到達する局面の数（手順の数）を数える方法がある。この数は盤面処理が正しければ一意に定まり、 既知の値と照合できる。チェスなどのプログラム開発で用いられる手法で、 perft(performance test) と呼ばれる。 

局面数(盤面 B, 手番 c, 深さ n):
1. n = 0 ならば、1 を返す
2. 手の一覧 ← 合法手の一覧(B, c)
3. 手の一覧が空ならば、局面数(B, −c, n − 1) を返す（パスも1手と数える）
4. 合計 ← 0
5. 手の一覧の各手 p について、以下を繰り返す
   5.1 着手(B, p, c) を行う
   5.2 合計 ← 合計 + 局面数(B, −c, n − 1)
   5.3 着手を取り消す
6. 合計を返す

6ミニマックス法を再帰で実装する

盤面処理が完成すれば、CPU の思考部分に進める。考え方の要点を振り返っておく。 現在の局面から合法手ごとに枝分かれし、その先でさらに相手の合法手ごとに枝分かれする木を、 決めた深さまで展開する。末端の局面を評価関数で数値にし、 自分の手番の局面では子の最大値を、相手の手番の局面では子の最小値を親へ伝える。 相手も自分にとって最も不利な手を選ぶと仮定して、最悪の場合の中で最善の手を選ぶ方法である。 これをミニマックス法(minimax) と呼ぶ。

符号の反転で1つの関数にまとめる

最大を選ぶ処理と最小を選ぶ処理を別々に書くと、ほぼ同じ手順が2つできる。 ここで、相手から見た評価値は自分から見た評価値の符号を反転したものだと考える。 すると「相手が自分にとっての最小を選ぶ」ことは、「相手が相手にとっての最大を選ぶ」ことと同じになる。 各局面で手番の側から見た評価値の最大を求め、親へ返すときに符号を反転すると決めれば、 手番によらず1つの関数で書ける。この書き方をネガマックス法(negamax) と呼ぶ。 空き・黒・白を 0・1・−1 で表しておくと、評価関数も 手番 c × 黒から見た評価値 で 手番の側から見た値に変換できる。 

探索(盤面 B, 手番 c, 深さ n):     ※ 手番 c の側から見た評価値を返す
1. n = 0 ならば、評価(B, c) を返す
2. 手の一覧 ← 合法手の一覧(B, c)
3. 手の一覧が空ならば
   3.1 合法手の一覧(B, −c) も空ならば、終局として 最終評価(B, c) を返す
   3.2 そうでなければ、−探索(B, −c, n − 1) を返す（パス）
4. 最良 ← −∞
5. 手の一覧の各手 p について、以下を繰り返す
   5.1 返した石 ← 着手(B, p, c)
   5.2 値 ← −探索(B, −c, n − 1)
   5.3 取り消し(B, p, c, 返した石)
   5.4 値 > 最良 ならば、最良 ← 値
6. 最良を返す

実際に打つ手を決めるのは、根の局面だけである。根では手順 5 の繰り返しの中で、 最良を更新したときの手 p を覚えておき、それを CPU の着手とする。 根以外の局面では手そのものは不要で、値だけを返せばよい。

図 6-2 は、図 6-1 の木をネガマックス法の値で描き直し、相手がパスとなる手D を加えたものである。 各節点の値は、その局面の手番の側から見た値である。 相手の手番の節点 A は、子の値 3・5 の符号を反転した −3・−5 のうち最大の −3 をとる。 根はさらにその符号を反転した 3 を受け取る。図 6-1 で「相手は最小を選ぶ」として求めた値と、符号を除いて一致する。

実装で誤りやすい点

  • 符号の反転 — 手順 5.2 と 3.2 の − を落とすと、相手の手番でも自分に有利な手を選ぶことになり、 CPU は相手に有利な手を好んで打つ。評価関数が手番の側から見た値を返していることも併せて確かめる。
  • パス — 合法手が無いときに評価値を返して終えると、パスの先の展開が読まれない。 パスでは盤面を変えずに手番だけを渡して探索を続ける。 両者とも打てない場合に終局とする判定を欠くと、パスが交互に続いて深さを使い切るまで読み進めてしまう。
  • 終局の評価 — 終局では勝敗が確定しているため、石数の差に大きな定数を掛けるなどして、 途中局面の評価値のどれよりも大きな値（負けなら小さな値）にする。 そうしないと、勝ちの確定した手より、評価値の高い途中局面へ進む手を選ぶことがある。

探索の手間は深さに対して急激に増える。中盤では合法手が10個前後あることが多く、 深さを1増やすたびに調べる局面はおよそ合法手の個数倍になる。 合法手が11個ある中盤の局面で実際に数えると、深さ4で約1.8万、深さ6で約230万の局面を訪れる（図 7-3・表 7-2）。 この増え方を指数関数的と呼ぶ。深さは、1手にかけられる時間から逆算して決める。

7αβ枝刈りと手の並べ替え

図 6-1 で手A の値が 3 と分かった後に手B を調べるとき、手B の最初の子で評価値 2 の局面が見つかった時点で、 手B の値は 2 以下に決まる。手A で 3 を確保できる以上、手B が選ばれることはなく、 手B の残りの子（評価値 6 の局面）を調べる必要はない。このように、結果に影響しないと確定した枝の探索を打ち切る方法を αβ枝刈り(alpha-beta pruning) と呼ぶ。 枝刈りは選ばれる手と評価値を変えずに、調べる局面の数だけを減らす。

実装では、各局面に二つの値を渡す。α は手番の側がすでに確保できると分かっている値の下限、 β は相手がそれ以上は許さない値の上限である。子の値が β 以上になれば、 相手はこの局面へ進む手を選ばないため、残りの子を調べずに戻ってよい。 ネガマックス法の形では、子へ渡すときに α と β を入れ替えて符号を反転する。 

探索(盤面 B, 手番 c, 深さ n, α, β):
1. n = 0 ならば、評価(B, c) を返す
2. 手の一覧 ← 合法手の一覧(B, c)
3. 手の一覧が空ならば
   3.1 合法手の一覧(B, −c) も空ならば、最終評価(B, c) を返す
   3.2 そうでなければ、−探索(B, −c, n − 1, −β, −α) を返す（パス）
4. 手の一覧の各手 p について、以下を繰り返す
   4.1 返した石 ← 着手(B, p, c)
   4.2 値 ← −探索(B, −c, n − 1, −β, −α)
   4.3 取り消し(B, p, c, 返した石)
   4.4 値 > α ならば、α ← 値
   4.5 α ≥ β ならば、繰り返しを打ち切る
5. α を返す

根では α = −∞、β = +∞ として呼び出す。ミニマックス法の擬似コードとの違いは、 引数の α・β、手順 4.2 の受け渡し、手順 4.5 の打ち切りの3か所だけである。 ミニマックス法の版を残しておけば、両者の結果を比べて枝刈りの実装を検証できる。

有望な手から調べる

枝刈りがどれだけ効くかは、手を調べる順序で決まる。最善の手を最初に調べれば α が早く大きくなり、 以降の手はすぐに打ち切られる。逆に、悪い手から順に調べると、ほとんど刈れない。 そこで、各局面で合法手を調べる前に、1手だけ進めた局面の評価値などの軽い見積もりで 有望な順に並べ替える。これを手の並べ替え(move ordering) と呼ぶ。

図 7-2 は、同じ木を C → A → B の順に調べた場合である。最善の C を最初に調べると根の α が 4 になり、 A と B にはともに (−∞, −4) が渡る。A は A1 の子の値 −3 が β = −4 以上となって打ち切られ、 B も B1 の子の値 −2 で打ち切られる。A → B → C の順では刈られる末端が B2 の 1 個だったのに対し、 この順では A2 と B2 の 2 個になる。根の値 4 と選ぶ手 C は変わらない。

3. 並べ替えた一覧を返す

手順 1.2 では、手番 c の側から見た評価値を求める。着手した後の局面は相手の手番になっているが、 比べたいのは c にとってどれだけ良いかであるため、評価(B, −c) と取り違えないようにする。 取り違えると、悪い手から順に調べることになり、枝刈りがかえって減る。 表 7-2 は、図 7-3 の中盤局面で、この並べ替えを全ての局面に適用した場合の局面数である。

補足 — 置換表

リバーシでは、異なる手順から同じ局面に到達することがある。例えば黒が a・b、白が x と打つ場合、 a → x → b の順でも b → x → a の順でも、結果の局面が同じになりうる。 調べ終えた局面の評価値をハッシュ表に記録しておけば、同じ局面を再び調べずに済む。 この表を置換表(transposition table) と呼ぶ。 局面からハッシュ値を計算してキーとするが、異なる局面が同じハッシュ値になる衝突は避けられないため、 局面そのもの（または十分に長い別のハッシュ値）も記録して一致を確かめる。 記録には読んだ深さも含め、浅く読んだ値を深い探索で使わないようにする。 置換表が効いてくるのは探索を深くした場合であり、ここまでの部品が揃ってからの改良となる。

解答

正解: (A)

αβ枝刈りは、結果に影響しないと確定した枝だけを打ち切るため、根の評価値はミニマックス法と一致する。 並べ替えは調べる順序を変えるだけであり、変わるのは打ち切りの起こる早さ、すなわち訪れる局面の数である。

(B) は順序が評価の正確さを左右すると考えているが、評価値は深さと評価関数で決まる。 (C) の深さは呼び出し側が与える値であり、局面数が減っても自動的には変わらない。 浮いた時間でより深く読むように作ることはできるが、それは別の仕組みである。 (D) は刈られた枝が選ばれうると考えているが、刈られるのは選ばれないと確定した枝に限られる。 同じ評価値の手が複数ある場合に、どれを選ぶかが順序で変わることはあっても、評価値は変わらない。

確認問題 7-2

探索の各局面で、合法手を見積もりの評価値の順に並べ替える。合法手は多くても十数個である。 並べ替えの手法の選び方として最も適切なものはどれか。

  1. 要素数が少ないため、計算量の差は全体の手間にほとんど影響せず、実装の簡単な手法を選んでよい
  2. 平均計算量が O(n log n) の手法でなければ、探索全体の計算量が O(n²) になってしまう
  3. 交換回数の多い手法を使うと、並べ替えの結果が変わり、枝刈りの効果が下がる
  4. 並べ替えは毎回ほぼ逆順の入力になるため、挿入ソートは避けるべきである
解答

正解: (A)

計算量の差が効くのは要素数が大きい場合である。十数個の並べ替えでは、 O(n²) の手法でも比較は百回程度にとどまり、各手の見積もりや子の探索の手間に比べて小さい。

(B) は並べ替えの計算量と探索全体の計算量を混同している。探索の手間は分岐の数と深さで決まり、 各局面の並べ替えの手法によって全体の増え方が変わるわけではない。 (C) の交換回数は手間の違いであり、どの手法でも並べ替えた結果の順序は同じになる。 (D) は入力の並びについて根拠のない仮定を置いている。合法手は盤面の走査順に得られるため、 評価値について逆順に並ぶ理由はない。

確認問題 7-3

図 7-1 と同じ木（A の先が 3・5、B の先が 2・6、C の先が 4・7。値は末端で手番の側から見た値）を、 αβ枝刈りで B → A → C の順に探索する。各節点の子は、図の左の子から順に調べる。刈られる末端の数はいくつか。

  1. 0 個
  2. 1 個
  3. 2 個
  4. 3 個
解答

正解: (A)

最初の B は (−∞, +∞) で呼ばれて刈られず、−2 を返す。根の α は 2 となり、A と C には (−∞, −2) が渡る。 A は A1 の子の値 −3 を得るが、−3 ≥ −2 は成り立たないため続けて A2 も調べ、−3 を返す。根の α は 3 となる。 C には (−∞, −3) が渡り、C1 の子の値 −4 も −4 ≥ −3 を満たさないため C2 まで調べる。 どの節点でも打ち切りが起こらず、刈られる末端は無い。

(B) は A → B → C の順に調べた図 7-1 の結果であり、順序が変わっても刈られる数は同じだと考えている。 (C) は最善の C から調べた図 7-2 の結果である。 (D) は、最初に調べる手以外の節点では、子を1つ調べれば必ず打ち切れると考えている。 打ち切りが起こるのは、子の値がその時点の β 以上になった場合に限られる。

8評価関数の設計

探索が正しく動いても、末端の局面を評価する関数が局面の良し悪しを捉えていなければ、CPU は強くならない。 最も単純な評価関数は、自分の石の数から相手の石の数を引いたものである。 しかしこの評価で打つ CPU は、序盤・中盤に多くの石を返す手を好み、結果として弱い。 リバーシでは途中の石数は終局の石数と結びつきにくく、むしろ自分の石が多いほど、 相手が挟める石が増えて相手の打てる場所が広がりやすいためである。

位置の重み

マスにはそれぞれ価値の違いがある。隅の石は、挟まれる方向が無いため二度と返されない。 一方、隅に隣接するマスに自分の石を置くと、隅が空いている間は相手が隅に置く足がかりを与えやすい。 隅の斜め隣のマスに打つことをX 打ち(X-square)、 隅の縦横の隣に打つことをC 打ち(C-square) と呼び、 いずれも序盤・中盤では避けるべき手とされる。 各マスに重みを定め、自分の石があるマスの重みの合計から相手の分を引いたものを評価値とする。

重みの表は1次元の盤面と同じ添字で持てば、評価は「盤内の各マスについて 重み × 石の値 を合計する」だけで書ける。 石の値が 黒 = 1・白 = −1 であるから、この合計は黒から見た評価値となり、手番 c を掛ければ手番の側から見た値になる。

図 8-2 の局面で、石数による評価と位置の重みによる評価を比べる。黒は石を 5 個持ち、白の 3 個より多い。 しかし白は隅の a1 を持ち、黒はその斜め隣の b2、すなわち X 打ちのマスに石を置いている。 

黒: b2 (−80) + c3 (5) + d3 (1) + d4 (0) + e4 (0) = −74
白: a1 (100) + d5 (0) + e6 (1) = 101
黒から見た評価値 = −74 − 101 = −175

評価の要素を組み合わせる

表 8-1　評価関数の要素。どの要素も局面の段階によって効き方が変わり、単独ではそれぞれの弱点が現れる。

要素求め方効く局面弱点
石数 自分の石 − 相手の石 終盤 序盤・中盤では、石を多く取る手ほど相手の打てる場所を増やしやすい
位置の重み 石のあるマスの重みの合計 序盤〜中盤 重みが固定であり、隅を取った後は C 打ちが安全になる、といった局面による変化を表せない
着手可能数(mobility) 自分の合法手の数 − 相手の合法手の数 中盤 評価のたびに両者の合法手生成を要し、1局面あたりの評価が重くなる。その分、同じ時間で読める深さが減る
確定石(stable disc) 今後どう打たれても返されない石の数 中盤〜終盤 正確な判定は難しく、隅から辺に沿って連なる石に限るなどの簡略化を要する

着手可能数は、合法手の一覧の長さを両者について求めて差をとる。 図 7-3 の局面では、黒の合法手が 11 個、白に手番があるとした場合の白の合法手が 12 個であり、 黒から見た着手可能数の差は 11 − 12 = −1 となる。 手番は黒であっても、相手の手番として合法手の一覧を呼び出せば白の数が得られる。

確定石の判定は、正確に行うと複雑になる。扱いやすい簡略化は、 隅の石と、隅から辺に沿って同じ色が切れ目なく続く石だけを確定石として数えるものである。 図 8-3 の b1 は、辺の方向では隅 a1 までの間に自分の石しか無く、他の方向では一方の側が盤外であるため、 どの方向にも挟まれることがない。

実際の評価関数は、これらの要素に係数を掛けて足し合わせた形で組み立てる。 例えば 評価値 ← a × 位置の重みの合計 + b × 着手可能数の差 とし、 係数 a・b を調整する。さらに、空きマスの数で局面の段階を判定し、段階ごとに係数を切り替えると、 表 8-1 の「効く局面」の違いを反映できる。

終盤では別の手段が使える。空きマスが残り少なくなれば、終局まで全ての手を読み切っても局面数が手に負える範囲に収まる。 このとき評価関数は不要で、終局の石数そのものを比べればよい。 これを完全読み(exhaustive endgame search) と呼ぶ。 何マス残りから完全読みに切り替えられるかは、実装の速さと1手にかけられる時間で決まるため、 局面数と時間を測って定める。

改良の効果を対戦で比べる

評価関数を変更したら、変更前の版と対戦させて効果を確かめる。 リバーシは先手・後手で有利不利があり、同じ評価関数どうしの対局は同じ手順を繰り返しやすい。 そのため、先手と後手を入れ替え、序盤の数手をランダムに打った局面から始めるなどして、複数局を対戦させる。 1局の勝敗は偶然に左右されるため、改良の判断材料にならない。

確認問題 8-1

位置の重みで、隅の斜め隣のマス（X 打ちのマス）に大きな負の値を与える理由として最も適切なものはどれか。

  1. 隅が空いている間にそこへ自分の石を置くと、相手が隅に打つ足がかりになりやすいから
  2. そのマスに置いた石は、隅の石と同じく二度と返されないから
  3. そのマスには合法手が生じにくく、置ける機会が少ないから
  4. 盤の端に近いマスほど、返せる石の数が少なくなるから
解答

正解: (A)

X 打ちのマスにある自分の石は、隅と反対側に相手の石があれば、相手が隅に置くことで挟まれる。 隅を取られると、その石は二度と取り返せない。負の重みは、この危険を評価値に反映させるためのものである。

(B) は隅の性質を隣接マスに当てはめている。隅の斜め隣は斜め方向に挟まれうるため、二度と返されない石ではない。 二度と返されないならば、正の値を与えるべきことになる。 (C) は置ける機会の多少と、置いたときの損得を混同している。重みは置いた結果の価値を表す。 (D) の返せる石の数は、評価関数の重みが表す事柄とは別であり、端に近いことが負の値の理由でもない。 実際、辺の中ほどのマスには正の値が与えられている。

確認問題 8-2

石数の差だけを評価値とし、深さ1で最も評価値の高い手を打つ CPU は、中盤で弱いことが多い。その理由として最も適切なものはどれか。

  1. 多く返す手は自分の石を増やす一方、相手が挟める石を増やして相手の打てる場所を広げやすく、途中の石数は終局の石数と結びつきにくいから
  2. 石数の差は計算に時間がかかるため、深く読めなくなるから
  3. 石数の差は手番によって符号が変わるため、正しく比較できないから
  4. 中盤では、どの手を選んでも返る石の数が同じになるから
解答

正解: (A)

勝敗を決めるのは終局の石数であり、途中の石数はそれと結びつきにくい。 中盤に石を多く取ると、相手の打てる場所を広げ、後で隅や辺の良い位置を相手に与えやすい。

(B) は弱さの原因を速度に求めているが、石数の差は合計するだけで求まり、評価関数の中では軽い部類に入る。 (C) の符号は、手番の側から見た値に変換すれば正しく比較できる。符号の扱いは実装の誤りの問題であり、評価の方針の弱さではない。 (D) は事実に反する。中盤では手によって返る石の数は大きく異なり、だからこそ石数だけの評価は多く返す手に偏る。

確認問題 8-3

図 8-1 の位置の重みで、次の局面を評価する。黒から見た評価値（黒の重みの合計 − 白の重みの合計）はいくつか。 

黒: a1, c3, d4
白: b2, b4, d5
  1. 186
  2. 24
  3. 105
  4. −186
解答

正解: (A)

黒は a1 (100) + c3 (5) + d4 (0) = 105、白は b2 (−80) + b4 (−1) + d5 (0) = −81 である。 黒から見た評価値は 105 − (−81) = 186 となる。白が負の重みのマスに石を置いていることは、黒にとって有利に働く。

(B) は白の合計を 81 として引いており、負の重みの符号を落としている。 (C) は黒の重みの合計だけを求め、白の分を差し引いていない。 (D) は白から見た評価値であり、どちらの側から見た値かを取り違えている。

確認問題 9-1

ミニマックス法で動いていた探索に、αβ枝刈りを加えた。枝刈りの実装が正しいことを確かめる方法として最も適切なものはどれか。

  1. 多数の局面について、同じ深さでミニマックス法の版と評価値が一致し、かつ訪れる局面数が減っていることを確かめる
  2. 枝刈りを加えた CPU を対戦させ、加える前の CPU に勝ち越すことを確かめる
  3. 訪れる局面数が、加える前より減っていることを確かめる
  4. 1手あたりの思考時間が、加える前より短くなっていることを確かめる
解答

正解: (A)

正しい αβ枝刈りは、ミニマックス法と同じ評価値を返しつつ、調べる局面を減らす。 この二つの性質を両方とも確かめることで、正しさと効果が同時に検証できる。 局面を変えて多数回比べるのは、特定の配置でのみ生じる誤りを拾うためである。

(B) は強さで正しさを判断している。同じ深さであれば正しい枝刈りは同じ手を選ぶため、 勝ち越すことはむしろ期待されない。勝ち越した場合は、結果が変わっている疑いがある。 (C) と (D) は効果しか見ていない。刈ってはならない枝まで刈る誤った実装でも、局面数は減り、思考時間は短くなる。

10総括

  • リバーシ CPU は、盤面表現・合法手生成・着手と取り消し・探索・評価関数の部品からなる。依存される側から順に作り、部品ごとに検証する
  • 盤面は空き = 0・黒 = 1・白 = −1 の配列で持つ。番兵付きの 10×10 を1次元に並べると、8方向の移動が一定のオフセットになり、範囲確認が不要になる
  • 合法手は、ある方向に相手の石が1個以上続き、その直後に自分の石があるマスである。8方向それぞれを打ち切りのある線形探索で調べる
  • 着手では挟めた方向の石だけを返す。探索で局面を戻す方法には盤面の複製と差分の記録があり、まず複製で正しい版を作る
  • 盤面処理は、誤りの種類ごとに用意した検証局面と、初期局面からの局面数の照合で検証する。探索は、手で読み切れる終盤局面で深さごとの手と値を照合する
  • ミニマックス法は、符号の反転によって1つの再帰関数（ネガマックス法）で書ける。パスでは手番だけを渡し、両者とも打てなければ終局とする
  • αβ枝刈りは評価値を変えずに局面数を減らし、手の並べ替えはその効果を高める。少数の合法手の並べ替えでは、ソート手法の計算量の差は問題にならない
  • 評価関数は石数・位置の重み・着手可能数・確定石などを組み合わせ、局面の段階で切り替える。終盤は完全読みで石数を直接比べる
  • 段階ごとに完成の判定を定めて積み上げ、ソースコード・検証用のコード・AI 利用時の全ログを提出する
