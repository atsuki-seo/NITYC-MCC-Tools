1配列では間に合わない場面

1000件の名簿が配列に格納されているとする。この名簿は氏名の五十音順に並んでおり、 新たに1件を正しい位置へ加えたい。挿入位置がちょうど中央であったとすると、 その位置を空けるために後続する約500件をすべて1つ後ろへずらす必要がある。 1件の追加に500回の移動を要する計算になる。

この手間は配列の弱点というより、配列が速さを得ている仕組みの裏返しである。 配列は要素を連続した領域に等間隔で並べるため、先頭の位置と添字から 目的の要素の位置を直接計算できる。その代償として、 要素の並び順が、メモリ上の配置そのものに固定される。 並び順を変えるとは、配置を変えることに他ならない。

そこで発想を変える。要素の順序を、メモリ上の配置ではなく、 要素自身が持つ「次はどれか」という情報で表すことにすれば、 順序の変更は配置の変更を伴わなくなる。この考え方に基づく構造を リスト(list) と呼ぶ。 本講では次の三つの方式を扱う。

  • 線形リスト(linear list) — 各要素が次の要素だけを指す
  • 双方向リスト(doubly linked list) — 各要素が次と前の両方を指す
  • カーソルリスト(cursor list) — 「次はどれか」を配列の添字で表す
本講の到達点
  • 線形リスト・双方向リスト・カーソルリストの構造と、要素をたどる仕組みを説明できる
  • 挿入・削除がポインタの張り替えで実現される手順を示せる
  • 配列とリストの適否を、行う操作に基づいて判断できる
確認問題 1-1

あるプログラムでは、データの途中への挿入と途中からの削除が頻繁に発生する。 一方で、任意の位置の要素を添字で取り出す操作はほとんど行わない。 この状況における構造の選択と、その根拠の組合せとして最も適切なものはどれか。

  1. 配列を選ぶ。要素が連続して並ぶため、途中へ挿入しても後続の要素を動かさずに済むから
  2. 配列を選ぶ。添字による直接アクセスが速いため、挿入・削除の位置も即座に更新できるから
  3. リストを選ぶ。次の要素を指す情報を付け替えるだけで挿入・削除が行え、他の要素を動かさずに済むから
  4. リストを選ぶ。先頭から順にたどる必要があるため、任意の要素へ高速に到達できるから
解答

正解: (C)

リストは順序を要素自身が保持するため、挿入・削除の際に動かすのは 「次はどれか」を示す情報だけである。他の要素の位置は変わらない。

(A) は配列の性質を逆に述べている。連続領域に並ぶからこそ、 途中への挿入では後続をずらす必要が生じる。 (B) は「要素へ到達する速さ」と「挿入・削除の速さ」を混同している。 添字計算が速いことは、ずらす作業が不要になる理由にならない。 (D) は前半の記述自体は正しいが、たどる必要があることは高速に到達できない理由であり、 リストを選ぶ根拠として成立しない。

2線形リスト — 要素が次を指す

線形リストでは、要素ひとつひとつを ノード(node) と呼ぶ入れ物で表す。ノードは二つの情報を持つ。

  • 格納したい値そのもの
  • 次のノードがどこにあるかを示す情報 — ポインタ(pointer)

リスト全体は、先頭ノードの位置を指す head という ひとつの手がかりから始まる。最後のノードは次が存在しないため、 そのことを表す特別な値を保持する。多くの言語では NULL と呼ばれる「どこも指していない」ことを示す値が用いられる。

要素への到達手段はたどることのみ

この構造では、ノードはメモリ上のどこに配置されていてもよい。 順序を決めているのは配置ではなくポインタだからである。 その結果として、k番目の要素を得るには head から k 回たどる以外に方法がない。 配列のような添字からの位置計算は成立しない。位置を計算する根拠となる 「等間隔に連続して並ぶ」という前提が、そもそも存在しないためである。

3番目のノードの値を取り出す手順は次のようになる。 

1. 現在位置 ← head
2. 繰り返しを 2 回行う
3.   現在位置 ← 現在位置が指す次ノード
4. 現在位置が持つ値を取り出す
誤りやすい点

線形リストに対して「3番目の要素」という言い方はできるが、 それは3回たどった先という意味であって、添字による指定ではない。 先頭に近い要素ほど少ない手数で到達でき、末尾に近い要素ほど多くの手数を要する。 どの要素にも同じ手数で到達できる配列とは、この点が本質的に異なる。

確認問題 2-1

ノードが6個つながった線形リストがある。head は先頭ノードを指している。 このリストにおける要素への到達について、正しい記述はどれか。

  1. どのノードへも、head から1回の操作で直接到達できる
  2. 末尾のノードへ到達するには head から5回たどる必要があり、先頭ノードへは0回で到達できる
  3. 各ノードは先頭からの通し番号を保持しているため、その番号を指定すれば直接到達できる
  4. ノードはメモリ上に連続して並ぶため、先頭のアドレスと通し番号から位置を計算して到達できる
解答

正解: (B)

head が指すのが先頭ノードであるから、先頭へはたどる操作を要しない。 以降は1つ進むごとに1回たどるため、6個目のノードへは5回を要する。

(A) は head が指すのは先頭ノードのみであり、他のノードの位置を head は知らない。 (C) はノードが持つのは値と次ノードへのポインタであって、通し番号は保持しない。 仮に保持させたとしても、その番号からノードの位置を求める手段がない。 (D) は配列の性質をリストに当てはめた誤りである。 リストのノードは連続領域に並ぶことを前提としないため、位置の計算は成立しない。

3挿入と削除 — ポインタの張り替え

リストの利点が最もよく表れるのが挿入と削除である。 ノード B と C の間へ新しいノード X を挿入する場合、 行う作業はポインタ2本の張り替えだけであり、 他のノードには一切触れない。

張り替えの順序には必然性がある

挿入手順は次の2行で表される。この2行の順序は入れ替えられない。 

1. X の次 ← B の次（すなわち C）
2. B の次 ← X

仮に順序を逆にすると、先に B の次を X に書き換えた時点で、 それまで B が保持していた「次は C である」という情報が失われる。 C の位置を知る手段は B のポインタしかなかったのであるから、 この時点でC 以降のノードすべてに到達できなくなる。 値の上書きによって元の値が失われるという性質が、そのまま現れた形である。

削除と、先頭を対象とする場合の扱い

削除はさらに単純で、ポインタ1本の付け替えで済む。 B と D の間にある C を取り除くには、B の次を D に向ければよい。 C 自体を消す操作は必要ない。どのノードからも指されなくなった時点で、 そのノードはリストの一部ではなくなる。 

1. B の次 ← C の次（すなわち D）
誤りやすい点

先頭ノードを対象とする場合だけは扱いが異なる。 先頭ノードを指しているのは他のノードではなく head だからである。 先頭への挿入では head を新ノードへ、先頭の削除では head を2番目のノードへ 向け直す。対象が先頭かどうかで操作する対象が変わる点に注意を要する。

確認問題 3-1

head → P → Q → R → NULL という線形リストがある。 P と Q の間へ新しいノード N を挿入するつもりで、次の順に操作を行った。 

1. P の次 ← N
2. N の次 ← P の次

この操作の結果として生じる状態はどれか。

  1. 意図どおり head → P → N → Q → R → NULL となる
  2. N が自分自身を指し、Q と R へ到達できなくなる
  3. N が挿入されず、リストは操作前と変わらない
  4. head が N を指すようになり、P へ到達できなくなる
解答

正解: (B)

操作1で P の次が N に書き換わった時点で、P が保持していた 「次は Q」という情報は失われている。続く操作2で参照する「P の次」は もはや Q ではなく N であるから、N の次には N 自身が設定される。 結果として Q と R を指すものが存在しなくなり、到達不能になる。

(A) は操作の順序が正しい場合の結果である。 N の次を先に設定してから P の次を書き換えれば、この状態になる。 (C) は操作1が実際に P のポインタを書き換えているため、変わらないということはない。 (D) は head を操作していないため生じない。head が関与するのは 先頭ノードを挿入・削除の対象とする場合に限られる。

確認問題 3-2

head → A → B → C → D → NULL という線形リストに対し、 以下の操作を順に正しく行った。すべての操作の完了後、 このリストに含まれるノードの個数はいくつか。 

1. B と C の間に新しいノード X を挿入する
2. ノード A を削除する
3. 末尾（D の後ろ）に新しいノード Y を追加する
4. ノード X を削除する
  1. 3個
  2. 4個
  3. 5個
  4. 6個
解答

正解: (B)

初期状態は A・B・C・D の4個である。操作1で X が加わり5個、 操作2で A が除かれ4個（head は B を指すようになる）、 操作3で Y が加わり5個、操作4で X が除かれ4個となる。 最終的なリストは head → B → C → D → Y → NULL である。

(A) は削除2回のみを数え、追加を取りこぼした場合の値である。 (C) は操作4の削除を反映し忘れた場合の値になる。 (D) は追加2回のみを数え、削除を反映しなかった場合の値である。 挿入と削除は個数を1ずつ増減させるだけであり、 操作する位置が先頭・中間・末尾のいずれであっても個数への影響は変わらない。

4双方向リスト — 前にも戻る

線形リストには不便な場面がある。あるノード C を削除したいとき、 実際に書き換える必要があるのはC の直前のノードが持つポインタである。 ところが C は自分の次しか知らず、直前が誰であるかを知る手段を持たない。 結局 head から順にたどり直して直前のノードを探すことになる。

この無駄を解消するのが双方向リストである。各ノードに、 次を指すポインタに加えて前のノードを指すポインタを持たせる。

得られるものと支払う代償

削除したいノードを手にしている状態であれば、そのノードの前と次は ノード自身から直ちに分かる。たどり直しは不要になる。 ノード C を削除する手順は次のとおりである。 

1. C の前が持つ「次」 ← C の次
2. C の次が持つ「前」 ← C の前

一方で代償もある。主たるものは整合を保つべき箇所が増えることである。 中間への挿入では、新ノードの前後2本と、前後のノードがそれぞれ持つ1本ずつで 計4本を扱うことになる。どれか1本でも張り替えを誤れば、 前からたどった並びと後ろからたどった並びが食い違う。 単方向であれば起こりえなかった種類の不整合である。

ノードあたりの記憶域も増えるが、これが選択を左右するのは ノードが小さく大量にある場合や、使える記憶域の総量が限られる環境に限られる。 ノードが相応の大きさのデータを持つなら、ポインタ1本分の増加は全体のごく一部である。

単方向で足りる場合

前へ戻れることは、それが必要な場合にのみ利点となる。 扱う操作の側に、前へ戻る動作が存在しない構造がある。 スタックは先頭への追加と先頭からの取り出しだけを行い、 キューは末尾への追加と先頭からの取り出しだけを行う。 いずれも途中のノードから前へ戻る場面がないため、 前のポインタを持たせても一度も使われない。

記憶域の比率が効いてくるのもこの場合である。 値が整数1つであるノードを考えると、おおよそ値8バイトにポインタ8バイトで16バイト、 双方向にすれば24バイトとなり、1.5倍に増える。

選択の向き

双方向リストは単方向リストの上位版ではない。 判断は「双方向のほうが多くのことができるから双方向にする」ではなく、 前へ戻る操作が必要かどうかで行う。 必要がなければ、使われないポインタと張り替えの手間を抱え込まずに済む。

誤りやすい点

双方向リストで前へ戻れるようになっても、添字による直接アクセスが できるようになるわけではない。増えたのは移動できる向きであって、 到達の手段は依然としてたどることのみである。 k番目の要素を得るには、やはり端から k 回たどる必要がある。

確認問題 4-1

単方向の線形リストを双方向リストに変更した。この変更によって 改善される操作として、最も適切なものはどれか。 いずれのリストでも、対象ノードは既に手元にあるものとする。

  1. 先頭から数えて k 番目のノードへ到達する操作
  2. 手元にあるノード自身をリストから削除する操作
  3. 末尾のノードの値を読み取る操作
  4. リスト全体のノード数を数える操作
解答

正解: (B)

自分自身の削除には直前ノードのポインタの書き換えが要る。 単方向では直前を知る手段がなく先頭からたどり直すことになるが、 双方向では前へのポインタから直ちに得られる。

(A) は向きが増えても到達手段がたどることである点は変わらないため、 要する手数は改善されない。 (C) は末尾へ到達するまでに全ノードをたどる点が単方向と同じである。 末尾を指す情報を別に保持すれば改善するが、それは双方向化とは別の工夫である。 (D) は結局すべてのノードをたどる必要があり、向きが増えても数える手間は変わらない。

5カーソルリスト — 添字で次を指す

ここまでの方式は、ノードを必要に応じて確保し、 その位置をポインタで指すことを前提としてきた。 しかしポインタを扱えない言語や、実行中の領域確保を避けたい環境では この前提が成り立たない。

カーソルリストは、あらかじめ確保した配列を記憶域として用い、 「次はどれか」を配列の添字で表す方式である。 ポインタの役割を添字が代行する。この添字を カーソル(cursor) と呼ぶ。 次が存在しないことは、添字として有効でない値（ここでは -1）で表す。

空き領域の管理という追加の仕事

ポインタを用いる方式では、新しいノードが必要になったときに その都度、処理系に領域を要求すればよかった。 カーソルリストにはその仕組みがないため、 配列のどの位置が未使用であるかを自分で管理する必要がある。

一般的な方法は、未使用の位置どうしを同じ仕組みで連結し、 空き位置の並びとして保持することである。挿入時はその先頭から1つ取り出して使い、 削除時は空いた位置をその並びへ戻す。 使用中の並びと未使用の並びが、ひとつの配列の中に共存する形になる。 この空き位置の並びを自由リスト(free list) と呼ぶ。

添字で指すことが要件になる場面

カーソルリストは、ポインタを持たない言語で連結リストを実現する技法として生まれた。 その意味では、ポインタと動的な領域確保を備えた言語を使える場面で あえて選ぶ理由は乏しい。空き領域の管理を自分で背負う負担に見合わないためである。

一方で、ポインタを使えない、あるいは使うべきでない場面では今も選ばれる。 いずれも「次の在りかを添字で表す」という性質そのものが要件になっている。

  • 処理系やランタイムの内部 — 動的な領域確保の仕組みを提供する側は、その仕組みを使えない。 空き領域を自由リストで管理する実装は、カーソルリストの考え方そのものである
  • 動的確保が禁じられる領域 — 組込みやリアルタイム制御では、実行中の確保失敗や所要時間の変動を避けるため、 記憶域をあらかじめ静的に確保する規約を採ることがある。 この制約下で連結構造を作る手段が添字による連結である
  • ファイルやデータベースへの保存 — ポインタが指すのは実行中の記憶域上の位置であり、 プログラムの外へ持ち出しても意味を成さない。 構造を保存する際は、参照を添字やファイル内の位置として表す必要がある
  • 走査の速さが要る場面 — ポインタで連結したノードは記憶域上に散らばりうるのに対し、 カーソルリストの要素は配列の中にまとまって並ぶ。 この配置の差が、連続した領域をまとめて読む計算機の仕組みの上では速度差として現れる

つまりカーソルリストは、ポインタ方式に取って代わられた古い技法ではなく、 ポインタが使えない条件下での定石として位置づけられる。

誤りやすい点

カーソルリストで行う挿入・削除は、ポインタ方式と同様に添字の付け替えで済み、 要素の移動は生じない。しかし記憶域は最初に確保した配列の範囲に限られる。 空き位置を使い切れば、それ以上の追加はできない。 挿入・削除が軽いことと、格納できる件数に上限がないこととは別の事柄である。

確認問題 5-1

線形リスト・双方向リスト・カーソルリストに関する記述のうち、 正しいものはどれか。

  1. 双方向リストは各ノードが次ノードへのポインタのみを持つため、前のノードへは戻れない
  2. 線形リストは配列と同様に、添字を指定して任意の要素へ直接アクセスできる
  3. カーソルリストは配列の添字で次の要素を指し示すため、格納できる要素数に上限はない
  4. いずれの方式でも、途中への挿入で他の要素を移動させる必要はない
解答

正解: (D)

3つのリストに共通する利点が、挿入・削除が参照の付け替えのみで完結する点である。 ポインタであれ添字であれ、順序を表しているのは要素自身が持つ情報であり、 それを書き換えれば順序は変わる。他の要素の位置は影響を受けない。

(A) は単方向の線形リストの説明である。双方向リストは前後2本のポインタを持つため、 前のノードへ戻れる。 (B) は線形リストに配列の性質を当てはめた誤りで、到達手段は先頭からたどることのみである。 (C) は前半の「配列の添字で次を指す」までは正しいが、結論が誤っている。 記憶域はあらかじめ確保した配列であるから、その範囲を超えて格納することはできない。

6リストと配列の使い分け

ここまでに、線形リスト・双方向リスト・カーソルリストの3つを見てきた。 いずれも要素自身が次の在りかを持つという点で共通し、 違いは前にも戻れるか、次の在りかをポインタで表すか添字で表すかにある。 配列と対比するうえでは、この3つはひとまとまりに扱える。

構造の選択は、優劣ではなくそのプログラムが頻繁に行う操作が何かで決まる。 判断の基準となる観点を整理する。

表 6-1　配列と3つのリストの対比。到達の速さと挿入・削除の軽さは両立しにくく、 一方を得るために他方を手放す関係にある。 このような関係をトレードオフ(trade-off) と呼ぶ。

k番目への到達 添字から直接計算できる 先頭から k 回たどる いずれかの端から k 回たどる 先頭から k 回たどる
途中への挿入・削除 後続要素をすべて移動する ポインタを付け替える ポインタを付け替える 添字を付け替える
直前の要素を知る 添字を1減らす 先頭からたどり直す 前のポインタから直ちに分かる 先頭からたどり直す

二つの速さを混同しない

選択を誤る最も多い原因が、「要素へ到達する速さ」と 「挿入・削除の軽さ」を同じものとして扱うことである。 この二つは配列とリストで逆の関係にある。

配列が到達に強いのは、要素が連続領域に等間隔で並ぶからである。 そしてまさにその並びを保つために、途中への挿入では後続をずらす必要が生じる。 リストが挿入・削除に強いのは、順序を配置から切り離したからである。 そしてまさにそのために、位置の計算による到達ができない。 一方の強みの根拠が、そのまま他方の弱みの原因になっている。

したがって選択の手順は、まずそのプログラムで何が頻繁に起きるかを見定めることになる。 要素をなぞって順に処理することが主であり、途中の出し入れが多いならリストが適する。 位置を指定した読み書きが主で、要素数がほぼ変わらないなら配列が適する。 ポインタを扱えない、あるいは実行中の領域確保を避けたい制約があるなら、 リストの利点をカーソルリストで得る。 前の要素へ戻る操作が繰り返し現れるなら、記憶域の増加を受け入れて双方向リストを選ぶ。

確認問題 6-1

要素数100の配列と、100要素の線形リストがそれぞれある。 次の操作のうち、要素の移動やたどり直しが最も少なく済むものはどれか。

  1. 配列の先頭（添字0）に新しい要素を挿入する
  2. 配列の添字50の要素の値を読み取る
  3. 線形リストの50番目のノードの直後に新しいノードを挿入する
  4. 線形リストの末尾に新しいノードを追加する
解答

正解: (B)

配列の添字を指定した読み取りは、先頭アドレスと添字から位置を計算して 直接行える。要素の移動もたどり直しも生じない。

(A) は先頭に場所を空けるため、既存の100要素すべてを後ろへずらす必要がある。 (C) はポインタの付け替え自体は軽いものの、50番目のノードへ到達するまでに 先頭から50回たどることになる。 (D) も末尾に到達するまで全ノードをたどるため、99回の移動を要する。 リストの挿入が軽いのは位置が既に分かっている場合であり、 位置を探す手間は別に生じる点に注意を要する。

7総括

  • 配列は順序をメモリ上の配置で表すため、途中への挿入で後続要素の移動を伴う
  • リストは順序を要素自身が持つ参照で表すことで、配置から順序を切り離す
  • 線形リストのノードは値と次への参照を持ち、要素への到達は head からたどることのみで行う
  • 挿入・削除はポインタの張り替えで完結する。張り替えの順序を誤ると以降のノードへ到達できなくなる
  • 先頭を対象とする挿入・削除では、ノードではなく head を書き換える
  • 双方向リストは前への参照を加えることで直前のノードを直ちに得るが、記憶域と張り替え本数が増える
  • カーソルリストはポインタの役割を配列の添字で代行し、空き位置の管理を自ら担う。格納件数は確保した配列の範囲に限られる
  • 構造の選択は、到達の速さと挿入・削除の軽さのどちらを必要とするかで決まる
