1速さを何で測るか

名簿に同じ学籍番号が二重に登録されていないかを調べたい。 ある手順は名簿を1回だけ見通して判定し、別の手順はあらゆる2人の組を突き合わせて判定する。 名簿が10人分であれば、どちらも一瞬で終わる。どちらを選んでも差は感じられない。

ところが名簿の件数が増えると事情が変わる。 番号ごとに印を付ける表を用意して1回見通す手順は、件数 n に比例する回数の操作で済む。これに対し、 組を突き合わせる手順はおよそ n × n 回の操作を要する。 1秒間に1億回の操作を行う計算機を仮定して、両者の所要時間を並べる。

表 1-1　1秒間に1億回の操作を行う計算機での所要時間。件数が少ないうちは差が見えないが、 100万件では一方が0.01秒、他方が約2.8時間となる。差を生むのは計算機ではなく手順である。

件数 nn 回の操作n × n 回の操作
100.1 マイクロ秒1 マイクロ秒
1,00010 マイクロ秒0.01 秒
1,000,0000.01 秒約 2.8 時間

手順の良し悪しを実行時間の秒数で比べようとすると、二つの困難に突き当たる。 第一に、秒数は計算機の性能・言語・処理系によって変わる。 同じ手順でも、速い計算機で動かせば短く測られる。 第二に、秒数は与えたデータの件数と並び方によって変わる。 10件で測った結果は、100万件での振る舞いを教えてくれない。

そこで、秒数の代わりに手順が行う操作の回数を、データの件数の式として表す。 この式は計算機に依存せず、件数が増えたときの振る舞いを直接示す。 このように、手順の実行に要する手間を見積もった量を 計算量(computational complexity) と呼ぶ。 計算量を用いて手順の効率を論じることが、アルゴリズムの評価の基本となる。

本講では次の事柄を扱う。

  • 基本操作の回数を、入力の規模の式として数える方法
  • 式から増え方だけを取り出す O記法
  • 代表的な計算量のクラスと、それぞれを生む手順の形
  • 手順の組み合わせから計算量を求める規則
  • 入力によって手数が変わる場合の、最悪・平均・最良の区別
  • 計算量に基づく手順とデータ構造の比較、およびその限界
本講の到達点
  • 手順の基本操作の回数を、入力規模 n の式として数えられる
  • O記法の意味を述べ、手数の式を O記法で表せる
  • 代表的な計算量のクラスを増え方の順に並べ、それぞれを生む手順の形を説明できる
  • 手順の組み合わせ方から計算量を求められる
  • 最悪計算量・平均計算量・最良計算量を区別できる
  • 計算量に基づいて手順やデータ構造を比較し、その比較が成り立つ条件を述べられる
確認問題 1-1

同じ問題を解く手順 P と手順 Q がある。P を自宅の計算機で、Q を学校の計算機で、 それぞれ手元にあったデータを与えて実行したところ、P は 0.8 秒、Q は 1.5 秒で終わった。 この結果から言えることとして、最も適切なものはどれか。

  1. P は Q より効率の良い手順であり、どの計算機・どのデータでも P のほうが速い
  2. 計算機とデータが揃っていないため、この測定値だけでは手順の優劣を判断できない
  3. Q は P のおよそ2倍の回数の操作を行っている
  4. 同じ計算機・同じデータで測り直して P が速ければ、件数をどれだけ増やしても P のほうが速いと確定する
解答

正解: (B)

実行時間は手順だけでなく、計算機の性能と与えたデータの件数・並び方にも左右される。 二つの条件が異なる測定値を比べても、差がどこから生じたのかを切り分けられない。

(A) は、条件の異なる一回の測定を手順の性質に帰している。 (C) は、時間と操作回数の比例を、性能の異なる計算機の間にまで当てはめている。 (D) は、ある件数で成り立った大小が、件数を増やしても保たれると考えている。 表 1-1 のように、件数が増えるほど開く差は小さな件数での測定には現れず、 件数によって大小が入れ替わることもある。

2手順を数える — 基本操作と入力規模

何を数えるか

計算量を求めるには、まず「1回」と数える単位を決める。 値の比較1回、代入1回、四則演算1回のように、 データの件数に関係なく一定の手間で終わる操作を 基本操作(basic operation) とみなし、その回数を数える。 比較と代入のどちらに時間がかかるかといった差は、計算機によって異なるため区別しない。

数えた回数は、手順に与えるデータの量によって変わる。 この量を 入力規模(input size) と呼び、 多くの場合 n で表す。配列であれば要素数、名簿であれば件数が入力規模にあたる。 基本操作の回数を n の式 T(n) として表したものを 時間計算量(time complexity) と呼ぶ。 単に計算量と言えば、通常は時間計算量を指す。

繰り返しの回数を数える

配列の最大値を求める手順で数え方を確かめる。 以下の擬似コードでは、添字を 1 から n までとする。 

最大値(配列 A, 要素数 n):
1. max ← A[1]
2. i を 2 から n まで 1 ずつ増やしながら、次を繰り返す
   2.1 A[i] > max ならば max ← A[i]
3. max を返す

比較が行われるのは 2.1 の行であり、繰り返しの中で1回ずつ実行される。 繰り返しは i が 2 から n までの値をとるので、回数は n − 2 + 1 = n − 1 回である。 両端を含む区間「a から b まで」に含まれる値の個数は b − a + 1 であり、 単に n − 2 とすると1回足りない。 比較回数は T(n) = n − 1 となり、要素数に比例して増える。

入れ子の繰り返しを数える

次に、配列の中に等しい値の組がいくつあるかを数える手順を考える。 冒頭の名簿の例で、あらゆる2人の組を突き合わせる手順にあたる。 

等しい組を数える(配列 A, 要素数 n):
1. count ← 0
2. i を 1 から n − 1 まで 1 ずつ増やしながら、次を繰り返す
   2.1 j を i + 1 から n まで 1 ずつ増やしながら、次を繰り返す
       2.1.1 A[i] = A[j] ならば count ← count + 1
3. count を返す

内側の繰り返しは j が i + 1 から始まるため、 外側が進むほど回数が減る。i = 1 のとき n − 1 回、 i = 2 のとき n − 2 回と続き、最後の i = n − 1 では1回になる。 比べる組を表のマス目として描くと、数え方が見える。

一般の n では、全 n × n マスから対角線の n マスを除き、 残りの半分を数えることになる。比較回数は T(n) = n(n − 1) ÷ 2 である。 n が 2倍になると回数はおよそ4倍になり、 最大値を求める手順の n − 1 回とは増え方が根本的に異なる。

確認問題 2-1

上の「等しい組を数える」手順に、要素数 n = 6 の配列を与える。 2.1.1 の行で行われる比較 A[i] = A[j] の回数はいくつか。

  1. 36 回
  2. 30 回
  3. 21 回
  4. 15 回
解答

正解: (D)

外側の i が 1, 2, 3, 4, 5 のとき、内側の繰り返しはそれぞれ 5, 4, 3, 2, 1 回である。 合計は 5 + 4 + 3 + 2 + 1 = 15 回で、6 × 5 ÷ 2 = 15 と一致する。

(A) の 36 は 6 × 6 であり、自分自身との比較と、同じ組の二度目の比較を含めている。 (B) の 30 は 6 × 5 であり、対角線は除いたが、 (i, j) と (j, i) を別の組として二度数えている。 (C) の 21 は 6 × 7 ÷ 2 であり、対角線のマスを数えに入れている。

3O記法 — 増え方だけを残す

大きな n では最高次の項が支配する

手順を細かく数えると、T(n) = 3n² + 5n + 2 のように複数の項を持つ式になることが多い。 この式の各項が全体に占める割合を、n を増やしながら調べる。

表 3-1　T(n) = 3n² + 5n + 2 の各項の値と、全体に占める 3n² の割合。 n が大きくなるほど、最高次の項だけで全体がほぼ決まる。

n3n²5n2T(n)3n² の割合
1030050235285.2 %
10030,000500230,50298.4 %
1,0003,000,0005,00023,005,00299.8 %

計算量が問題になるのは、n が大きい場合である。 件数が少なければどの手順でもすぐに終わり、選択の根拠にならない。 そして n が大きいとき、低次の項 5n と定数 2 は全体にほとんど影響しない。

残った 3n² の係数 3 も、手順の性質を表すものではない。 何を基本操作として数えたか、どの計算機で動かすかによって、係数は容易に変わる。 一方、n が 2倍になれば手数がおよそ4倍になるという増え方は、係数によらず変わらない。 手順を比べる際に知りたいのは、この増え方である。

O記法の定義

手数の式から増え方だけを取り出して表す記法を O記法(big-O notation) と呼ぶ。 「オーダー」と読み、T(n) = O(n²) のように書く。定義は次のとおりである。

定義

ある正の定数 c と n₀ が存在して、 n ≥ n₀ を満たすすべての n について T(n) ≤ c · f(n) が成り立つとき、 T(n) = O(f(n)) と書く。

言い換えると、十分大きな n では、T(n) が f(n) の定数倍を超えないということである。 T(n) = 3n² + 5n + 2 であれば、c = 4 とすると n ≥ 6 で T(n) ≤ 4n² が成り立つ。したがって T(n) = O(n²) である。

O記法で表す手順

定義から、手数の式を O記法で表す際には次の操作を行えばよい。

  • 最も速く増える項だけを残し、それ以外の項を捨てる
  • 残した項の係数を捨てる

n − 1 は O(n)、n(n − 1) ÷ 2 = n²/2 − n/2 は O(n²)、 n によらず一定の回数で終わる手順は O(1) となる。 O記法の中には、係数と低次の項を除いた最も簡潔な形を書くのが慣例である。

対数を含む計算量では、底を書かずに O(log n) と書く。 底の異なる対数は log₂ n = log₁₀ n ÷ log₁₀ 2 のように定数倍の違いしかなく、 O記法では係数を区別しないためである。

誤りやすい点

O記法が示すのは上からの抑えである。 T(n) = O(n) は「手数がちょうど n 回である」ことも、 「どんな入力でも n に比例して必ずかかる」ことも意味しない。 十分大きな n で、手数が n の定数倍を超えないことだけを述べている。 また、どの定数倍かを明示しないため、特定の n での回数の上限も O記法からは読み取れない。

確認問題 3-1

ある手順の基本操作の回数が T(n) = 4n² + 100n + 7 と求まった。 これを O記法の慣例に従って最も簡潔に表したものはどれか。

  1. O(n)
  2. O(n²)
  3. O(4n²)
  4. O(n² + n)
解答

正解: (B)

最も速く増える項 4n² を残し、係数 4 を捨てると O(n²) になる。

(A) は、小さな n では 100n が 4n² より大きいことに引きずられている。 n = 25 を越えると 4n² のほうが大きくなり、以降その差は開く一方である。 n の定数倍で抑えることはできない。 (C) と (D) は誤りではないが、係数や低次の項を残しており、慣例に従った簡潔な形ではない。 O記法はこれらを区別しないため、書き残しても情報は増えない。

確認問題 3-2

手順 R の計算量が O(n) であると分かっている。この事実から言えることとして、正しいものはどれか。

  1. R の基本操作の回数は、ちょうど n 回である
  2. n = 100 のとき、R の基本操作の回数は 100 回以内である
  3. 十分大きな n では、R の基本操作の回数は n の定数倍を超えない
  4. R に与える入力をどう選んでも、基本操作の回数は n に比例して増える
解答

正解: (C)

O記法の定義そのものである。ある定数 c と n₀ があって、 n ≥ n₀ では回数が c · n 以下に収まる。

(A) は、O記法が係数と低次の項を捨てた表記であることを見落としている。3n + 5 回の手順も O(n) である。 (B) は、定数 c が 1 であると決めつけている。O記法は定数倍を明示しないため、特定の n での回数は分からない。 (D) は、上からの抑えを、下からの抑えと取り違えている。 入力によっては1回で終わる手順であっても、計算量は O(n) と書ける。

4代表的な計算量のクラス

O記法で表した計算量は、実際に現れるものが限られている。 増え方の遅い順に並べると、次のようになる。

O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ)

ここでの < は、n が十分大きいとき左のほうが手数が少ないことを表す。 それぞれの計算量は、特定の形の手順から生じる。手順の形を見分けられれば、 細かく数えなくても計算量の見当がつく。

表 4-1　代表的な計算量のクラスと、それを生む手順の形。手順の形は、繰り返しの回数が n とどのように結び付いているかで決まる。

計算量呼び方手順の形例
O(1) 定数時間 n に関係なく一定の回数で終わる 配列の添字による読み出し、スタックへの push
O(log n) 対数時間 1回の操作ごとに候補を半分（一定の割合）に絞る 形の整った二分探索木での探索
O(n) 線形時間 すべての要素を一定回数ずつ扱う 配列の最大値、リストを先頭からたどる
O(n log n) — 全体を半分に分けることを繰り返し、分けた各段で全要素を一定回数ずつ扱う。または O(log n) の操作を n 回繰り返す 形の整った二分探索木への n 回の挿入、並べ替えてから隣どうしを比べる重複調べ
O(n²) 2乗時間 すべての要素の組を扱う（入れ子の繰り返し） 等しい組を数える手順（図 2-1）
O(2ⁿ) 指数時間 各要素を「選ぶ・選ばない」のすべての組合せを試す 要素の部分集合をすべて調べる

対数は「半分にできる回数」

O(log n) は、表の中で最も直観に結び付きにくい。 1 から 16 までの数のうち相手が思い浮かべた一つを、 「ある数以下か」という問いへの答えだけで当てる場合を考える。 候補の中央で区切って問うと、答えがどちらであっても候補の半分を捨てられる。

候補が 2倍に増えても、問いは1回増えるだけで済む。 対数時間の手順は、入力規模が何倍になっても手数がほとんど増えない。 ただしこの手が使えるのは、1回の操作で候補の一部をまとめて捨てられる場合に限られる。 候補が大小の順に並んでいる、木の形が整っているといった前提が崩れると、 半分に絞る根拠が失われる。

O(n log n) — 段の数 × 各段の手数

O(n log n) は、log n 回で済む構造と n 回を要する構造が 掛け合わさったときに現れる。典型的な形は二つある。

一つ目は、全体を半分に分けることを繰り返し、分けてできた各段で全要素を扱う形である。 n 個の要素は log₂ n 回半分にすると1個ずつになる。 段ごとに組の数と大きさは変わるが、どの段でも組をすべて合わせれば n 個である。

たとえば、二つの組をそれぞれ大小の順に並べ終えていれば、両者の先頭どうしを比べて小さいほうを取り出すことを 繰り返すだけで、合わせた組全体を大小の順に並べられる。この手間は二つの組の要素数の合計に比例する。 1個ずつの組から始めてこの「まとめ上げ」を段ごとに行えば、各段の手数は n に比例し、 段の数は log₂ n であるから、全体は O(n log n) となる。

二つ目は、O(log n) の操作を n 回繰り返す形である。 次のような手順がこれにあたる。

  • n 個の値を、形の整った二分探索木に1つずつ挿入する。 1回の挿入は木の高さ、すなわち log n 程度の手数で済み、それを n 回行う
  • 大小の順に並んだ n 件の名簿に対し、n 件の問い合わせそれぞれについて、 図 4-1 のように候補を半分ずつ絞って該当者を探す
  • n 回の繰り返しの中で、値を 2 で割り続ける処理を行う

冒頭の名簿の重複調べも、この計算量で行える。すべての組を突き合わせる手順は O(n²) であった。 代わりに、まず名簿を番号の順に並べ替え、次に隣り合う2件だけを比べる。 同じ番号は並べ替えた後に必ず隣り合うため、隣どうしを n − 1 回比べれば重複を見落とさない。 並べ替えは n log n 程度の手数で行う方法が知られており、 後半の n − 1 回はそれより遅く増えるので、全体は O(n log n) に収まる。 100万件であれば手数は約2,000万回となり、1秒間に1億回の操作を行う計算機で約0.2秒である。 同じ件数ですべての組を突き合わせると約2.8時間を要するのと比べ、 O(n log n) は O(n) よりわずかに重いだけで、O(n²) とは桁違いに軽い。

O(1) から O(n²) までは、n のべき乗またはそれ以下で抑えられる。 このような計算量を 多項式時間(polynomial time) と呼ぶ。 O(2ⁿ) は n が1増えるたびに手数が2倍になり、多項式時間のどれよりも速く増える。 1秒間に1億回の操作を行う計算機でも、n = 60 で約365年を要する。 指数時間の手順は、入力規模が数十を越えると計算機の性能向上では救えない。 すべての組合せを試す以外の方法が見つかるかどうかが、実用になるかどうかの分かれ目となる。

確認問題 4-1

要素数 n の配列に対する次の手順のうち、計算量が O(log n) となるものはどれか。

  1. 配列の全要素の合計を求める
  2. 値 n を 2 で割る（小数点以下切り捨て）ことを、1 以下になるまで繰り返し、その回数を数える
  3. 配列のすべての要素の組について、2要素の差を求める
  4. 配列の添字 n ÷ 2（中央）の要素を読み出す
解答

正解: (B)

1回の割り算ごとに値が半分になるため、繰り返しの回数は n を半分にできる回数、 すなわち log₂ n 程度である。図 4-1 の候補の絞り込みと同じ形をしている。

(A) はすべての要素を1回ずつ足すため O(n) である。 (C) はすべての組を扱うため O(n²) である。 (D) は「半分」という語から対数を連想させるが、添字から位置を計算して1回読み出すだけであり、 n によらず一定の手数で終わる O(1) である。 対数が生じるのは、半分にする操作を繰り返す場合である。

確認問題 4-2

計算量が O(n²) の手順に n = 1,000 の入力を与えたところ、2秒で終わった。 同じ計算機で n = 10,000 の入力を与えたとき、所要時間はおよそどれだけと見込まれるか。

  1. 2秒（計算量のクラスが同じため変わらない）
  2. 20秒
  3. 200秒
  4. 2,000秒
解答

正解: (C)

手数が n² に比例するので、n が10倍になると手数は 10² = 100 倍になる。 2秒の100倍で約200秒と見込まれる。

(A) は、計算量のクラスが入力規模によらず同じであることを、所要時間が同じであることと取り違えている。 クラスが表すのは増え方であって、時間そのものではない。 (B) は O(n) の手順の見積もりであり、手数が n に比例すると考えている。 (D) は 1,000倍、すなわち n³ に比例するとした場合の見積もりである。

確認問題 4-3

要素数 n の配列 B は、値が大小の順に並んでいる。これとは別に n 個の値の組 C がある。 次の手順のうち、計算量が O(n log n) となるものはどれか。

  1. ある値 1 個が B に含まれるかを、候補を半分ずつ絞る方法で調べる
  2. C の各値が B に含まれるかを、それぞれ候補を半分ずつ絞る方法で調べる
  3. C の各値が B に含まれるかを、それぞれ B の先頭から順に調べる
  4. C の各値を、B の先頭の要素 1 個とだけ比べる
解答

正解: (B)

候補を半分ずつ絞る1回の調べは O(log n) であり、それを C の n 個の値について行う。 O(log n) の操作を n 回繰り返す形であり、O(n log n) となる。

(A) は調べる回数が1回だけなので O(log n) である。n 回の繰り返しが掛からない。 (C) は1回の調べが先頭から順にたどる O(n) であり、それを n 回行うので O(n²) となる。 繰り返しの形は (B) と同じだが、1回あたりの手数が異なる。 (D) は1回の比較が O(1) であり、n 回で O(n) である。

5計算量の求め方 — 組み合わせの規則

手順は、繰り返しや条件分岐を組み合わせて作られる。 部分ごとの計算量が分かれば、組み合わせ方に応じた規則で全体の計算量が求まる。

表 5-1　手順の組み合わせ方と計算量の規則。逐次は和、入れ子は積をとり、 和は O記法の下で最も大きい項だけが残る。

組み合わせ方規則例
逐次（順に実行する） 大きいほうが残る O(n) の後に O(n²) → O(n²)
入れ子（繰り返しの中で実行する） 繰り返し回数と中身の計算量の積 n 回の繰り返しの中で O(n) → O(n²)
半分にしていく繰り返し 回数は log n 変数を 2 で割り続ける → O(log n)
条件分岐 重いほうの分岐で見積もる 一方が O(1)、他方が O(n) → O(n)

逐次 — 大きいほうが残る

最大値を求めてから等しい組を数える手順の手数は、 (n − 1) + n(n − 1) ÷ 2 である。 和をとっても、O記法では最も速く増える項だけが残るので、全体は O(n²) になる。 順に並んだ処理のうち、最も重い一つが全体の計算量を決める。 手順を速くしたいとき、軽い部分を改良しても計算量は変わらない。

入れ子 — 回数を掛け合わせる

繰り返しの中に処理があれば、繰り返しの回数と中身の計算量を掛ける。 次の手順は、外側が n 回、内側が n 回であり、O(n × n) = O(n²) である。 

1. i を 1 から n まで 1 ずつ増やしながら、次を繰り返す
   1.1 j を 1 から n まで 1 ずつ増やしながら、次を繰り返す
       1.1.1 基本操作を 1 回行う

図 2-1 の手順のように内側の回数が外側に応じて減る場合も、合計は n²/2 程度であり、 計算量は同じく O(n²) となる。

誤りやすい点

入れ子の深さが、そのまま n の次数になるとは限らない。 決め手は各繰り返しの回数が n とどう結び付いているかである。 内側の繰り返しが n によらず3回で終わるなら全体は O(n) であり、 内側が値を半分にしていく繰り返しなら O(n log n) となる。

半分にしていく繰り返し

1. k ← n
2. k > 1 である間、次を繰り返す
   2.1 k ← k ÷ 2（小数点以下切り捨て）

繰り返しのたびに k が半分になるため、回数は log₂ n 程度である。 図 4-1 で候補が半分ずつ減ったのと同じ構造である。 倍々に増やしていく繰り返し（k ← k × 2 を k が n に達するまで）も、 同じく O(log n) となる。

条件分岐 — 重いほうで見積もる

条件によって実行される処理が異なる場合、どちらが実行されるかは入力によって変わる。 どの入力に対しても成り立つ見積もりとするには、重いほうの分岐の計算量を採る。 入力によって手数が変わる場合の見積もり方は、最悪・平均・最良の区別として整理される。

確認問題 5-1

次の手順の計算量はどれか。

1. i を 1 から n まで 1 ずつ増やしながら、次を繰り返す
   1.1 k ← n
   1.2 k > 1 である間、次を繰り返す
       1.2.1 基本操作を 1 回行う
       1.2.2 k ← k ÷ 2（小数点以下切り捨て）
  1. O(n)
  2. O(log n)
  3. O(n log n)
  4. O(n²)
解答

正解: (C)

内側の繰り返しは k を半分にしていくため、log₂ n 回程度で終わる。 これが外側の n 回の繰り返しの中にあるので、積をとって O(n log n) となる。

(A) は外側の繰り返しだけを数え、内側を一定回数とみなしている。 (B) は内側の繰り返しだけを数え、外側との積をとっていない。 (D) は、繰り返しが二重であることから次数を2と決めつけている。 内側の回数は n ではなく log n である。

6最悪・平均・最良 — 入力によって変わる手数

ここまでの例は、n が決まれば手数も決まる手順であった。 しかし多くの手順では、同じ n でもデータの中身や並び方によって手数が変わる。 配列の中から値 x を先頭から順に調べて探す手順で確かめる。 

探す(配列 A, 要素数 n, 値 x):
1. i を 1 から n まで 1 ずつ増やしながら、次を繰り返す
   1.1 A[i] = x ならば、i を答えとして終了する
2. 見つからなかったとして終了する

このように先頭から順に一つずつ調べる探し方を 線形探索(linear search) と呼ぶ。 x が先頭にあれば比較は1回で済む。末尾にあるか、配列に含まれていなければ n 回を要する。 同じ要素数でも、手数は 1 回から n 回までの幅を持つ。

三つの見積もり方

  • 最悪計算量(worst-case complexity) — 要素数 n の入力のうち、手数が最も多くなるものでの計算量。線形探索では O(n)
  • 平均計算量(average-case complexity) — 入力の現れ方を仮定し、手数の平均をとった計算量。x が必ず含まれ、どの位置にも等しい確率で あるとすれば、比較回数の平均は (1 + 2 + … + n) ÷ n = (n + 1) ÷ 2 回であり、O(n)
  • 最良計算量(best-case complexity) — 手数が最も少なくなる入力での計算量。線形探索では O(1)

アルゴリズムを評価する際は、一般に最悪計算量を用いる。 最悪計算量は、どの入力に対しても手数がそれを超えないという保証になるためである。 応答時間に上限が求められる処理では、平均的に速いことよりも、最悪でも一定の時間に収まることが重要になる。 平均計算量は実際の振る舞いに近い見積もりを与えるが、入力がどのように現れるかの仮定を要する。 仮定が実際のデータと合わなければ、見積もりは外れる。 最良計算量は、たまたま都合の良い入力が来た場合の値にすぎず、手順を選ぶ根拠にはなりにくい。

平均と最悪の差が大きい例に、二分探索木がある。 形が整っていれば探索は O(log n) で済むが、 整列済みの値を順に挿入して一列に退化した木では O(n) を要する。 平均計算量は O(log n)、最悪計算量は O(n) である。 入力が整列済みに近い状況が実際に起こりうるなら、最悪計算量の側で評価しなければならない。

確認問題 6-1

アルゴリズムを評価する際、一般に最悪計算量が用いられる。その理由として最も適切なものはどれか。

  1. 実際の利用では、手数が最も多くなる入力が最も頻繁に現れるから
  2. どの入力に対しても、手数がその値を超えないことを保証できるから
  3. 最悪計算量は、最良計算量よりも常に小さい値になるから
  4. 平均計算量は O記法で表すことができないから
解答

正解: (B)

最悪計算量は、要素数 n のあらゆる入力の中で手数が最も多いものに基づく。 したがって、どの入力が来てもその計算量を超えないという上限の保証になる。 入力の現れ方について何の仮定も要しない点も利点である。

(A) は、最悪の入力が現れる頻度を問題にしている。最悪計算量を用いる理由は頻度ではなく保証であり、 最悪の入力がまれであっても、起こりうる限り上限として意味を持つ。 (C) は大小を取り違えている。最悪の場合の手数は、最良の場合の手数以上である。 (D) は誤りである。線形探索の平均が O(n) であるように、平均計算量も O記法で表せる。 平均計算量の難点は表記ではなく、入力の現れ方の仮定を要することにある。

7計算量で比較・評価する

データ構造の操作を計算量で整理する

データ構造の得意・不得意は、操作ごとの計算量として表せる。 配列・リスト・スタック・キュー・二分探索木はいずれも要素の集まりを保持する構造であり、 どの操作が速いかの違いを同じ尺度で並べられる。

表 7-1　データ構造の主な操作の計算量（要素数を n とする）。 計算量の違いは、要素の配置の仕方から直接説明できる。

構造操作計算量根拠
配列 添字を指定した読み出し O(1) 先頭の位置と添字から、要素の位置を計算で求められる
先頭・途中への挿入 O(n) 挿入位置より後ろの要素を1つずつずらす
値の探索（並びに規則がない場合） O(n) 先頭から順に調べるしかない
線形リスト
（先頭のみ保持）		 位置が分かっているノードの直後への挿入 O(1) ポインタの張り替えだけで済み、他のノードは動かない
k 番目のノードへの到達 O(n) 先頭から順にたどるしかない
k 番目の直後への挿入 O(n) 到達 O(n) と張り替え O(1) の逐次であり、大きいほうが残る
スタック push・pop O(1) top の位置だけを操作し、既存の要素には触れない
キュー enqueue・dequeue O(1) 先頭と末尾の位置を保持しており、両端だけを操作する
二分探索木 値の探索・挿入・削除 平均 O(log n)
最悪 O(n)		 手数は木の高さに比例する。高さは形が整っていれば log n 程度、退化すれば n 程度

リストの挿入は張り替えだけで済むので O(1) と言われることが多いが、 これは挿入する位置にすでに到達している場合の計算量である。 k 番目という指定で挿入するなら、そこまでたどる O(n) が加わる。 手順の計算量を見積もる際は、目的の位置へ届くまでの手数を含めて数える必要がある。

計算量で比較できる範囲

計算量は、n が大きいときの増え方を比べる尺度である。 したがって、計算量の小さい手順のほうが速いと言えるのは、n が十分大きい場合に限られる。 手数がそれぞれ 100n 回と n² 回の手順を比べると、 計算量では前者の O(n) が優れている。しかし n が 100 未満では後者の手数のほうが少ない。

この逆転が選択を左右するのは、扱うデータが常に数十件程度に限られる場合や、 小さな入力に対する処理を非常に多くの回数繰り返す場合である。 このような場面では、計算量の大きい単純な手順のほうが実際には速いことがある。 一方、データの件数が増えていくことが見込まれる場面では、計算量の差がいずれ係数の差を上回るため、 計算量の小さい手順を選ぶ。

時間と記憶域

手順の評価には、時間のほかに、実行中に必要な記憶域の量という観点もある。 記憶域の量を入力規模の式として表したものを 空間計算量(space complexity) と呼び、同じく O記法で表す。 入力のほかに一定個の変数しか使わない手順は O(1)、 入力と同じ大きさの作業用の配列を用意する手順は O(n) である。

時間と記憶域は、一方を得るために他方を手放す関係になることが多い。 たとえば、あらかじめ計算した結果を表に記録しておけば、同じ問いに O(1) で答えられるが、 表のぶんだけ記憶域を使う。このような関係を トレードオフ(trade-off) と呼ぶ。 記憶域の増加が選択を左右するのは、n が使える記憶域の総量に迫る規模である場合や、 記憶域の限られた機器で動かす場合である。それ以外の場面では、時間計算量を優先して評価することが多い。

確認問題 7-1

いずれも n 個の要素を保持している次の構造について、操作の計算量が O(1) であるものはどれか。

  1. 配列の先頭（最初の添字の位置）に新しい要素を挿入する
  2. 先頭のノードの位置だけを保持する線形リストで、末尾のノードの値を読み出す
  3. キューから要素を1つ取り出す
  4. 形が整っていない場合もある二分探索木で、最大の値を探す（最悪の場合で評価する）
解答

正解: (C)

キューは先頭の位置を保持しており、取り出しは先頭の要素を返して位置を1つ進めるだけで済む。 他の要素には触れないため、n によらず一定の手数で終わる。

(A) は、先頭に場所を空けるために既存の n 個の要素をすべて後ろへずらすため O(n) である。 添字による読み出しが O(1) であることと、挿入の手数を混同しやすい。 (B) は、末尾に到達するまで先頭から n 個のノードをたどる必要があり O(n) である。 (D) は、最大の値を求めて右の子をたどり続けるため、手数は木の高さに比例する。 最悪の場合、木が一列に退化していれば O(n) となる。

確認問題 7-2

同じ問題を解く手順 A と手順 B がある。入力規模 n のとき、 A の基本操作の回数は 100n 回、B は n² 回である。 B の回数が A の回数を上回る最小の n はどれか。

  1. 10
  2. 100
  3. 101
  4. B の回数はどの n でも A を上回る
解答

正解: (C)

n² > 100n を n で割ると n > 100 となる。 これを満たす最小の整数は 101 である。 n = 100 では両者とも 10,000 回で等しく、それより小さい n では B のほうが少ない。

(A) は n² = 100 を解いており、A の回数が 100n であることを見落としている。 (B) は、両者が等しくなる境界の値を、上回り始める値と取り違えている。 (D) は、O記法での大小 O(n) < O(n²) が、どの n でも成り立つと考えている。 O記法の比較は、n が十分大きい場合についてのみ述べている。

8総括

  • 手順の効率は実行時間の秒数ではなく、基本操作の回数を入力規模 n の式として表して比べる。 秒数は計算機とデータに左右されるが、回数の増え方は手順だけで決まる。
  • 繰り返しの回数は、両端を含む区間「a から b まで」で b − a + 1 回と数える。 すべての組を比べる二重の繰り返しは n(n − 1) ÷ 2 回となる。
  • O記法は、十分大きな n で手数が f(n) の定数倍を超えないことを表す。 最も速く増える項を残して係数を捨てれば求まり、対数の底は区別しない。 O記法が示すのは上からの抑えである。
  • 代表的な計算量は O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) の順に増える。 候補を半分ずつ絞る手順は対数時間、半分に分ける段ごとに全要素を扱う手順や 対数時間の操作を n 回繰り返す手順は O(n log n)、すべての組を扱う手順は2乗時間、 すべての組合せを試す手順は指数時間となる。
  • 逐次に並んだ処理は最も重いものが残り、入れ子の処理は回数を掛け合わせる。 入れ子の深さではなく、各繰り返しの回数と n の結び付きが計算量を決める。
  • 同じ n でも入力によって手数が変わる場合は、最悪・平均・最良を区別する。 評価には、どの入力でも超えない保証となる最悪計算量を用いることが多い。
  • データ構造の得意・不得意は、操作ごとの計算量として要素の配置から説明できる。 計算量の比較が成り立つのは n が十分大きい場合であり、 時間と記憶域の間にはトレードオフがある。
