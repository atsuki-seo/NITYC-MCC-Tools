1取り出す順序を定めるという発想

配列は、保持した要素のうち任意の一つを添字で指定して取り出せる構造である。 この自由度は強力であるが、裏を返せば、どの要素を取り出すかを 利用する側が毎回決めなければならないということでもある。

ところが、実際の処理には「取り出す順序があらかじめ決まっている」ものが 少なくない。二つの状況を対比する。

  • 文書編集における取り消し操作 — 直前に行った操作から順に元へ戻す。 三つ前の操作だけを取り消すことはできず、必ず新しいものから処理する
  • 印刷の待ち行列 — 先に依頼された文書から順に印刷する。 後から依頼した文書が先に出力されては、依頼した側の期待に反する。 必ず古いものから処理する

両者はいずれも「溜めておいて、後で一つずつ処理する」という同じ形をしているが、 取り出す順序は正反対である。この順序の規約そのものを構造に埋め込んでしまえば、 利用する側は取り出す位置を指定する必要がなくなり、「次を取り出す」と 命じるだけで済む。この考え方に基づく代表的な構造が スタック(stack) と キュー(queue) である。

本講では、この二つの構造について、順序の規約・基本操作・配列を用いた実装・ 利用に際しての境界条件を扱う。

本講の到達点
  • スタックとキューが定める取り出し順序の規約を、区別して説明できる
  • push／pop、enqueue／dequeue の各操作が構造をどう変化させるかを追跡できる
  • 両構造を配列上に実装する際の位置管理と、境界条件の検査を記述できる
確認問題 1-1

ある処理では、受け付けた依頼を溜めておき、後から一つずつ処理する。 このとき「スタックとして扱うか、キューとして扱うか」という選択が 決定づける事柄として、最も適切なものはどれか。

  1. 溜めておける依頼の最大件数
  2. 依頼を処理する順序
  3. 一件の依頼を処理するのに要する時間
  4. 依頼を溜めるために必要な記憶領域の量
解答

正解: (B)

スタックとキューを分かつのは、溜めた要素のうちどれを次に取り出すか という規約であり、それ以外の性質ではない。

(A) の最大件数は、どちらの構造を選ぶかではなく、確保した領域の大きさによって定まる。 (C) の処理時間は個々の依頼の内容に依存するものであり、溜め方とは独立である。 (D) の記憶領域は保持する要素数と一要素あたりの大きさで決まり、 両構造の間に本質的な差はない。

2スタック — 後入れ先出し

スタックは、最後に入れた要素を最初に取り出す 構造である。この規約を 後入れ先出し(LIFO: last in, first out) と呼ぶ。

二つの基本操作

  • push — 要素を一つ積む
  • pop — 最後に積んだ要素を一つ取り出し、構造から取り除く

重要なのは、出入口が一箇所しかないという制約である。 積むのも取り出すのも同じ端であり、途中や底にある要素へ直接触れる手段は 用意されていない。底にある要素を得るには、その上に積まれた要素を すべて取り出すほかない。

要素を出し入れする側の端を 頂上(top) と呼ぶ。 実装では、この頂上がどこであるかを常に把握しておく必要がある。

頂上の管理

頂上を表す位置を変数で保持する場合、その値が何を指すかには二通りの流儀がある。

  • 最後に積んだ要素の位置を指す方式 — 空の状態を「要素が存在しない」ことを表す値で示し、push では先に位置を一つ進めてから書き込む
  • 次に積むべき位置を指す方式 — 空の状態では先頭位置を指し、push では書き込んでから位置を一つ進める

いずれの方式でも動作するが、push と pop で解釈を取り違えると、 要素の書き潰しや読み飛ばしが生じる。実装の際は、どちらの流儀を 採るかを先に決め、両操作で一貫させることを要する。

誤りやすい点

pop は「頂上の要素を読む」操作と「頂上の位置を一つ戻す」操作の二つからなる。 位置を戻すのを忘れると、同じ要素を何度も取り出し続けることになる。 一方、読む前に位置を戻すと、一つ下の要素を取り出してしまう。 順序は方式に応じて定まるため、機械的に暗記せず、 頂上が何を指しているかから導く必要がある。

確認問題 2-1

空のスタックに対して、次の操作を上から順に実行した。 すべての操作を終えた時点で、スタックに残っている要素を 底から頂上へ向かう順に並べたものはどれか。 

1. push 5
2. push 7
3. pop
4. push 2
5. push 9
6. pop
  1. 5、2
  2. 5、7
  3. 2、5
  4. 5、2、9
解答

正解: (A)

各操作後の内容を底から順に追うと、 5 → 5, 7 → 5（7 を取り出す）→ 5, 2 → 5, 2, 9 → 5, 2（9 を取り出す）となる。 残るのは底から 5、2 である。

(B) は手順 3 の pop で取り除かれるのが 7 ではなく 5 であると誤ったもので、 取り出す端を底と取り違えている。 (C) は残る要素は正しいが並び順が逆であり、後から積んだ 2 が 底にあると解釈している。 (D) は手順 6 の pop を反映し忘れたもので、 操作の数と状態変化の対応が取れていない。

3キュー — 先入れ先出し

キューは、最初に入れた要素を最初に取り出す 構造である。この規約を 先入れ先出し(FIFO: first in, first out) と呼ぶ。窓口に並ぶ待ち行列がそのまま比喩になる。

二つの基本操作

  • enqueue — 要素を一つ、末尾に加える
  • dequeue — 先頭の要素を一つ取り出し、構造から取り除く

スタックとの決定的な違いは、出入口が両端に分かれていることである。 加えるのは末尾、取り出すのは先頭であり、二つの端は別の場所にある。 したがって実装では、先頭と末尾の二つの位置を別々に管理する必要が生じる。 スタックが頂上一つで済んだのに対し、管理すべき情報が一つ増える。

確認問題 3-1

空のキューに対して、次の操作を上から順に実行した。 三回の dequeue によって取り出される値を、取り出された順に 並べたものはどれか。 

1. enqueue 4
2. enqueue 1
3. dequeue
4. enqueue 8
5. dequeue
6. enqueue 3
7. dequeue
  1. 1、8、3
  2. 4、1、8
  3. 4、8、3
  4. 1、4、8
解答

正解: (B)

先頭から取り出されるため、手順 3 では最初に加えた 4、手順 5 では次に加えた 1、 手順 7 ではその次の 8 が取り出される。加えた順序がそのまま取り出す順序になる。

(A) は末尾から取り出すと解釈したもので、スタックの規約と混同している。 (C) は手順 5 で 1 を飛ばして 8 を取り出しており、 先頭の位置が一つずつ進むことを反映できていない。 (D) は取り出す値の集合は正しいが順序が入れ替わっており、 先入れ先出しが「入れた順に出る」ことを保証する点を捉えていない。

4配列による実装

スタックもキューも、連続した領域を持つ配列の上に実装できる。 ただし両者で、実装に要する手間は大きく異なる。

スタックの実装は素直である

スタックは出入口が一箇所であるため、頂上の位置を示す変数を一つ持てば足りる。 push は頂上の位置へ書き込んで位置を一つ進め、pop は位置を一つ戻して読み出す。 既存の要素を動かす必要は一切ない。 

push（値 v を積む）
1. もし 頂上 = 領域の大きさ ならば あふれとして処理を中止する
2. 配列[頂上] ← v
3. 頂上 ← 頂上 + 1

pop（値を取り出す）
1. もし 頂上 = 0 ならば 空として処理を中止する
2. 頂上 ← 頂上 - 1
3. 配列[頂上] を結果として返す

キューを素朴に実装すると破綻する

キューを「先頭は常に添字 0」と決めて実装すると、dequeue のたびに 残る要素をすべて一つずつ前へずらす必要が生じる。 要素が 100 個あれば 99 個を動かすことになり、 取り出す手間が要素数に比例して増大する。 一定の手間で出し入れできるという、この構造を用いる利点が失われる。

そこで、先頭の位置を変数で保持し、dequeue では 要素を動かす代わりに先頭の位置を一つ進める方式が考えられる。 これで取り出す手間は要素数によらず一定になる。

ところが、この方式には別の問題がある。先頭の位置は進む一方であり、 後ろへ戻ることがない。出し入れを繰り返すうちに、 配列の前方に使われない領域が溜まっていき、 実際に保持している要素数が少なくても末尾に到達してしまう。

確認問題 4-1

キューを配列で実装するにあたり、dequeue のたびに残りの要素を すべて一つずつ前へずらす方式を採った。この方式の問題点として、 最も適切なものはどれか。

  1. 取り出される要素の順序が、先入れ先出しにならない
  2. 取り出しに要する手間が、保持している要素数に比例して増える
  3. 配列の前方に、使われない領域が溜まっていく
  4. 先頭と末尾の位置を管理する変数が、二つとも必要になる
解答

正解: (B)

ずらす方式では、要素が n 個あれば dequeue のたびに n − 1 個を動かすことになる。 一定の手間で出し入れできるという利点が失われる点が問題である。

(A) は誤りで、ずらす方式でも取り出す順序は先入れ先出しのまま保たれる。 問題は順序ではなく手間である。 (C) は先頭位置を進める方式で生じる問題であり、 ずらす方式では先頭が常に添字 0 に保たれるため、前方に空きは生じない。 二つの方式の欠点を取り違えている。 (D) はずらす方式では先頭が添字 0 に固定されるため、 むしろ管理する位置は末尾の一つで済む。

5リングバッファ — 領域を使い切る

前節の問題は、配列を一直線の領域として扱っていることに起因する。 そこで、末尾に達した位置を先頭へ回り込ませることで、 配列を環状に見立てる方式を採る。これを リングバッファ(ring buffer) あるいは循環キュー(circular queue) と呼ぶ。

位置を一つ進める操作は、剰余を用いて記述できる。 領域の大きさを n とすると、位置 p の次の位置は次式で求まる。 

次の位置 ← (p + 1) を n で割った余り

p が n − 1 のとき、p + 1 は n であり、n を n で割った余りは 0 となる。 こうして位置が自動的に先頭へ戻る。条件分岐を書かずに 回り込みを表現できる点が、この記法の利点である。

空と満杯の区別

回り込みを導入すると、新たな問題が生じる。要素が一つもない状態と、 領域が要素で埋め尽くされた状態が、どちらも「先頭と末尾が同じ位置を指す」 という形になってしまう。位置の比較だけでは、この二つを区別できない。

区別する方法は主に二通りある。

表 5-1　リングバッファにおける空と満杯の区別。いずれの方法も、 位置の情報だけでは足りない分を、別の情報か領域の犠牲かで補っている。 どちらを採るかは、領域の逼迫度と管理の簡潔さの兼ね合いによる。

方法判定の仕方代償
要素数を別に保持する 要素数が 0 なら空、領域の大きさと等しければ満杯 出し入れのたびに要素数の更新を要する
一つ分を常に空けておく 先頭と末尾が同位置なら空、末尾の次が先頭なら満杯 領域を一つ分使えない
誤りやすい点

要素数を保持する方法を採った場合、enqueue と dequeue の双方で 要素数を更新しなければならない。片方だけを更新すると、 実際の保持数と記録された数が食い違い、空でないのに空と判定される、 あるいは領域に空きがあるのに満杯と判定されるといった不整合を招く。

確認問題 5-1

領域の大きさが 8 のリングバッファがある。現在、末尾の位置は添字 7 を指している。 ここに新たな要素を一つ加えたとき、加えた後の末尾の位置を示す添字はどれか。 ただし末尾の位置は「次に加えるべき位置」を指すものとし、 領域には十分な空きがあるものとする。

  1. 0
  2. 1
  3. 7
  4. 8
解答

正解: (A)

添字 7 へ書き込んだ後、末尾を一つ進める。 (7 + 1) を 8 で割った余りは 0 であるから、末尾は添字 0 を指す。 これが回り込みである。

(B) は二つ進めた結果であり、一回の enqueue で位置が進むのは一つだけである。 (C) は書き込んだだけで位置を進めておらず、 次の enqueue が同じ位置を書き潰すことになる。 (D) は剰余を取らずに 7 + 1 をそのまま答えたもので、 添字 8 は大きさ 8 の配列には存在しない。 最後の添字が 7 であることと、大きさが 8 であることの区別が必要である。

6操作の手間と使い分け

適切に実装されたスタックとキューでは、要素の出し入れに要する手間は 保持している要素数によらず一定である。 push も pop も、enqueue も dequeue も、位置を示す変数を読み書きして 配列の一箇所に触れるだけで完結する。要素が 10 個でも 10000 個でも変わらない。

この一定の手間は、触れられる要素を端に限ったことの見返りである。 配列は任意の要素を添字で参照できたが、スタックとキューはそれを捨てている。 構造が課す制約は、機能の制限であると同時に、性能の保証でもある。

表 6-1　配列・スタック・キューの対比。スタックとキューは 任意位置への参照という自由度を捨てる代わりに、 処理する順序を構造自体が保証する。どの構造を選ぶかは、 扱うデータに対して順序の規約が定まっているか否かで判断する。

観点配列スタックキュー
取り出す順序 利用者が添字で指定 後入れ先出し 先入れ先出し
出入口 任意の位置 一箇所（頂上） 両端（先頭・末尾）
管理する位置 — 1 つ 2 つ
途中の要素への参照 できる できない できない
出し入れの手間 一定（位置が既知の場合） 一定 一定

どちらを選ぶか

選択の基準は単純である。処理したい順序が、新しいものからか、 古いものからかで決まる。

スタックが適するのは、最後に始まったものが最初に終わる形を した処理である。積み上げた皿を上から取る動作が、この形の身近な例である。

  • 関数呼び出し(function call)の管理 — 呼び出された関数は、呼び出し元より先に終了する。 各呼び出しの戻り先を積み、終了時に頂上から取り出す。 この領域を コールスタック(call stack) と呼ぶ
  • 括弧の対応の照合 — ( [ ( ) ] ) のような入れ子を検査する。 開き括弧を積み、閉じ括弧が来たら頂上と対応するかを見る。 最後に開いた括弧が最初に閉じるため、頂上との照合だけで済む
  • ブラウザの「戻る」操作 — 訪れた頁を順に積み、直前の頁から順に遡る

キューが適するのは、発生した順序を保って処理する形である。 窓口に並ぶ待ち行列が、この形の身近な例である。

  • 緩衝領域としての利用 — 生成する側と消費する側で速度が異なる場合に、 生成された順を保ったまま両者を切り離す。 キーボード入力や通信の受信データがこの形で扱われる
  • 資源の割り当て — 限られた資源を複数の利用者が待つ場面で、 待ち始めた順に割り当てる。 これにより、特定の利用者が待ち続ける状態を避けられる
  • 幅優先探索(breadth-first search) — 探索対象を発見した順に取り出すことで、近い位置から順に調べられる

いずれの例も、構造そのものが順序の規約を保証している点が要である。 利用する側は取り出す位置を判断せず、「次を取り出す」と命じるだけでよい。 順序の管理を構造に委ねることが、これらを用いる目的である。

一方、保持している要素を走査したい、途中の要素を書き換えたい という要求がある場合、これらの構造は適さない。 その場合は配列など、任意位置に参照できる構造を用いる。

確認問題 6-1

ある処理系では、利用者から届いた要求を溜めておき、 届いた順に一件ずつ処理する。先に届いた要求が後回しにされることは あってはならない。この用途に適する構造と、その理由の組合せとして 最も適切なものはどれか。

  1. スタック。最後に届いた要求から処理されるため
  2. キュー。先に届いた要求から処理されるため
  3. スタック。要素の出し入れが要素数によらず一定の手間で済むため
  4. 配列。任意の要求を添字で指定して取り出せるため
解答

正解: (B)

「届いた順に処理する」「先に届いたものが後回しにされない」という要件は 先入れ先出しそのものであり、キューが適する。

(A) は構造と理由が整合しているが、後入れ先出しでは後から届いた要求が 先に処理され、要件に反する。 (C) は述べている性質自体は正しいものの、その性質はキューにも当てはまるため、 スタックを選ぶ理由にならない。手間の一定性は両構造で共通である。 (D) は配列でも実現しうるが、取り出す順序を利用する側が毎回管理せねばならず、 順序の保証が構造によって与えられない。要件を満たすには追加の手当てを要する。

7あふれと空の扱い

実装にあたって必ず手当てを要するのが、領域の限界と、 取り出すものが無い状態という二つの境界である。

  • あふれ(overflow) — 領域が埋まっている状態で、さらに要素を加えようとすること
  • 下位あふれ(underflow) — 要素が一つもない状態で、取り出そうとすること

これらを検査せずに操作を実行すると、確保した領域の外へ書き込む、 あるいは意味を持たない値を読み出すことになる。いずれも 誤りが即座に現れるとは限らず、無関係に見える箇所で 不具合として表面化するため、原因の特定が難しい。 操作の冒頭で検査することを要する。

検査式における境界の扱い

検査式を書く際に誤りやすいのが、最後の添字と領域の大きさの区別である。 多くの言語では添字が 0 から始まるため、大きさ n の配列で 利用できる最後の添字は n − 1 である。

頂上が「次に積むべき位置」を指す方式のスタックでは、 頂上が n に達した時点で領域が埋まっている。検査式は次のようになる。 

あふれの検査
  もし 頂上 = n ならば あふれである

空の検査
  もし 頂上 = 0 ならば 空である

ここで、あふれの検査を「頂上 = n − 1 ならば」と書くと、 最後の一箇所を使わないまま満杯と判定することになる。 逆に「頂上 > n ならば」と書くと、すでに領域外へ書き込んだ後にしか 検知できず、検査の意味をなさない。

誤りやすい点

境界の検査式は、頂上や先頭・末尾が何を指しているかによって変わる。 「最後に積んだ位置」を指す方式であれば、あふれの条件は 「頂上 = n − 1」となり、上記とは異なる。 検査式だけを他の実装から写しても正しく動作しない。 採用した方式から式を導くことを要する。

確認問題 7-1

大きさ 10 の配列でスタックを実装する。頂上を示す変数は 「次に積むべき位置」を指し、空の状態では 0 である。 このとき、push の冒頭に置くあふれの検査式として正しいものはどれか。

  1. 頂上 = 9 ならば あふれ
  2. 頂上 = 10 ならば あふれ
  3. 頂上 > 10 ならば あふれ
  4. 頂上 = 0 ならば あふれ
解答

正解: (B)

頂上が「次に積むべき位置」を指すため、添字 9 へ積んだ後、頂上は 10 になる。 この時点で利用できる位置は残っておらず、満杯である。 したがって検査式は「頂上 = 10」となる。

(A) の 9 は最後の添字であり、この時点ではまだ添字 9 が空いている。 最後の一箇所を使わないまま満杯と判定してしまう、典型的なオフバイワンの誤りである。 (C) は頂上が 10 の状態での push を許してしまい、 添字 10 すなわち領域外へ書き込んだ後にしか検知できない。 (D) の 0 は空の状態を表す条件であり、 あふれではなく pop の側で検査すべき内容である。

8総括

  • スタックとキューは、取り出す位置を利用する側が指定するのではなく、 取り出す順序の規約そのものを構造に埋め込んだデータ構造である
  • スタックは後入れ先出しであり、push と pop を出入口一箇所で行う。 管理すべき位置は頂上の一つで足りる
  • キューは先入れ先出しであり、末尾に加えて先頭から取り出す。 出入口が両端に分かれるため、位置の管理は二つ必要になる
  • キューを配列で素朴に実装すると、要素をずらす手間が要素数に比例するか、 配列の前方に使えない領域が溜まるかのいずれかに陥る
  • リングバッファは剰余演算によって添字を回り込ませ、領域を使い切る。 その代わり、空と満杯がともに先頭と末尾の一致として現れるため、 要素数を保持するか一箇所を空けておくかで区別を付ける
  • 両構造とも出し入れの手間は要素数によらず一定である。 これは途中の要素に触れられないという制約の見返りであり、 走査や任意位置の書き換えを要する用途には適さない
  • あふれと空は、操作の冒頭で必ず検査する。 検査式は位置を示す変数が何を指すかによって変わるため、 採用した方式から導く必要がある

9確認問題

確認問題 9-1

空のスタックと空のキューを一つずつ用意した。 両方に対して 1、2、3 をこの順に加えた後、 それぞれから続けて三回取り出した。 スタックから取り出された順とキューから取り出された順の組合せとして 正しいものはどれか。

  1. スタック: 1、2、3 ／ キュー: 3、2、1
  2. スタック: 3、2、1 ／ キュー: 1、2、3
  3. スタック: 3、2、1 ／ キュー: 3、2、1
  4. スタック: 1、2、3 ／ キュー: 1、2、3
解答

正解: (B)

スタックは後入れ先出しであるから、最後に加えた 3 から順に取り出される。 キューは先入れ先出しであるから、最初に加えた 1 から順に取り出される。

(A) は両者の規約を取り違えている。 (C) と (D) はいずれも両構造が同じ順序で取り出すとしており、 両者を分かつのが取り出す順序である点を捉えていない。

確認問題 9-2

領域の大きさ 5 のリングバッファでキューを実装している。 現在、先頭は添字 3、末尾（次に加えるべき位置）は添字 1 を指しており、 要素数は 3 である。ここで dequeue を一回、enqueue を一回行った。 操作後の先頭と末尾の添字の組合せとして正しいものはどれか。

  1. 先頭 4、末尾 2
  2. 先頭 4、末尾 1
  3. 先頭 2、末尾 2
  4. 先頭 3、末尾 2
解答

正解: (A)

dequeue で先頭が一つ進み、(3 + 1) を 5 で割った余りは 4 であるから先頭は 4 になる。 enqueue で末尾が一つ進み、(1 + 1) を 5 で割った余りは 2 であるから末尾は 2 になる。

(B) は dequeue のみを反映し、enqueue による末尾の前進を忘れている。 (C) は先頭を進める方向を誤り、逆向きに動かした結果である。 先頭も末尾も、進む向きは常に同じである。 (D) は enqueue のみを反映し、dequeue による先頭の前進を忘れている。 出し入れのそれぞれが、異なる位置を動かす点に注意を要する。

確認問題 9-3

スタックとキューの双方に共通して当てはまる性質として、 最も適切なものはどれか。

  1. 管理すべき位置を示す変数が一つで足りる
  2. 保持している要素のうち、途中にあるものを添字で直接参照できる
  3. 要素の出し入れに要する手間が、保持している要素数によらず一定である
  4. 最後に加えた要素が、最初に取り出される
解答

正解: (C)

適切に実装された両構造では、出し入れは位置を示す変数の更新と 配列一箇所への読み書きで完結するため、要素数によらず手間は一定である。

(A) はスタックには当てはまるが、キューは先頭と末尾の二つを要するため共通しない。 (B) は両構造が捨てている性質であり、配列の特徴である。 途中の要素に触れられないことが、これらの構造の制約である。 (D) はスタックの規約であり、キューでは最初に加えた要素が最初に取り出される。 両者を分かつ性質を共通の性質と取り違えている。

確認問題 9-4

リングバッファにおいて、要素数を別に保持せず、先頭と末尾の位置のみで 空と満杯を判定しようとすると不都合が生じる。その理由として 最も適切なものはどれか。

  1. 剰余演算では、添字を先頭へ回り込ませることができないため
  2. 空の状態と満杯の状態が、どちらも先頭と末尾が同じ位置を指す形になるため
  3. 先頭と末尾が、それぞれ逆の向きに進むため
  4. 満杯の状態では、末尾の位置が領域の大きさを超えてしまうため
解答

正解: (B)

要素をすべて取り出した状態でも、領域を埋め尽くした状態でも、 先頭と末尾は同じ位置を指す。位置の比較だけでは両者を区別できないため、 要素数を保持するか、一箇所を常に空けておく必要がある。

(A) は誤りで、剰余演算はまさに回り込みを実現する手段である。 (C) も誤りで、先頭と末尾はいずれも同じ向きに進む。 (D) は剰余を取る以上、位置が領域の大きさに達することはなく、 常に 0 から n − 1 の範囲に収まる。 添字の範囲と、空・満杯の判別という別々の問題を混同している。
